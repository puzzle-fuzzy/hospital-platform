# 旧仓库凭据暴露面只读审计（2026-08-31）

本文只记录旧仓库 Git 元数据层面的暴露面，不读取环境文件、PEM 内容、提交 diff 或任何
凭据值。审计对象是只读本地副本 `G:\\fuck\\hospital`；它不是新仓库，也没有对旧仓库、
旧服务或远程仓库执行清理、重写历史或轮换操作。

## 1. 审计结果

旧仓库的 Git remote 为：

```text
https://gitee.com/yanyaodingsheng/hospital.git
```

当前 Git 跟踪到以下敏感或可能包含敏感配置的路径：

| --- | --- | ---: | --- |

| `hospital-app/project.private.config.json` | 是 | 未统计 | 属于私有开发配置，不能复制到新仓库或运行包 |

本轮使用 `GIT_TERMINAL_PROMPT=0 git ls-remote --heads origin` 做了最小远程可见性检查，
未提供账号或密码即成功读取到 6 个 branch refs。这个结果证明远程 Git 服务至少允许匿名
读取引用元数据，显著提高了历史文件可能被不应访问人员取得的风险；它不等于本轮已经读取
远程文件内容，也不替代 Gitee 项目可见性、fork、镜像和访问审计的管理员确认。

“触及提交数”只表示路径出现在 Git 历史中，不表示本轮读取了内容，也不表示每个提交都
含有真实值。由于 remote 指向代码托管平台，暴露范围必须由仓库管理员结合平台可见性、
fork、镜像、构建日志和访问审计进一步确认。

## 2. 处置边界

- 不把旧环境文件、PEM、医保 `.env`、小程序私有配置复制到新仓库、发布包或服务器新 release。
- 不在没有管理员授权和 Provider/微信确认的情况下删除旧历史、重写远程、替换证书或修改旧服务环境。
- 若任一文件曾包含真实值，应按“已暴露”处理：先吊销/轮换微信、医保和 Provider 凭据，再核对旧服务与新服务的最小权限和生效时间，并保留管理员操作记录。
- 轮换前不得因为新仓库 `secret:audit` 通过，就推断旧仓库历史安全；两个审计范围不同。

## 3. 当前结论

本轮确认了 P0 凭据风险不是假设，而是旧 Git 跟踪、历史存在且远程 refs 可匿名读取的真实事实；
但没有权限替管理员完成吊销/轮换，也没有读取内容来判断具体值。`TODO.md` 中该项继续保持未完成，直到取得
平台历史可见性、凭据吊销/轮换、旧服务更新和新旧环境验证的外部证据。受控处置顺序见
[`legacy-credential-rotation-runbook.md`](旧凭据轮换手册.md)。
