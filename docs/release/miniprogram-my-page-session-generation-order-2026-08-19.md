# “我的”页会话读取代际顺序契约（2026-08-19）

本文记录“我的”页普通资料和患者目录的读取顺序修正。它解决的是两个受保护 GET 并行时，资料请求先触发 401 自动换会话，导致患者目录落在旧会话代际的问题。

## 1. 业务不变量

“我的”页展示的普通资料和患者卡片必须属于同一个当前平台会话：

1. 先确认 `/me`，确认页面周期仍有效；
2. 再读取普通资料。资料失败可以降级为默认昵称和低敏提示，但资料请求必须先结束；
3. 最后读取患者目录，并以当前会话代际解析当前就诊人和患者数量；
4. 患者目录失败时清理患者派生展示，不能把旧患者卡片留在页面；
5. 资料成功只更新昵称，不得清除患者上下文错误；患者成功只更新患者字段，不得覆盖已经加载的昵称。

普通资料 GET 允许受控会话恢复，因此不能与患者目录并行。串行不是把资料升级为关键业务，而是保证资料触发会话轮换后，患者关键读模型从最新代际开始。资料的慢响应会延迟患者目录读取，这是避免跨代际混合的明确取舍；资料失败则降级后继续读取患者目录。
