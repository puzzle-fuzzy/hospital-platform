# 小程序只读页面跨会话本地事件审计（2026-08-21）

> 当前候选：服务端 release `5a31427`；小程序运行包来源
> `7a6f4df34fac5975c6012a30d2c137953a892059`（提交 `7a6f4df`）。

## 发现

“我的挂号”“爽约记录”和“报告目录”此前在 `/me`、患者目录和业务列表提交前
校验了会话代际，但页面只保存了 `selectedPatient`，没有保存这张卡片所属的代际。
页面停留期间若另一个页面完成账号或患者切换，旧页面的本地分页、预约标签、报告
详情或静态业务事件仍可能继续消费旧读模型。服务端 owner 校验是最后防线，但页面
不应先把旧快照当作当前事实交给用户。

## 修正

三页现在统一保存 `patientSessionGeneration`：

- 新查询开始或错误时清除代际和患者读模型；完整患者上下文与业务结果都成功后才提交代际。
- 本地分页、预约在线标签和预约卡片操作在消费前确认代际仍是当前值，并确认当前
  storage 选择仍对应页面患者；失配时重新执行当前页面的组合读取。
- 报告详情入口继续只接受当前渲染批次的 opaque 引用，并额外绑定页面代际。
- “更换就诊人”不被这道门禁拦截，因为它不携带旧患者数据，且正是用户修复上下文
  的安全入口。

代码注释明确区分了“本地 UI 动作”和“患者范围业务事实”，避免后续把 page index、
旧患者对象或相同 opaque ID 当成跨会话授权凭据。
