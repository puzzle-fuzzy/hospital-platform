# 小程序门诊费用会话竞态修正审计（2026-08-21）

## 结论

门诊费用页原先只在页面请求令牌和本地 `selected_patient_id` 上做回写校验，
没有记录当前患者卡片所属的会话代际。另一个页面完成微信会话轮换，或完成显式
更换就诊人后，旧页面短时间内仍可能保留上一轮 `selectedPatient`；如果此时点击
“已缴费/待缴费”，旧对象有机会在客户端请求前进入费用查询参数。

这不是把服务端 owner 校验删掉或替换成前端判断的问题。服务端仍然是最终授权边界，
但客户端也必须在请求前阻止一条已经失去会话/患者上下文的请求，避免制造错误的网络、
日志和 Provider 访问。

## 修正内容

1. `OutpatientPaymentPageData` 增加 `patientSessionGeneration`，患者卡片和费用读模型
   只有在同一会话代际下才可以提交到页面。
2. `loadRecords` 在调用费用 service 前执行 `assertSessionGeneration`；响应返回后仍保留
   原有代际、页面令牌和当前显式患者三重回写校验。
3. 状态 tab 点击如果发现会话代际变化，或本地选择已经不再匹配卡片患者，只记录用户
   最后一次状态意图并重新执行 `/me` → 患者目录 → 当前状态费用查询，不把旧患者对象
   直接交给 API。
4. 费用查询失败时同时清空患者卡片和会话代际，避免错误态继续显示上一位患者的身份。

## 未完成边界

这项修正只解决客户端患者范围查询的会话组合竞态，不代表门诊缴费、微信支付、医保
结算、退款或 HIS 回写已经开放。真实 Provider 请求、服务端同链低敏日志和真机页面
结果仍需在当前候选二维码下分别验收。
