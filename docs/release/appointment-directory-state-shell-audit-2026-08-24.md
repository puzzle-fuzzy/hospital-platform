# 预约目录状态容器审计（2026-08-24）

## 结论

本地未发布候选已补齐预约目录的状态容器高度：

- 首层科室目录的加载、错误和合法空目录统一使用 `query-state-shell`，固定为 `380rpx`；
- 右侧排班的加载和空排班统一使用同一容器，固定为 `500rpx`；
- 未改变科室级联、日期筛选、号源本地分页和只读下单关闭边界；
- 未部署线上，未修改旧 Python 服务、生产数据库或 Redis。

## 为什么需要修正

预约目录存在两个连续读阶段：先读取科室，再读取当前科室的排班。此前首层状态没有固定高度，右栏加载态为 `420rpx`、空态为 `500rpx`。Provider 返回后从“正在加载”切换到“暂无排班”时，插图、说明和重试动作会改变布局高度，造成页面跳动。

这次只收敛展示状态的空间契约，不把科室或排班提前铺开，也不把 Provider 失败降级为空目录。错误判断仍优先于空态判断；空态只在本次读取成功且结果确实为空时显示。

## 验证边界

本记录只覆盖源码结构、TypeScript 构建、运行包和自动化回归。真实微信开发者工具、真机页面和线上 Provider 三层证据仍需按当前运行包发布手册单独取得，不能由本地高度修正推导出来。
