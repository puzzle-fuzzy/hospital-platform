# 原生小程序普通资料会话显示边界

> 记录日期：2026-08-19
>
> 目的：说明普通资料页在保存或读取过程中失去会话归属后，为什么必须清理旧账号资料，避免把跨账号数据继续当作当前资料。

当前本地小程序候选来源为 `379eae2a528265df900030cea6e8dc45a82902c1`；本记录只描述新小程序代码，未上传或替换线上小程序包。

## 发现

`requestWithSession` 在第一次收到 `401` 时会受控地重新进行一次微信 code 兑换；如果重试仍然失败，或并发请求返回 `session-changed`，普通资料页的保存失败分支此前只展示错误文案，仍保留旧的昵称、性别、年龄、邮箱和版本字段。

这会产生一个错误的显示快照：页面已经没有证明当前资料属于当前微信 principal，但用户仍能看到上一轮资料，甚至可能在重新登录后把它误认为新账号资料。普通网络故障和持久化暂时不可用则不能被同样处理，因为它们没有证明账号已经变化。

## 修正后的不变量

1. `access_token` 存在不等于资料归属已经验证；资料页面的编辑态必须绑定最近一次成功的服务端读取。
2. `unauthorized`、`session-changed`，以及自动重新登录失败后已经没有平台 token 时，清理当前页面的资料派生字段。
3. 清理只作用于页面状态，不删除服务端资料、不删除仍可重试的平台 token，也不触碰旧 Python 服务、数据库或 Redis。
4. 普通网络失败、Provider/持久化暂时不可用和 `user-profile-conflict` 保留各自语义；409 只要求重新读取最新版本，不能被改写成会话失效。
5. 清理后 `loaded=false`，保存入口不可用；只有重新成功读取 `/me/profile` 后，页面才恢复编辑和保存。

## 实现与证据

- `apps/miniprogram/src/pages/profile/profile.ts` 新增 `shouldClearProfileDisplay`，在资料读取和保存失败时区分会话归属失效与普通依赖错误。
- `clearDisplayedProfileContext()` 会清理昵称、性别、年龄、邮箱、版本和保存导航状态，但不修改服务端或认证存储。
- `apps/miniprogram/scripts/acceptance.test.ts` 新增静态门禁，确认会话失效分支先清除旧字段，再展示错误，并把页面恢复到 `loaded=false`。
- 当前小程序测试为 130 项、1089 次断言，TypeScript 类型检查通过；这些是代码级证据，不替代真机微信账号切换和公网 trace 验收。

## 不扩大范围

本次没有执行真实 `PUT /me/profile`，没有改变头像、实名、手机号或患者档案能力，也没有新增 Provider、支付、医保、二维码或旧服务操作。真实资料首次更新、409 并发冲突和真机显示仍须按资料验收手册单独取证。
