# 门诊费用账单时间窗口校验记录

> 记录时间：2026-08-18
> 变更类型：门诊费用只读链路的服务层业务正确性加固
> 状态：代码与自动化验证完成，尚未替代真实 Provider、真机和线上业务验收

## 1. 发现的问题

门诊费用 Provider 请求由服务端生成最近 30 个中国标准时间日的
`startTime`/`endTime`。此前 adapter 会严格校验 `billDate` 的格式和自然日，
但 `OutpatientPaymentService` 的第二道网关校验只验证了安全文本、金额、状态和
唯一引用，没有再次确认账单时间属于本次请求窗口。

这会让错误的回放网关、未来替换的 Provider 实现或异常上游响应绕过 adapter 后，
把窗口外费用带到患者端。因此本次在领域层和服务层同时收紧：格式先严格解析，
再按服务端生成的中国标准时间窗口做闭区间比较。

## 2. 当前规则

- `billDate` 必须严格符合 `YYYY-MM-DD HH:mm:ss`，不接受带时区的 ISO 文本。
- 自然日、小时、分钟和秒必须真实有效，禁止 `2026-02-31` 等自动进位日期。
- 账单时间必须落在本次服务端生成的 `[startTime, endTime]` 闭区间内。
- 只要一条记录越过窗口，整批返回 `502/provider-response-invalid` 对应的内部原因
  `bill-date-outside-query`；不筛掉异常行，不记录 `loaded` 成功事件。
- 失败日志只保留稳定的 `resultViolation`，不记录费用单号、金额、患者号或 Provider 原文。
- 本次仍然只读门诊费用列表，不打开现金支付、医保结算、退款或 HIS 写回。

## 3. 验证证据

- 领域包测试：23 项通过，覆盖非法自然日、带时区文本和读模型拒绝。
- API 服务测试：106 项通过，覆盖窗口内/窗口外混合返回的整批拒绝语义。
- API、领域包 TypeScript 类型检查和 Biome 格式检查通过。
- 完整 `pnpm check` 仍需在本次文档变更后执行，并以其最终输出作为提交门禁。
