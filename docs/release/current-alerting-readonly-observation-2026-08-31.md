# 生产告警接入只读观测（2026-08-31）

本文记录本轮通过 `ps@192.168.112.172` 对生产告警接入的只读核对。检查只关注 unit、进程
名称、非敏感环境变量名和 journald 目录，不读取配置值，不发送测试通知，不修改服务或日志。

## 1. 观测结果

| 检查项 | 结果 | 结论 |
| --- | --- | --- |
| systemd 监控/告警相关 unit | 未发现 Prometheus、Alertmanager、Loki、Vector、Filebeat、Telegraf、Zabbix 或 OTel 相关 unit | 未取得生产指标/日志告警接入证据 |
| 监控/日志采集进程 | 未发现上述采集器的可确认运行进程 | 未取得生产采集证据 |
| 新 API/Worker 公开配置键 | 仅看到 `LOG_LEVEL`、`WECHAT_PAY_NOTIFY_URL` 等匹配键；没有看到告警接收端、值班或通知配置键 | 不能证明有通知路由、责任人或恢复策略 |
| journald | `/var/log/journal` 与 `/run/log/journal` 均存在 | 只能证明日志目录存在，不代表告警已发送 |
| 触发/恢复演练 | 本轮没有发送通知或制造故障 | 未取得演练证据 |

## 2. 与仓库实现的边界

仓库中的 `@hospital/observability` 已定义 readiness、`not_configured`、Provider 错误率、
延迟和人工复核积压等低敏告警判定规则，并有本地测试。但这些规则需要实际指标或日志平台
接收、通知路由、值班责任人和触发/恢复演练才能成为生产告警能力；本地单元测试不替代上述
外部证据。

## 3. 结论

本轮确认生产主机上没有可由本地 systemd/进程直接证明的告警接入。由于外部云监控平台可能
不运行在该主机上，本观察不能断言“绝对没有外部监控”；但在取得平台侧接入截图/配置摘要、
通知责任人、测试通知和恢复记录前，生产告警 TODO 必须保持未完成，不能打开支付、HIS 或
自动补偿 Worker。
