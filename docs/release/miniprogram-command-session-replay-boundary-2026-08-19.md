它只证明本地代码、测试和构建边界，不代表新小程序包已经上传线上，也不代表真机、Provider、预约写入、支付或医保已经验收。

## 1. 发现的问题

请求层原先对所有受保护请求统一处理 `401`：清理旧 token、重新兑换微信会话，再把原请求重放一次。
这个策略对只读 GET 可以接受，但对资料 PUT、患者同步 POST、支付预支付和其它命令请求存在业务风险：
原请求体、幂等键或支付意图可能在账号切换后被带到新会话，或者让用户误以为一次命令已经被安全重试。

## 2. 当前规则

- 只有受保护的幂等 GET 允许自动重新登录并重试一次。
- PUT、POST、DELETE 收到 `401` 后不自动登录、不重放原请求；旧 token 清理后由用户明确重新触发命令。
- 如果命令请求等待期间已经发生账号切换，返回 `session-changed`，并保留新 token，避免误删新账号会话。
- 患者选择页和普通资料页在会话 owner 失效后清理页面派生数据并回到首页，由用户确认当前账号后重新登录。
- 服务端仍以 owner 范围、幂等键、持久化操作账本和最终状态查询作为第二道边界。
