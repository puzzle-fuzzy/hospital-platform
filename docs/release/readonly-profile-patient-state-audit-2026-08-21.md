## 2. 普通资料状态机

普通资料只允许昵称、性别、年龄和邮箱四类展示字段，服务端以当前 Bearer principal
确定 owner，以 `version` 做条件更新。页面端的关键顺序如下：

```text
GET canonical snapshot
  -> 记录所属 session generation
  -> 用户编辑有限字段
  -> saving/loading/loaded/session generation 门禁
  -> PUT(version)
  -> 再次确认 session generation
  -> 只提交服务端 canonical response
```

必须保持的规则：

- `version=0` 只代表尚未持久化的默认资料，默认读取不创建数据库行。
- 普通网络失败不能被误判为账号失效，页面可以保留编辑值等待重试。
- `unauthorized`、`session-changed` 或当前会话已不存在时，必须清理昵称、性别、年龄、
  邮箱、版本和保存状态，再返回首页重新确认会话。
- PUT 返回后如果会话代际变化，先释放 `saving` 再发起异步回首页；不能让页面永久停在
  “保存中”，也不能把旧账号的成功响应展示给新账号。
- `user-profile-conflict` 必须退出可编辑态，要求重新 GET 最新 canonical `version`，
  不能自动覆盖另一设备的修改。
- 小程序 API 客户端对非 GET 的 401 不自动重新登录和重放，防止资料命令、患者同步或
  未来支付命令被带到新账号或重复执行。

## 3. 就诊人目录与切换状态机

就诊人目录使用两层标识：小程序只保存 owner 范围内的 opaque `patientId`；众阳目录号、
档案 `patId`、卡号和身份证只留在服务端映射或 adapter 边界。目录展示成功不等于临床
映射已经确认，只有同步完成且 `clinicalAccess=ready` 才能返回调用页。

```text
平台目录读取
  -> 展示资料但撤销“当前”角标
  -> 完整临床映射同步
  -> 校验当前 session generation 与页面 request token
  -> 恢复已确认患者或要求用户显式选择
  -> 只写入 opaque patientId
```

必须保持的规则：

- 首次没有历史选择时，只能默认第一位 `ready` 患者。
- 已有患者从最新 owner 目录消失、目录为空或临床映射不可用时，不能静默切换到第一位。
- 读取或同步失败时不能保留上一轮“当前”角标；会话失效时连姓名、关系和脱敏卡号也必须
  清理，避免跨账号展示医疗派生数据。
- 页面级和进程级 single-flight 必须按 session generation 隔离；旧账号的在途同步结果
  不能交给新账号。
- 选择页只有在完整同步完成后才能写入新的患者选择并返回；“添加就诊人”暂时只展示
  医院绑定契约未接入提示，不伪造成功。
- “其他”只在服务端明确返回 `relationship=other` 时显示；脱敏卡号由服务端读模型提供，
  小程序不接收完整卡号或身份证再自行脱敏。
