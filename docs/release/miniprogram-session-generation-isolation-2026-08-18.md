# 小程序患者同步会话代际隔离（2026-08-18）

## 发现的问题

患者同步同时被首页和选择页使用。原实现使用进程级、页面级 single-flight 复用在途 Promise，但没有区分会话代际。如果旧微信账号的同步请求尚未完成时发生重新登录，新账号可能消费旧 Promise 的患者快照，造成跨账号患者上下文污染。

## 修正规则

- `session-generation.ts` 只维护一个内存中的数字代际，不保存 token、openid、患者号或日志字段。
- `api-client.ts` 只有在平台 token 真正变化时推进代际；同一 token 的重复请求不会无意义地制造新代际。
- 首页和选择页的页面级 single-flight key 包含当前代际。
- 进程级患者同步协调器按代际维护 Promise；旧代际的 Promise 完成后，如果当前代际已经变化，则以 `session-changed` 错误拒绝。
- 旧代际协调器在成功或失败后都会回收；当前导航门禁只检查当前代际，不会因为旧账号请求仍在网络中而阻塞新账号。
