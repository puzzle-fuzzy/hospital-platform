# 小程序首页会话状态竞态审计（2026-08-22）

## 结论

发现并修复首页 `onShow()` 与下拉刷新并发时的状态竞态：旧的目录读取被新的读取淘汰后，原回调仍可能把
`sessionStatus` 写成“已恢复会话”。这会让用户在当前患者目录尚未确认时看到可用入口，随后进入预约、报告或费用页。

## 修复边界

- `onShow` 只在 `PatientDirectoryLoadResult === "loaded"` 时恢复会话状态；`"superseded"` 只表示旧周期失去回写资格；
- 下拉刷新拥有独立的 session guard 和页面生命周期检查，淘汰 `onShow` 后由自己的最新目录周期负责状态收敛；
- 目录读取失败时按 `invalid/unavailable` 区分会话失效和暂时故障，不把失败或空目录伪装成成功；
- 登录、目录读取和患者范围业务仍由服务端 `/me`、owner、患者映射和稳定会话请求共同保护。

## 回归证据

- 新增静态验收：旧目录周期不能写入“已恢复会话”，下拉刷新必须消费 `loaded/superseded`；
- 小程序测试和仓库级门禁将在本次提交前重新执行；
- 本修复只修改新项目小程序代码与文档，不修改旧 Python 服务、线上配置、数据库、Redis 或 Provider 自动化。

支付、医保、退款、预约写入和 HIS 回写继续保持最后专项。
