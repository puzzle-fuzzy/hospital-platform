## 日志读取失败边界

首次尝试使用 `sudo journalctl` 时，服务器返回“需要密码”；如果把该命令直接接入聚合管道，聚合器可能只收到
一行空输入并输出 `parsedRecords=0`，这不能解释为“窗口内没有业务事件”。正确做法是：

1. 先单独验证 `journalctl` 权限；
2. 使用 `sudo -n`，或使用已获 journald 读取权限的账号直接执行 `journalctl`；
3. 使用 `set -o pipefail`，任何日志读取或聚合失败都必须让命令失败；
4. 只有 `parseErrors=0` 且输入行数、聚合结果和业务门禁均可解释时，才允许形成观察记录。

后续真机取证仍须从当前待验收候选重新生成二维码，并同时保存页面、客户端 HTTP 和服务端同链证据；
本记录不能替代设备证据。
