# 普通资料年龄输入边界修正（2026-08-22）

## 结论

本轮修正了小程序个人资料页的年龄输入语义：输入阶段保留用户原文，保存阶段才执行严格解析。
`-1`、`1.5`、科学计数法、字母和超过 150 的值都会被拒绝，不再通过删除字符被改写成另一组合法数字。

本次只修改新项目的小程序源代码、测试和文档，没有修改旧 Python 服务、旧域名、线上数据库、Redis
或任何并行会话维护的 Provider 自动化代码。

## 1. 原问题

原资料页的 `onAgeInput` 使用 `replace(/\D/g, "")` 清洗输入。这个做法表面上限制了数字，实际会改变
用户意图：

| 用户输入 | 旧行为 | 风险 |
| --- | --- | --- |
| `-1` | 变成 `1` | 非法负数被伪装成合法年龄 |
| `1.5` | 变成 `15` | 小数被伪装成整数 |
| `1e2` | 变成 `12` | 科学计数法被静默改写 |

输入控件的 `type=number` 不能替代业务校验，因为开发者工具、真机键盘和自动化事件对控件输入形态并不
完全一致。

## 2. 当前规则

- `onAgeInput` 只保存 `event.detail.value`，不删除字符、不自动修正用户输入。
- `parseProfileAgeInput` 只接受空字符串或十进制整数文本。
- 空字符串映射为 `age: null`，表示用户主动清空年龄。
- 非空值必须是 `0` 到 `150` 的安全整数，否则在发出 PUT 前显示中文错误并停止请求。
- 服务端仍然执行同一范围和类型校验；小程序校验只是用户体验和提前失败，不是授权边界。

## 3. 验证

新增 `apps/miniprogram/src/services/profile-form.test.ts`，覆盖空值、前导零、边界值、负数、小数、科学计数法、
字母、超范围值和非字符串事件值。小程序全量测试、TypeScript 类型检查和 Biome 必须在提交后重新通过；
运行包来源指纹必须对应包含本次修正的提交，不能继续使用旧 `dist/build-info.json` 进行真机验收。

## 4. 真机验收边界

在最新运行包中进入“我的 → 个人资料”时，应分别验证：

1. 输入 `32` 可以保存；
2. 输入 `-1` 或 `1.5` 时页面提示年龄范围错误，客户端不发出 PUT；
3. 清空年龄后提交 `age: null`，服务端返回 canonical 资料；
4. 资料成功写入和旧版本 `409` 仍按普通资料原有的会话代际、版本和低敏日志规则处理。

这项修正不改变头像、实名、手机号、患者绑定、支付或医保的关闭状态。
