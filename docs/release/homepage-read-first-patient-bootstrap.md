# 首页患者上下文启动边界

## 目的

首页打开时必须优先保证页面可用。平台会话和患者目录是首页的只读依赖，众阳患者同步属于外部副作用，不能作为首页启动的必需步骤。

## 当前流程

```text
小程序启动
  -> 恢复全局微信会话与用户资料
  -> GET /patients
  -> 仅使用当前 owner 目录中 clinicalAccess=ready 的已确认患者
  -> 首页正常展示
```

首页启动不再自动调用 `POST /patients/sync`。因此，众阳短暂超时不会把首页直接推入“外部服务暂时不可用”错误态，也不会影响首页读取已经落库的安全读模型。

## 同步触发边界

患者同步只允许出现在明确的业务动作中：

- 用户进入“选择就诊人”页面并执行页面的同步/刷新操作；
- 用户在仍保留该入口的页面上明确点击“同步就诊人”。

首页的“重新加载”只重新读取健康状态和平台患者目录，不重放 Provider 同步。这样重试语义稳定，也不会因为反复点击造成外部同步租约竞争。

## 患者安全约束

- 目录中没有 `ready` 临床映射时，不能静默选择患者；
- 已保存患者从当前 owner 目录消失时，保持 `stale`，必须由用户显式重新选择；
- 只有选择页完成同步并返回 `ready` 患者后，预约、报告和费用等患者范围业务才允许继续；
- Provider 同步失败只能表示“同步本次失败”，不能被翻译成“没有就诊人”。

## 维护提示

`directory-loaded` 表示“安全目录读取成功”，`succeeded` 表示“明确同步成功”。两者不能混用：前者不证明本轮 Provider 映射刚刚刷新，后者才代表本轮同步命令完成。
