# 小程序患者选择页会话恢复竞态审计（2026-08-21）

## 发现的问题

选择页的患者同步入口会调用 `syncPatientsFromHospital`。该同步内部先用 `/me` 建立当前 owner 证明，再发起患者同步命令；受保护 GET 在收到 401 时允许安全地清理旧 token、重新登录并推进客户端会话代际。

旧实现却在同步 Promise 发起前记录页面会话代际。于是“旧 token → `/me` 自动恢复 → 同步成功”的正常路径，会因为返回代际与同步开始前的旧代际不同，被页面误判成 `session-changed`，表现为刷新就诊人偶发失败。

## 修正后的不变量

1. 患者同步请求仍由 `requestWithSession` 在发请求前和响应回写前校验 token/代际；命令不会被自动重放到新账号。
2. 页面只有在同步 Promise 成功、`patient-list-load` 和 `sync` 两个页面令牌仍然有效时，才记录本页成功快照所属的会话代际。
3. 被新一轮刷新淘汰的旧结果不会更新页面代际，也不会恢复当前患者标记。
4. 之后点击患者仍必须通过页面成功快照的代际校验、临床映射和 `selectionReady` 门禁；不会因为延后记录代际而放宽患者归属。
