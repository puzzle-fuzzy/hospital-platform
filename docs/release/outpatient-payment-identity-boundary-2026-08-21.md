# 门诊费用稳定身份字段边界审计（2026-08-21）

## 本轮结论

门诊费用当前只开放只读查询。适配器会把 Provider 返回的稳定身份字段组成内部 `recordId`，供页面状态关联和后续详情/支付边界使用；该字段不直接返回给用户，也不应被当作可支付凭证。

本轮发现旧实现会把“字段存在但格式异常”的值静默当作缺失。例如 `outTradeOrderId` 是对象时，如果同时存在 `chargeId`，适配器仍可能使用后者生成一个看似合法的 `recordId`。这会掩盖上游协议漂移，并让同一账单的内部身份随返回字段变化而漂移。

## 已收紧的运行时规则

| 输入形态 | 处理 | 原因 |
| --- | --- | --- |
| `undefined`、`null`、空字符串 | 视为该候选字段缺失 | Provider 可能只返回其中一组稳定 ID |
| 字符串或有限数字 | 去除首尾空白后参与身份组合 | 保留已冻结的兼容字段形态 |
| 对象、数组、布尔值、`NaN`、无穷数字 | 整批拒绝并标记 `responseInvalid` | 不允许异常值被静默降级为缺失 |
| 含控制字符的值 | 整批拒绝 | 防止日志/关联输入出现换行等不可见边界 |
| 超过 256 个 UTF-16 单元的值 | 整批拒绝 | 限制未经审计的上游值进入哈希输入 |
| 所有候选字段均缺失，或最终 `recordId` 重复 | 整批拒绝 | 不生成不可定位或有歧义的费用记录 |

账单时间继续参与内部哈希，以区分同一项目在不同开单时刻产生的记录；金额不参与哈希，避免待缴金额与结算后金额变化导致业务记录换 ID。金额、交易状态、患者归属和 30 天查询窗口仍沿用门诊费用只读 contract 的既有校验。

## 代码与验证

- 适配器：`packages/adapters/src/zhongyang-outpatient-payments.ts`
- 回归测试：`packages/adapters/src/zhongyang-outpatient-payments.test.ts`
- 对象、控制字符和超长身份字段均要求 `ProviderRequestError.responseInvalid = true`；不会触发支付、医保授权或结算调用。
- 本轮只验证本地合成 Provider 响应和类型/测试门禁，不代表真实众阳环境、微信真机或线上 release 已完成验收。

## 后续边界

1. 取得当前 release 的门诊费用真实请求、服务端低敏日志和页面结果三层配对证据。
2. 在取得费用详情、支付参数、医保授权和结算 contract 前，继续保持这些能力关闭。
3. 若 Provider 后续确认新的稳定 ID 字段，应先更新 contract、脱敏规则、回归样例和回滚说明，再扩大白名单；不能通过放宽 `unknown` 解析来兼容未知字段。
