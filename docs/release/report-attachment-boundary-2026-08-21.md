# 报告附件标记边界审计（2026-08-21）

## 本轮结论

报告当前只提供目录级“是否含附件”提示，不返回 Provider 地址，也未开放文件下载和授权。LIS 的 `pdfUrlList` 是字符串数组；旧实现只拒绝对象、数组和布尔值等非字符串元素，却会把带换行等控制字符的字符串当成有效附件。

这会把异常 Provider 响应映射成患者可见的“含附件”，并为未来下载/授权逻辑留下未经校验的上游值。即使当前只返回布尔值，附件字段也必须在 adapter 边界完整校验。

## 已收紧规则

- `undefined`、`null`、空数组和空字符串数组表示当前没有可用附件。
- 数组元素必须是字符串；对象、数组、布尔值和数字整批拒绝。
- 字符串含控制字符时整批拒绝，不静默删除或截断。
- 目录和 LIS 详情继续只返回 `hasAttachment`，不返回 URL、文件名或 Provider 原始字段。
- 失败使用 `ProviderRequestError.responseInvalid = true`，不会降级成空目录，也不会发起下载或支付/医保调用。

## 验证边界

新增回归测试覆盖对象元素和带控制字符的字符串元素；本轮仍只验证本地合成 Provider 响应。真实报告 Provider、PACS/ECG 详情、体检报告、文件下载、授权和真机页面证据仍未完成，必须等待对应 contract、脱敏样例和可回滚验收材料。
