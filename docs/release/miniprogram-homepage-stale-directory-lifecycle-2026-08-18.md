# 首页目录请求生命周期修正（2026-08-18）

本文记录原生小程序首页在患者目录请求失去页面或请求资格后的错误回写边界。
它只涉及患者目录只读加载和页面生命周期，不修改服务端、数据库、Provider、支付或旧 Python 服务。

## 1. 发现的问题

首页的 `onShow` 和下拉刷新都会启动患者目录读取。旧请求在新一轮目录读取开始，或页面已经卸载后，
仍可能把失败继续冒泡到外层回调。外层回调随后可能清空新请求已经得到的展示结果，或者在页面销毁后继续尝试
更新页面状态。这个问题不会改变 Provider 数据，但会让首页出现旧错误覆盖新结果、卸载页面仍提示错误等生命周期错乱。

## 2. 修正后的状态边界

```text
目录请求开始
    ↓
请求 token + 页面生命周期仍有效？
    ├─ 否：旧请求以安全空完成收敛，不再冒泡或 setData
    └─ 是：按当前错误策略清理患者展示态并向当前页面提示
```

- 目录请求在错误出口重新核对 `patientDataGuard`；失去资格的旧请求返回安全空数组，
  不把错误交给 `onShow/onRefresh` 的外层处理器。
- `onShow` 和下拉刷新处理器在展示错误前核对页面生命周期，避免页面卸载后继续 `setData`。
- 仍属于当前请求的失败继续清空首页患者卡片和临床展示态，但保留本地 opaque 选择，便于下一次恢复。
- 该边界不把旧请求当作成功，也不把网络/持久化错误降级为空目录；只有已失去回写资格的旧请求才安全收敛，
  当前请求仍按既有错误语义向页面传播。
