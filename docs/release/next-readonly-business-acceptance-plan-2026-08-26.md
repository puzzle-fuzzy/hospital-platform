## 统一业务链路

```text
微信会话
  -> /me owner 校验
  -> GET /patients 确认当前 owner 的患者目录
  -> 显式选择 patientId（不使用 provider patId）
  -> 业务只读请求
  -> API canonical 响应校验
  -> 页面提交“患者 + 列表”同一快照
  -> requestId / traceId / providerRequestId 低敏关联
```

会话代际或当前患者在请求期间发生变化时，旧响应必须丢弃；不能把上一位患者的卡片、记录、费用或资料写入当前页面。
空结果只允许在业务请求明确成功且响应通过 canonical 校验后展示；401、Provider 拒绝、持久化故障和超时必须保持错误态。

## 域级验收顺序

### 1. 就诊人目录与显式切换

- 登录后进入首页，确认当前患者卡片只显示脱敏姓名、关系和卡号；不展示 `patId`、身份证、手机号或原始 Provider 字段。
- 进入独立选择页，确认首次进入允许默认第一位“临床可用”患者；已有选择不因目录顺序变化而静默换人。
- 选择另一位患者后返回首页、我的挂号、爽约和门诊费用，确认每页重新读取当前患者，不能沿用旧列表。
- 更换微信账号后重新进入首页，确认旧账号的患者目录、当前就诊人和业务列表都被清理，不能把账号切换误当成普通刷新。
- 同步失败、目录为空、患者映射失效时，确认页面不把“无记录”当成成功空目录，也不显示错误的当前标记。

### 2. 我的挂号与爽约记录

- “在线挂号”和“全部挂号”必须分别触发服务端定义的 `scope=online|all`；不能用前端过滤把在线列表复制成全部列表。
- 爽约记录只能使用服务端标准化的 `missed` 状态；未知状态、取消状态和查询异常不能被推导为爽约。
- 验证未来/历史窗口、空结果、切换患者和刷新并发；卡片点击不能使用列表索引拼接详情或取消 URL。
- 挂号写入、取消、预问诊和详情继续进入固定关闭态。

### 3. 门诊费用只读

- 分别检查待缴、已缴和成功空结果；费用金额必须来自服务端 `amountFen`，页面不得自行计算医保/现金金额。
- 查询失败、患者映射缺失和会话失效必须分别显示错误语义，不能显示“暂无费用”。
- 只能进入费用只读展示；点击支付、医保授权、结算或退费继续进入关闭态，不创建订单、不调用 `wx.requestPayment`。

### 4. 普通个人资料

- 首次读取确认只返回昵称、性别、年龄、邮箱和 `version`；头像、手机号、身份证、微信身份和患者字段不可出现。
- 使用专用测试账号修改一个可回滚字段，确认服务端 canonical 响应版本递增后页面才更新。
- 使用旧版本并发提交，确认返回 `409 user-profile-conflict`，页面退出可编辑态并要求重新读取，不能自动覆盖新版本。
- 资料更新期间切换会话，旧响应不能写回新账号；日志不能出现 userId、昵称、邮箱、请求正文或授权头。

## 证据格式与门禁

证据清单使用 `tools/device-evidence-audit.mjs` 的固定域名和场景枚举。每个域至少需要：

- 页面截图和操作时间；
- 不带查询参数的公共 `/api/v2` 方法、路径、状态码和客户端 requestId；
- 低敏服务端 `requested/succeeded/http2xx/failed` 摘要及关联指纹；
- Provider 请求号只保留有界低敏值，不保存 Provider 原文；
- 失败、空结果、会话失效和切换患者等场景的明确页面结果。

证据文件不得写入 access token、`openid`、`session_key`、身份证、完整卡号、手机号、`patId`、Provider 原始响应或带敏感查询参数的 URL。
候选来源、线上服务端 release 和证据中的来源必须一致；否则只保留 `pending`，不能写成 `passed`。

## 停止条件

出现以下任一情况立即停止当前域，不扩大到下一个高风险能力：

- Provider 响应缺少已确认字段、状态或患者映射；
- 发现患者卡片与列表不是同一会话/患者快照；
- 只能证明 HTTP 成功，无法关联服务端业务事件；
- 需要读取完整卡号、身份证、手机号或长期 Provider URL；
- 需要修改旧 Python 服务、旧数据库结构、旧 Redis namespace 或旧域名代理；
- 需要打开预约写入、支付、医保、退款或 HIS 回写才能继续。

完成 A 批次的真实证据后，才进入病历/健康内容/外部入口的独立 contract；支付、医保、结算和 HIS 回写仍是最后专项。
