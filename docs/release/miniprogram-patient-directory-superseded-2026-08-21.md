# 小程序患者目录淘汰结果与同步门禁（2026-08-21）

## 发现的问题

首页的患者目录读取使用页面实例级“最后一次请求获胜”守卫。旧请求失去回写资格时，原实现把异常路径收敛成 `[]`，而登录恢复链只等待 Promise 完成，不知道这次读取其实已经被新请求淘汰。

这会产生错误的业务顺序：

```text
旧目录读取被淘汰
        ↓
错误返回 []
        ↓
登录恢复链误判为目录读取完成
        ↓
再次启动患者同步，制造重复 Provider 请求/同步租约竞争
```

`[]` 只能表示服务端明确返回的成功空目录，不能同时表示“请求已淘汰”。

## 修正后的不变量

首页目录读取现在只返回两个生命周期结果：

- `loaded`：当前请求仍然拥有页面写回资格，并且已经把本轮目录提交到页面状态；登录恢复或主动登录可以继续患者同步。
- `superseded`：请求在成功或失败回调阶段已经被新的读取/页面生命周期淘汰；它不是空目录，调用链必须停止，不得启动同步。

成功响应和失败响应都先检查页面请求守卫。这样即使 Provider 返回 200，但响应落地前已经有新一轮读取开始，也不会把旧快照当成当前目录。

## 代码与测试

- `apps/miniprogram/src/pages/index/index.ts`：页面目录读取改为显式返回 `loaded/superseded`，登录恢复链和主动登录链只在 `loaded` 时调用 `onSyncPatients()`。
- `apps/miniprogram/src/services/patient-bootstrap.ts`：集中定义目录生命周期结果及后续同步门禁，并用中文注释说明不能把淘汰当作空目录。
- `apps/miniprogram/src/services/patient-bootstrap.test.ts`：覆盖淘汰结果不得启动同步。
- `apps/miniprogram/scripts/acceptance.test.ts`：更新首页并发边界验收，禁止重新引入 `return []` 兼容分支。
