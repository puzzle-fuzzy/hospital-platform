# 患者范围只读请求会话代际审计（2026-08-22）

## 结论

已修复一个真实的客户端时序缺口：页面先检查会话代际、随后再调用普通 GET 时，普通 GET 可能因
401 自动登录并重放请求。若此时患者上下文仍携带旧的 opaque patient ID，就可能让旧患者 ID
跨到新登录会话中。即使页面最终丢弃了旧响应，患者 ID 已经越过错误会话边界，这不符合患者隔离要求。

本轮没有修改旧 Python 服务、线上配置、数据库、Redis 或 Provider 自动化代码。

## 修复边界

`requestWithStableSession` 只允许患者范围的 GET 使用，调用入口同步固定：

- 当前 token；
- 当前 session generation；
- 页面传入的 expected session generation。

固定入口不执行自动登录、不跨代重放；如果 token 或代际在发出 `wx.request` 前已经变化，则请求直接
停止。如果请求收到 401，只清理仍属于同一代的旧 token，不误删更新后的新会话。现有页面代际守卫
继续负责丢弃返回期间已经过期的页面结果。

受影响的只读链路包括预约历史、爽约记录、报告目录、报告详情和门诊费用；患者目录本身仍按服务端
登录/同步协议单独处理，不把患者 ID 读取重试混入普通会话恢复。
