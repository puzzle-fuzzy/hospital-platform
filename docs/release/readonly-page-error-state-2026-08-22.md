# 患者范围页面错误态收口记录（2026-08-22）

## 发现的问题

预约历史、爽约记录、报告目录和门诊费用页在请求失败后都会清空患者和列表读模型，顶部虽然会显示错误提示，
但 WXML 后续仍可能落入“空列表”分支，把依赖未配置、会话失效、患者映射失败或 Provider 暂时不可用误显示为
“暂无数据”或“请先选择就诊人”。本轮继续审计又发现患者选择页和预约目录页存在同类问题：同步失败可能落入
“暂无就诊人”，科室/排班失败可能落入“暂无科室/暂无排班”。这些都不符合 fail-closed 约束。

## 当前修正

- 九个页面都在成功空列表或级联内容分支之前增加独立错误分支；当前覆盖首页、“我的”、患者选择、预约目录、预约记录、爽约记录、门诊费用、报告目录和个人资料；
- 错误分支显示明确的“本次数据未加载成功”状态，不伪造临床空结果；
- 所有上述页面都提供“重新加载”；首页复用健康检查、会话和患者目录刷新编排，“我的”页重新组合 `/me`、普通资料和患者目录，患者范围页重新执行当前页面完整的会话、患者目录和业务只读链路；
- “选择就诊人”重新进入统一患者选择页，避免页面清空患者上下文后失去换号入口；
- 患者选择页重试完整执行平台目录读取和临床映射同步；预约目录页重试完整执行科室和排班两层读取，
  不复用错误时保留的旧快照；
- 核心方法和 WXML 分支均补充中文注释，说明错误态与成功空结果的边界。

## 验收边界

本修正只改变小程序错误态渲染和恢复入口，不改变服务端 contract、Provider 请求、数据库、Redis、支付、医保或旧 Python 服务。
必须通过小程序定向测试、TypeScript 检查、构建和 `runtime:verify` 后，才能把当前运行包交给真机验收；真实 Provider 成功或空结果
仍需页面、客户端请求和服务端低敏日志三层证据，不能由本地错误态测试代替。
