### 2.1 真实瞬态故障与恢复

同一真机在 16:24:07 发起患者目录读取时，新 API 记录了 `patient.directory.read.requested`；
16:24:08 以 `503` 结束，安全诊断字段为 `PersistenceUnavailableError`、
`persistenceOperation=read`、`persistenceErrorCode=PROTOCOL_CONNECTION_LOST`。
这说明用户偶尔看到“数据服务暂时不可用，请稍后重试”确实有一次真实数据库连接层瞬断作为依据，
不是微信授权弹窗缺失，也不是把旧服务路由到了新服务。

随后 16:58:49 的存活探针、16:58:51 的 readiness 探针和系统 ping 均返回 `200`；readiness 明确显示
数据库、Redis、schema 均为 `ok`。新服务进程自 13:42 启动后持续运行，没有因本次故障重启；旧 Python
服务没有修改或重启。

当前行为保持 fail-closed：MySQL 仓储只对幂等读做固定的短退避恢复尝试，仍无法取得连接时返回 503；
小程序清理未经本轮确认的患者卡片并保留可重试入口，不能把这次故障降级成空目录，也不能无限自动重放。
因此，本次瞬态已定位但不等于数据库稳定性问题根治，后续仍需观察同类 `PROTOCOL_CONNECTION_LOST` 是否复发。

## 4. 关于“微信授权弹窗”

本项目使用 `wx.login()` 的静默登录方式，只兑换一次性 code，不读取头像、昵称或手机号。因此真机扫码或点击登录时没有“获取用户信息”
授权弹窗是预期行为，不是授权失败。若产品后续需要头像/昵称，必须另行设计用户主动触发的资料授权流程，不能混入医疗身份登录。
