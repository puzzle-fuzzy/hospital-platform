# 小程序普通资料响应运行时契约校验（2026-08-19）

## 结论

本次只收紧新小程序的客户端边界，不修改 Elysia API、MySQL、Redis、Provider、旧 Python 服务或线上发布。
`GET /api/v2/me/profile` 和 `PUT /api/v2/me/profile` 的成功响应现在必须经过完整 canonical 资料快照校验，
才会进入资料页面或保存成功分支。

## 为什么需要这层校验

TypeScript 的 `UserProfileResponse` 只在编译期生效，微信请求拿到的 JSON 仍可能因为反向代理、版本错配或异常
响应被客户端误认为正确对象。资料页如果接受缺少 `data`、非法性别、越界年龄、字符串版本号或异常邮箱类型，
就可能显示半套资料，并在下一次保存时使用错误的版本号。

客户端现在复核以下运行时事实：

- 成功外壳必须是 `success: true` 且包含 `data` 对象；
- `displayName` 必须是 1 至 64 个 Unicode 字符；
- `gender` 只能是 `male`、`female` 或 `unknown`；
- `age` 必须是 `null` 或 0 至 150 的安全整数；
- `email` 必须是 `null` 或不超过 320 个 Unicode 字符的字符串；
- `version` 必须是 0 至 `4294967295` 的安全整数。

这些检查只负责阻止协议错配进入页面；服务端仍是字段格式、权限、归一化和版本条件更新的唯一权威。
校验失败统一使用 `provider-response-invalid`，不把异常响应降级成默认资料，也不自动重放 PUT。

## 验证范围

- 新增纯函数测试覆盖完整快照、缺失字段、非法枚举、越界年龄、字符串/越界版本和异常邮箱类型；
- `pnpm check` 必须继续通过后才能进入提交；
- 本次没有执行真实资料 PUT，也没有把开发者工具或真机观察写成业务成功证据。
