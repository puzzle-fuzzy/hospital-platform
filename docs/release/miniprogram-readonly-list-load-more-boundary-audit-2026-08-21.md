## 发现的问题

预约历史、爽约记录、报告目录和门诊费用都把服务端一次完整只读结果保存到页面，再用“加载更多”控制首屏渲染数量。旧 WXML 事件可能在刷新、切换患者、切换费用状态或会话代际变化后抵达；如果页面只依赖按钮当时是否显示，事件就可能继续修改已经失去业务上下文的本地窗口。

## 修正规则

四个页面的 `onLoadMore` 现在统一遵循以下顺序：

1. 加载中或没有当前患者时直接忽略事件；
2. 患者或会话代际已经变化时，重新建立当前 `/me` → 患者目录 → 业务读模型组合，不展开旧快照；
3. 当前结果确实还有未展示记录时才计算下一窗口；
4. 下一展示数量必须严格大于旧数量，并限制在本次完整结果总数内。

这项规则只保护客户端渲染生命周期，不新增 Provider 分页语义、不改变金额/预约状态、不触发支付、医保、预约写入或 HIS 回写。
