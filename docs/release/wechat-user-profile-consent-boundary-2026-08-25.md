## 1. 问题和结论

微信登录成功只证明平台会话已经建立，不能从 `wx.login()` 结果推导昵称、头像或性别。此前“我的”页
只显示服务端普通资料默认值“微信用户”和默认头像，因此出现“正在获取用户信息”后仍没有真实资料，
不是患者目录或登录接口可以解决的问题。

当前方案分成两个明确阶段，但资料读取已经提升到 App 级：

1. 首页启动时由 `global-user-profile.ts` 单飞恢复当前 Bearer 会话并读取普通资料；服务端资料、owner、
   会话代际和当前设备已有的微信资料缓存进入 App 全局快照。四个主 Tab 和资料页只订阅这份快照，不在每次
   `onShow` 时重复读取 `/me/profile`，也不会把已确认昵称临时清成“正在获取用户信息”。
2. 首次头像昵称授权仍只能由用户点击“我的”页头像或授权提示触发，之后由同一个全局仓库完成本机缓存、
   页面同步以及默认昵称的 `version` 条件写入。授权弹窗和资料 PUT 在 App 内单飞，多个页面不会并发触发两次。

微信官方原生资料授权接口要求由用户点击触发，且返回的是 `userInfo` 展示资料；本项目因此不在登录、
`onShow`、患者同步或预约请求中触发授权。[微信小程序全局配置与接口说明](https://intl.cloud.tencent.com/zh/document/product/1219/61710)

## 2. 当前实现

### 2.1 展示来源

| 展示内容 | 来源 | 当前边界 |
| --- | --- | --- |
| 昵称 | 服务端 `GET /me/profile`；默认值时可使用微信授权昵称 | 服务端已保存的自定义昵称优先，授权不会静默覆盖 |
| 性别 | 服务端普通资料；首次授权时可补全 | 只保存 `male`、`female`、`unknown`，不推导实名或医疗结论 |
| 头像 | 用户主动授权返回的 HTTPS URL；为空时使用默认占位图 | 只按当前 `user.id` 写入本机缓存，不写入服务端，不当作永久头像 |
| 年龄 | 服务端普通资料或资料页显式编辑 | 微信资料授权不提供年龄，不能猜测 |
| 邮箱 | 服务端普通资料或资料页显式编辑 | 微信资料授权不提供邮箱，不能猜测 |

### 2.2 App 全局资料生命周期

| 阶段 | 统一行为 | 页面行为 |
| --- | --- | --- |
| 小程序启动 | 首页启动全局资料仓库，恢复会话并读取 `/me/profile` | 只显示稳定占位，不重复发起资料请求 |
| 切换主 Tab | 复用同一个已完成或在途 Promise | 订阅快照，不清空昵称头像 |
| 进入“我的” | 资料仓库已经 ready 时直接消费；患者目录仍单独刷新 | 只重新确认就诊人，不重新获取个人资料 |
| 进入资料页 | 消费服务端普通资料字段 | 编辑的是服务端 canonical 资料，不把本机临时昵称当作已保存事实 |
| 资料保存成功 | 更新全局服务端快照和 version | 返回“我的”即可看到新昵称/性别 |

普通资料接口暂时不可用时，仓库保留已经完成的会话 owner，并把错误降级为个人资料提示；就诊人、预约等
主流程不因头像资料增强失败而被伪装成未登录。明确会话失效时才清空全局资料，防止账号切换残留。

### 2.3 授权状态

“我的”页资料卡使用以下状态，避免加载卡片和空资料卡之间突然跳变：

- `idle`：尚未在本设备授权，展示默认头像和“点击获取头像和昵称”。
- `loading`：正在等待微信授权回调，重复点击被忽略。
- `ready`：已经得到本机校验通过的昵称/头像；如果普通资料同步失败，提示中明确写“资料同步失败”，
  不伪造服务端保存成功。
- `declined`：用户拒绝或取消授权；页面保留可重试入口，不把用户选择记成登录故障。
- 基础库不支持 `wx.getUserProfile` 时单独显示版本能力提示，不把运行环境缺失误报成用户拒绝。

### 2.4 owner 隔离

本机缓存 key 为 `wechat-user-profile:{userId}`，值中再次保存 `ownerId`。读取时同时校验 key 对应的
owner 和头像/昵称格式；账号切换、空 owner、非 HTTPS 头像、控制字符昵称和不完整数据都不能进入页面。
空头像地址是合法缺省值，只会回退默认头像，不会丢弃已经授权的昵称。
缓存只承担短期展示，不改变患者选择、医疗身份或登录 session。

## 3. 普通资料同步规则

授权成功后，如果当前服务端昵称仍是“微信用户”，小程序发送：

```json
{
  "version": 0,
  "displayName": "微信昵称",
  "gender": "unknown"
}
```

真实性别会按微信回调映射为 `male` 或 `female`。请求不携带头像 URL、openid、unionid、encryptedData、
iv、年龄或邮箱。若服务端已有自定义昵称，则不发送昵称覆盖请求，页面继续显示服务端自定义昵称；头像仍可
作为本机展示资料显示。

服务端写入失败时，页面可以保留用户刚刚授权的本机昵称和头像，但必须给出“资料同步失败”提示并允许
重试。若授权期间会话代际发生变化，则丢弃本次页面上下文，不把旧账号的 `version` 写入新账号。

## 5. 真机验收清单

使用与当前源码 revision 对应的新 `dist` 预览包验证：

1. 打开小程序，首页启动后应自动完成静默微信登录和服务端资料读取；进入“我的”时昵称和基本资料不应因为 Tab 切换重新回到 loading。
2. 若当前设备此前已经授权，进入“我的”应直接显示当前 owner 的缓存昵称和头像；缓存没有头像时只回退默认头像，不丢弃昵称。
3. 首次没有授权时，不应在进入小程序时自动弹窗；点击头像或“点击获取头像和昵称”后才出现微信资料授权弹窗。
4. 同意后所有已打开页面应收到同一份昵称、头像和性别；服务端默认资料应只完成一次正常的 version 写入。
5. 拒绝后页面显示可重试提示，重新点击仍能再次发起授权，不影响已登录状态。
6. 资料页检查昵称、性别；年龄和邮箱没有服务端值时保持空值，不能被微信昵称授权流程填充。
7. 切换账号后不得出现上一账号头像或昵称；缓存失效后重新授权即可恢复。

以下能力仍不属于本次修复：永久头像上传、对象存储、头像内容安全审核、手机号/实名资料授权，以及医保
支付和医保电子凭证授权。
