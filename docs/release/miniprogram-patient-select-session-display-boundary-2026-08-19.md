# 原生小程序就诊人目录会话显示边界

> 记录日期：2026-08-19
>
> 目的：说明患者选择页在会话失效或账号切换后，为什么必须清理旧账号的患者目录，而不能只清除“当前”角标。

本修正最初在小程序候选 `d2086d8` 中观察，运行包来源指纹为
`d2086d819b3e393da2e8c5c39d7704012854214b`；它是历史代码证据，不是当前真机包。当前真机候选为
`3a66d12`，完整来源指纹为 `3a66d125b0c1ca53879dd88a3661e3025fb7dd3d`，尚未上传或替换线上小程序。

## 发现

患者选择页此前在同步失败时会清除 `selectedPatientId` 和 `selectionReady`，但保留已经渲染的患者列表，理由是让暂时故障可以保留诊断和重试线索。

这个策略没有区分依赖暂时不可用与会话归属失效：如果请求最终返回 `unauthorized`、`session-changed`，或自动重新登录失败后本地已经没有 token，列表中的姓名、关系和脱敏电子就诊卡仍可能属于上一账号。此时只清除“当前”标记仍然会把跨账号医疗目录留在页面上。

## 修正后的不变量

1. 患者目录中的每条展示记录都必须有当前微信会话 owner 的服务端读取证明；本地 token 存在本身不构成证明。
2. `unauthorized`、`session-changed` 或无 token 时清理患者列表、当前标记和临床可用门禁。
3. Provider、Redis、MySQL 等暂时故障仍可保留列表用于重试，但不得保留上一轮“当前”标记；这与会话失效的跨账号风险分开处理。
4. 清理只作用于页面派生状态，不删除本地 opaque `patientId`，不修改服务端目录，也不触碰旧 Python 服务、数据库或 Redis。
5. 重新建立有效会话后，必须重新读取 owner-scoped 目录并完成临床映射；不能从旧列表或本地缓存直接恢复当前患者。

## 实现与证据

- `apps/miniprogram/src/pages/patient-select/patient-select.ts` 新增 `shouldClearPatientDirectory`，区分会话归属失效和暂时依赖错误。
- `clearDisplayedPatientDirectory()` 统一清理患者列表、当前标记和 `selectionReady`，但保留本地选择用于后续 stale 判断。
- `apps/miniprogram/scripts/acceptance.test.ts` 新增门禁，确认会话失效时清除整个目录，而不是只清除当前角标。
- 修正落地时小程序测试为 131 项、1095 次断言，TypeScript 类型检查和 14 页面构建通过；这些是历史代码级证据，当前候选的全量门禁以路线图顶部记录为准，不替代真机账号切换和公网 trace 验收。

## 不扩大范围

本次没有新增患者绑定/建档接口，没有调用真实写入，没有改变 Provider 合同、支付、医保、二维码或报告 gate，也没有修改旧项目和线上旧服务。真实多患者切换、失效恢复和真机网络证据仍需单独验收。
