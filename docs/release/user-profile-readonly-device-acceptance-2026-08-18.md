# 普通资料真机与日志验收手册（2026-08-18）

本文只验收普通资料的读取、版本条件更新和并发冲突，不验收实名资料、头像、患者关系、医保身份或任何支付能力。
当前配套服务端 release 为 `1b94c46`，小程序运行包来源必须为完整
`691ba28053775bce84f1285583c6741018eb0d40`。旧 `mp-weixin` 项目、旧 Python 服务和旧接口不属于本手册证据。

## 1. 业务不变量

1. owner 只能从当前 Bearer 会话解析，客户端不能提交 `userId`、openid、unionId 或患者标识来指定资料归属。
2. `GET /api/v2/me/profile` 返回的是普通展示资料；首次没有资料行时返回安全默认值，但不能因为读取默认值就创建数据库副作用。
3. `PUT /api/v2/me/profile` 必须携带当前 `version`，成功写入后版本严格递增一位；服务端不能静默忽略未知字段。
4. 两个设备使用同一旧版本时，只有一个更新可以成功；另一个必须得到 `409 user-profile-conflict`，不能返回 200 或覆盖新资料。
5. 输入校验、版本冲突和数据库/服务异常是三个不同结果：前两者是可解释的业务失败，后一种不能被页面伪装成保存成功。
6. 日志只记录 `traceId`、事件名、字段数量、错误类型和版本结果等低敏元数据；不能记录昵称、邮箱、userId、token 或原始请求正文。

## 3. 验收场景

### 3.1 首次读取与安全默认值

1. 新项目完成微信登录，确认进入“我的”页后打开普通资料页。
2. 记录 `GET /api/v2/me/profile` 的 HTTP 状态、请求 ID 和页面显示结果。
3. 如果账号没有资料行，页面应显示安全默认值并保持可编辑；不能因为默认值出现而声称资料已持久化。
4. 服务器应出现 `user.profile.requested` 和 `user.profile.loaded`，其中 `persisted` 只能反映是否存在资料行。

### 3.2 正常版本更新

1. 在资料页修改一个或多个普通字段并保存，提交的 `version` 必须等于刚才读取到的版本。
2. 验证 HTTP 返回 `200`，响应版本为原版本加一，页面提示保存成功并按原页面逻辑返回。
3. 服务器应在同一 trace 关联到 `user.profile.update.requested` 和 `user.profile.updated`；`fieldCount` 必须等于请求中明确出现的字段数量。
4. 重新进入资料页读取，确认新值和新版本来自当前 owner；不能只依据保存 Toast 判断成功。

### 3.3 两次保存的 409 并发冲突

使用两个同一账号的受控会话或同一页面的两份已读取版本快照：

1. 两次更新都携带版本 `N`，第一请求先成功，得到版本 `N+1`。
2. 第二请求仍携带版本 `N`，必须返回 `409`，错误码为 `user-profile-conflict`。
3. 页面应提示“个人资料已被其他设备修改，请下拉刷新后重试”，不能自动覆盖、无限重试或导航成保存成功。
   冲突提示出现后保存入口必须隐藏，页面只有重新 GET 到最新 `version` 后才能再次编辑提交旧字段；
   不能让用户继续使用同一过期版本反复 PUT。
4. 服务端应出现 `user.profile.conflict`；第二次请求不能出现 `user.profile.updated`，日志中不能出现字段值或 userId。

### 3.4 非法字段和输入边界

在不使用真实个人信息的受控测试数据下验证：

- 携带 `avatar`、openid 或其它旧端字段时返回 `400 validation`，不能静默删除未知字段后返回 200；
- 昵称为空、超过 64 个 Unicode 字符或含控制字符时拒绝；
- 年龄必须为 `0` 到 `150` 的整数，邮箱清空使用明确的 `null`；
- 版本达到 MySQL `INT UNSIGNED` 上限时在仓储写入前拒绝，不产生越界写入；
- 输入失败日志只记录 `user.profile.update_failed` 和固定错误类型，不记录非法值。

## 4. 证据接收门禁

普通资料只有在以下证据全部属于同一新项目、同一服务端 release 和同一时间窗口时，才能标记为“真机已验收”：

1. 页面截图或录屏能看出读取、编辑、保存和 409 提示；
2. HTTP trace 能关联 GET、成功 PUT、冲突 PUT 和验证失败响应；
3. 低敏服务日志同时具备 requested/result 或 conflict 事件，且 `parseErrors=0`、无 systemd warning；
4. 重新 GET 能证明成功写入的版本和值属于当前会话 owner；
5. 日志、截图和网络记录中没有 token、openid、unionId、userId、邮箱、真实昵称或原始 provider 内容。

单元测试、ready、模拟器页面和旧项目真机网络只能证明各自边界，不能单独通过本手册。
