# 就诊与互联网医院状态布局复核（2026-08-27）

本次复核只修正小程序状态卡片的视觉布局，不扩大任何业务能力，也不调用
Provider、支付、医保或 HIS。旧端和新端都允许这两个主 Tab 在服务尚未开放或
没有预约摘要时展示状态卡片，因此这类状态的排版本身属于可独立验收的迁移面。

## 发现的问题

`pages/consult/consult.wxml` 和 `pages/hospital/hospital.wxml` 的状态卡片都包含
图片、标题和说明，但对应 WXSS 只声明了 `display: flex`，没有声明
`flex-direction`。微信 WXSS 的 flex 容器默认按 `row` 排列，窄屏真机上会把状态
内容横向挤压，和旧页面的居中纵向空态不一致。

## 修正内容

- `consult-state` 明确使用 `column`、水平/垂直居中和居中文本；
- 互联网医院的 `state-card` 使用同样的纵向关闭态布局；
- 两个状态卡片仍保持 `380rpx` 固定高度，不因 loading、空态或迁移提示切换而跳变；
- 在小程序 acceptance test 中锁定两个 CSS 选择器的纵向布局，防止后续只保留
  `display:flex` 又退回横向错位。

这次只涉及小程序源码和自动化验收，不修改旧 Python 服务、数据库、Redis、线上
Elysia release，也不改变预约、实时叫号、互联网医院 WebView 或支付/医保关闭边界。

## 验证边界

本次可以由源码、构建和测试证明 CSS 规则存在；当前没有运行中的微信开发者工具
或真机会话，因此还不能把真机截图、设备像素效果或页面业务链路写成已验收。真机
恢复后应从当前 live `dist` 普通编译，重点查看就诊页三个状态和互联网医院关闭态
是否均为居中纵向排列，并继续保留客户端 requestId 与服务端日志的业务证据要求。
