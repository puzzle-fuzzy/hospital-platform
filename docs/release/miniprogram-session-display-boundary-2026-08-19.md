# 原生小程序会话与患者卡片显示边界

> 记录日期：2026-08-19
>
> 目的：说明首页在本地 token 存在但尚未完成服务端验证时，为什么必须先隐藏患者派生数据。

当前本地小程序候选为 `d2086d8`，运行包来源指纹为
`d2086d819b3e393da2e8c5c39d7704012854214b`；该运行包尚未上传或替换线上小程序。

## 发现

微信开发者工具复核首页时观察到 `/api/v2/me` 返回 `401/unauthorized`。新客户端的认证请求会清理旧 token，
并最多自动执行一次 `wx.login()` 重新建立平台会话；这条机制本身没有把 401 当成业务成功。

但首页旧的 `onShow` 只要发现本地仍有 token，就直接读取患者目录。请求等待期间页面可能继续保留上一次已经渲染的
患者卡片，形成“当前会话尚未证明，但页面仍显示旧患者”的短暂不一致。

## 修正后的不变量

1. 本地 `access_token` 只是待验证凭证，不是当前微信 principal 或当前就诊人的证明。
2. `onLoad`、后续 `onShow` 在 `/me` 或患者目录恢复开始前，先清除 `selectedPatient`、患者数组和展示用
   `selectedPatientId`。
3. 清除展示不删除本地显式选择。恢复成功后仍由 owner-scoped 患者目录解析；如果原患者消失，必须进入 stale，
   不能静默切换到目录第一位。
4. 目录读取成功后才把页面会话状态恢复为“已恢复会话”；读取失败则区分 `invalid` 与 `unavailable`，不保留旧患者卡片。
5. 该修正只作用于新小程序客户端，不修改旧 Python 服务、线上路由、MySQL、Redis 或 Provider 数据。

## 验证边界

- 原生 acceptance 新增顺序门禁：`clearDisplayedPatientContext()` 必须出现在 `onShow` 的 `loadPatients()` 之前。
- 开发者工具已确认首页可进入独立“选择就诊人”页面，患者目录成功显示；关系枚举 `other` 由展示层翻译为“其他”，
  不代表后端返回了中文文本。
- 这次修正和模拟器观察不替代真机微信会话、多患者切换、Provider 业务、公网 HTTP trace 或正式发布包验收。
