# 原生小程序开发者工具只读观察记录（2026-08-18）

本文记录本次重启后，在微信开发者工具中对新项目包的只读观察结果。它用于补充验收证据，不等同于真机验收，也不替代服务端业务日志和公网链路证据。

## 1. 操作边界

- 只操作新项目 `hospital-platform/apps/miniprogram` 对应的微信开发者工具窗口。
- 未打开、修改或重启旧 Python 项目；旧服务端口 `8001` 未参与本次客户端操作。
- 只访问登录恢复、患者目录同步和患者选择页面。
- 未点击添加就诊人、预约提交、支付、医保授权、退款或其他医疗写入入口。
- 页面中的真实姓名、卡号和身份标识不写入本文；截图和 Network 证据也必须继续脱敏。

## 2. 已观察结果

### 2.1 页面和患者上下文

新项目模拟器成功加载以下页面：

- 首页：患者卡片、服务入口和固定底部导航可见。
- 我的挂号：患者选择行、院区行、在线挂号/全部挂号标签和空态可见。
- 选择就诊人：页面包含“添加就诊人”入口、患者卡片、关系标签“其他”、当前标签、脱敏电子就诊卡和“刷新就诊人”按钮。

当前页面展示的关系标签来自服务端患者读模型的 `relationship` 字段，前端只做枚举映射；“其他”不是前端凭空推断的患者关系。脱敏卡号由服务端返回脱敏读模型，前端不接收完整卡号再处理。

### 2.2 患者目录刷新

在“选择就诊人”页面点击一次“刷新就诊人”后，开发者工具 Network 面板观察到：

| 项目 | 结果 |
| --- | --- |
| 请求类型 | XHR |
| 请求标识 | `sync` |
| HTTP 状态 | `200` |
| 传输大小 | 约 `816 B` |
| 耗时 | 约 `1.74 s` |
| 观察来源 | 新项目模拟器 Network 面板 |

页面刷新后仍保持患者选择页结构，没有出现旧患者卡片与新列表混合、未完成同步就允许继续、或前端生成完整身份字段的现象。

### 2.3 “我的”页面视觉对照

模拟器打开“我的”页后，观察到顶部背景、家庭成员管理卡片、三组四列菜单、旧端图标和固定底部导航均正常显示。三组标题都显示为“我的订单”并不是新端误写：旧项目 `G:\fuck\hospital\hospital-app\src\jsonData\userNavData.json` 的三个原始分组标题就是同一文本；新端保留该重复标题属于视觉一致性要求，不在本轮擅自改成新的分类名称。

“我的挂号”页使用独立页面布局，不额外显示“我的”页底部导航；“我的”页底部导航的当前项为“我的”，与首页共用同一套本地图标资源。

### 2.4 门诊缴费只读页面

模拟器打开门诊缴费页后，页面展示了当前就诊人、待缴费/已缴费两个标签，以及两条明确的只读边界提示：当前只展示查询结果，支付、退费和医保结算以医院正式渠道为准；支付调起、医保授权和结算回写需独立业务契约验收后开放。当前测试账号没有可展示的费用记录，页面保持空态，没有出现支付按钮或伪造金额。

该页面观察仍只属于开发者工具模拟器 UI 证据。Network 面板没有形成可与服务端低敏业务事件对齐的完整费用请求证据，不能据此宣称门诊费用 Provider 查询已经完成验收。

### 2.5 报告目录依赖失败边界

模拟器打开报告目录后，客户端向公网 Hospital API 发起了报告目录只读请求；Network 面板观察到该请求返回 `503`。页面没有展示伪造的空报告列表，而是显示“报告服务暂未配置完成，请联系管理员”。

本次记录只保留路径和状态的低敏摘要，患者参数以 `<opaque-patient-id>` 表示，不写入真实内部标识。该结果说明报告依赖未配置时的用户态错误边界生效，但不代表 LIS/PACS/ECG Provider 已接入；在取得真实报告 contract、字段白名单、详情引用 TTL 和服务端成功事件前，不继续实现报告详情或附件下载。

### 2.6 预约目录只读结果

从首页进入医院前置页再进入预约目录后，模拟器显示了旧端一致的两列级联布局：左侧科室列表，右侧当前科室的日期、医生/门诊和号源摘要。Network 面板观察到排班请求返回 `200`，页面显示一个排班和一个号源摘要；请求日期窗口为当前中国标准时间起连续 7 天，内部科室参数以 `<opaque-department-id>` 脱敏记录。

本次只验证目录读取，没有点击号源确认，也没有触发锁号、预约提交、取消或支付。页面底部仍明确提示“当前为预约目录查询”，因此目录成功不能被记录为预约成功；预约写入 gate 继续关闭。

## 3. 会话日志解释边界

本次模拟器导航期间控制台曾出现一次 `/patients` 的 `401`。随后页面能够继续完成患者读模型展示和 `sync` 请求 `200`，与客户端“收到会话失效后清理本地令牌、单飞重新登录、只重试一次”的设计一致。

该现象只能说明模拟器观察到了会话恢复路径，不能单独证明微信登录已经在真机、当前生产 release 和真实 Provider 链路上验收通过。后续必须用同一候选包在真机保存页面截图、HTTP `requestId/traceId` 和服务端低敏业务成功事件；如果重试后的最终请求仍为 `401`，必须停止该业务域并回到身份链路排查。
