# 患者关系“其他/未知”语义边界（2026-08-20）

## 结论

本次修正了患者目录中关系缺失被错误归类为“其他”的问题。新服务现在明确区分：

- `other`：Provider 明确返回 `other` 或“其他”；
- `unknown`：Provider 没有返回关系，或返回了平台暂时无法识别的关系。

小程序选择页分别显示“其他”和“关系未提供”，不再把关系资料缺失伪装成真实业务分类。

## 修改边界

- Elysia 公共契约、领域校验、MySQL 读写枚举和小程序运行时校验同步增加 `unknown`；
- 众阳 adapter 只把明确的 `other/其他` 映射为 `other`，默认回退改为 `unknown`；
- 未修改 Provider 请求参数、旧 Python 服务、旧数据库表结构或线上配置；现有 `relationship` 字段为有限字符串，`unknown` 不超过既有长度约束，无需数据库迁移；
- 未开放患者新增、绑定家属或任何支付/医保写入能力。

## 验收

- adapter 测试覆盖关系缺失、中文明确“其他”和英文明确 `other` 三种结果；
- domain 与小程序运行时测试覆盖 `unknown` 的合法传递；
- 文档已同步公共 API 和小程序患者读模型契约；
- 真实 Provider 关系字段和真机多患者数据仍需在用户提供当前候选二维码及服务端低敏日志后验收，不能用本地测试替代。
