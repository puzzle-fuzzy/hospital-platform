# 小程序选择页会话代际边界（2026-08-19）

## 1. 本次修正

选择就诊人页面可能在页面栈中停留较久。若其它页面在同步完成后重新登录或轮换
平台 token，原选择页仍可能保留上一会话的姓名、关系和脱敏卡号；仅依赖页面请求
序号无法识别这种“请求已经完成后会话才变化”的情况。

本次在新原生小程序中为选择页增加进程内会话代际标记：

- 患者同步开始时记录当前会话代际；
- 同步结果回写前再次校验代际，变化时以 `session-changed` 进入既有 owner 失效清理；
- 用户点击患者时再次校验代际，旧列表先清空，再重新读取当前会话目录；
- 代际只保存在页面实例的 `WeakMap`，不写入 WXML、微信 storage 或网络请求；
- 页面卸载时删除实例标记，避免页面栈长期保留非渲染状态。

核心注释位于 `apps/miniprogram/src/pages/patient-select/patient-select.ts`，说明了
“请求完成后账号变化”和“旧 patientId 不能交给首页猜测归属”的原因。

## 2. 业务不变量

这项修正不会改变以下既有规则：

1. 选择页必须等待医院目录同步完成后才能点击患者返回；
2. `stale`、`unavailable` 和 `empty` 继续保持不同语义；
3. 旧患者不会静默替换为目录第一位患者；
4. 小程序只保存平台 opaque `patientId`，不保存 Provider 患者号或身份证；
5. 预约、报告和门诊费用仍由服务端执行最终 owner 校验。
