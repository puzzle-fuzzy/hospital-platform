- 被裁剪的文本字段：10 条，但旧导出只保留聚合计数，当前无法定位到正文；

质量告警不能由迁移工具自动“修正后发布”。重复关系需要确认是否是同名不同药品，控制字符需要内容责任人决定删除还是重新导出，裁剪字段必须取得可定位的脱敏内容源。

## 4. 本轮结论

- 健康百科的页面、API、领域校验、MySQL 单事务导入和撤回边界属于代码已准备状态；
- 源快照质量和临床审核仍未通过，不能把当前 15,668 条旧内容导入 staging，更不能挂到生产患者端；
- 不能用“过滤坏行后剩余内容”替代完整质量处理，否则会产生看似成功但内容不完整的医疗知识版本；
- 下一个可执行输入是由内容责任人提供独立审核 bundle，随后按 [`../migration/health-knowledge-import-runbook.md`](../migration/health-knowledge-import-runbook.md) 走只读校验、staging 导入、发布撤回演练和真机验收。

## 5. 对全量迁移的影响

B 批次继续等待真实审核材料；C 临床只读、D 患者与便民写入、E 外部入口和 F 支付医保不因本次审计而顺延或偷换契约。各域保持自己的状态页和准入门禁，下一批材料到达时可以并行进入各自的 contract → adapter → API → 小程序 → 测试链路。
