# 添加就诊人改由公众号绑定（2026-10-26）

## 当前流程

用户在就诊人选择页点击“添加就诊人”，小程序打开百灵的医院公众号就诊卡页面。患者在该页面完成绑定，再点击左上角返回小程序；选择页会同步当前微信账号的真实就诊人目录。

固定入口为：

```text
https://cx.o2o.bailingjk.net/wechat/#/bluser/userCard/index?publicNoCode=gzh-048400_0001
```

入口与现有互联网医院 Tab 共用 `services/bailing-patient-card.ts`，仅追加加载时间戳。由百灵页面自行进行网页微信授权，不固定示例链接中的个人 `userId`，也不携带其嵌套 `redirectUrl`、平台 token、患者姓名、证件号或手机号。不接受路由传入任意网页地址。

## 暂停范围

`pages/patient-binding/patient-binding` 保留原路径，内容改为固定 WebView。小程序内姓名、手机号、身份证号表单和提交动作暂停，进入该页面不会再获取旧服务登录 code，也不会调用平台 `POST /patients/bind` 来查档、建档或绑卡。

服务端原有绑定接口代码和配置保留，未因本次小程序入口调整被删除或重新部署。患者目录查询与同步继续使用原有当前账号校验，不直接在平台数据库中补建关联。

## 返回和失败处理

- 返回时沿用选择页的绑定返回标记，只发起一次目录同步；同步结束前保持加载状态，避免提前显示空列表。
- 网页打开、网页消息和返回动作都不代表绑定成功，以目录返回的就诊人为准。若未完成绑定，返回后仍展示实际目录结果。
- 网页无法加载时提供重试及返回操作，并提示可在高平市人民医院公众号完成绑定，再返回小程序刷新就诊人。
- 平台账号切换时移除当前 WebView，卸载时释放页面监听；重试重新检查平台登录状态。

## 验证边界

本地测试验证固定地址、拒绝路由注入、页面不再提交绑定、错误与重试、账号切换清理及返回同步。构建与运行包校验不能证明百灵当前网页授权或实际绑定已经成功。

真机需确认小程序业务域名已配置 `cx.o2o.bailingjk.net`，并核对百灵授权跳转链实际需要的域名。使用当前微信账号完成一次绑定，返回后检查目录是否出现对应就诊人；本次实现不自动提交真实患者资料或补做医院绑定。
