# 管理端支付记录身份查询

支付记录的“姓名/用户名”同时匹配就诊人姓名和下单用户的普通资料名称，支持名称片段查询。下单用户可能代缴，不能视为微信钱包的实名付款人。

“就诊人身份证号”使用完整 15 位或 18 位身份证号精确匹配，末尾小写 `x` 会统一为大写 `X`。两个条件同时填写时取交集，并继续结合日期、来源、业务、状态和订单号筛选。查询回到第一页，刷新和翻页保留已应用条件，重置清空筛选。

身份证号仅在受保护的管理端支付历史中展示，来源是对应订单已有的加密自费或医保结算上下文，不扩大患者端公共资料模型，也不调用医院接口。只投影明确的就诊人证件号，不下发整份上下文、支付凭证或微信身份；未留存、格式不合法或证件别名冲突时显示“未留存”。因此未留存证件号的订单不会被身份证条件命中。

带姓名或身份证筛选时，服务端先核对候选数量，再完整读取有界候选、筛选、计算总数和分页，避免只过滤当前页。查询范围超过 10000 条或计数与读取期间发生变化时，明确提示缩小日期范围或重试，不返回不完整匹配结果。并发读取最多 8 条；不带身份筛选保留原分页路径。

旧管理端与 Admin2 使用同一受保护历史接口和代理参数白名单；查看账号与操作员的现有权限保持一致。新增搜索内容不写入应用日志。部署与业务验收以实际运行包和只读检查证据为准。
