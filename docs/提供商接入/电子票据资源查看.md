# 门诊电子票据查看

## 查看链路

查看已开具票据只读，不复用 `2.6.29` 开票命令：

```text
小程序 GET /api/v2/payments/outpatient/invoices/{recordId}/resource?patientId=...
  → 会话鉴权和当前用户/就诊人映射校验
  → 2.6.17 重新读取并匹配原发票、结算主键生成的 recordId
  → 校验已开具状态和医院返回资源地址
  → https://gpsrmyy.meiyi.pro/proxy/forward（现有二进制资源中转）
  → 医院票据 HTTP 资源
  → 返回严格校验的 PNG/JPEG/PDF，经平台 HTTPS 接口供原生预览
```

请求仅接受平台 `recordId` 和内部 `patientId`，不能由客户端指定 URL、医院主键、资源路径或中转目的地。新资源响应不包含院端地址或密文；既有列表中的原链接仍可供用户确认后复制到浏览器查看。

## 当前配置与资源边界

- 生产组合根仅在电子票据查询已配置、`ZHONGYANG_BASE_URL` 为 `https://gpsrmyy.meiyi.pro` 根地址时启用资源网关，复用该中转，不新增域名或通用代理配置。
- 医院源默认只允许 `http://111.111.111.52:18003`。
- H5 仅允许 `/medical-web/industryMain.do?method=displayH5&ciphertext=<十六进制密文>`，不能变更 method 或追加参数。
- 静态资源限定同源 `/medical-web/` 下 PNG/JPEG/PDF 文件，查询参数仅允许可选的 `ciphertext`。不携带平台/众阳 Token、Cookie 或其他用户鉴权头。
- 支持直接图片/PDF，以及 H5 中唯一、明确的静态图片/PDF资源；不运行脚本、不透传 HTML、不猜测动态接口。静态资源不明确时返回不可预览提示。
- 文件须同时通过 MIME、实际魔数及 8 MiB 大小检查；资源请求最多 20 秒，且不超过调用上下文截止时间。H5 最多 12 MiB。
- API 到中转使用 HTTPS 且不跟随外层重定向。现有 Java 中转内部的 HTTP 客户端属于已有受信传输边界，外层 `redirect: manual` 不表示限制了其内部重定向。
- 返回 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`；各次用户访问仍需遵守现有隐私日志策略。

## 小程序行为

下载只访问平台 API，携带当前会话鉴权。下载前、完成后和打开前均核对会话代际、当前就诊人和页面请求代际；切换用户/患者、刷新或卸载后，旧响应不得打开票据，相关临时文件会被清理。原生图片使用 `wx.previewImage`，PDF 使用 `wx.openDocument`。

按钮显示加载状态并阻止重复点击。原 Base64 图片仍可预览，但使用独立文件名并检查实际图片格式。错误提示不再把“无法预览”说成对微信后台域名配置的检测结果；有医院原链接时，用户可确认复制，失败不清空票据、不重新开票。

这条原生图片/PDF链路不使用 WebView；小程序仍须在微信后台将平台 HTTPS API域名配置为合法下载域名。源码与本地构建不能替代该后台配置或真机验收。

## 2026-10-26 核验边界

现有中转的 `UnifiedProxyController` 已只读确认支持字节流及 Content-Type 转发，`type` 缺省为 `auto`、`download` 缺省为 `false`；无需修改或重启中转。

医院原 `111.111.111.52:18003` 票据页面从开发机访问返回 502，从 API 服务器和中转机直连均超时。因此尚未验证该院实际 H5 的结构兼容性，也未完成真实票据预览验收。仅接入中转不能证明医院源站已经恢复。

本地验证使用虚构票据和受控网络桩，覆盖归属校验、不开票、资源限制、中转映射、超时、患者/会话切换、临时文件清理、图片/PDF预览与失败提示。真实票据、链接密文和凭据不写入本说明或测试。
