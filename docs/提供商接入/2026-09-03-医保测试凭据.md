## 5. 当前冻结项

- 不注册任何医保 API，不实现 SM2/SM4 代码，不向测试或生产医保环境发送真实请求；
- `MEDICAL_INSURANCE_READY` 保持关闭；反馈单与旧 env 凭据不进入 `.env.example`、

- golden vector 仍缺失：实现 crypto 前必须先用旧 Java JAR 离线生成参考向量并双向验证，
  不得凭规范文本直接写密码实现。

## 6. 下一步执行顺序

crypto 实现必须走四层验证链，任何一层失败不得进入下一层；旧 Java JAR 只是其中一层的差分基准，
不是真值来源（旧生产配置 `MBS_SM2_VERIFY_STRICT=False`、`MBS_KEEP_PLAINTEXT_INPUT=True`，
旧实现的验签方向从未被严格执行，加密路径也存在保留明文的折扣）：

1. 国标公开测试向量（GB/T 32905/32907/32918）验证 SM2/SM3/SM4 原语；
2. 按规范文本的签名拼接、JSON 键排序、空值剔除与 `appId` 派生密钥规则编写单测；
3. 与旧 Java JAR 在大量随机与边界输入（中文、空值、长报文、金额小数）上做差分测试；
4. 受控窗口用测试环境凭据做最小链路验证（如 1101）：对方接受我方 envelope，且我方能用
   平台公钥验签并解密回包，方为端到端事实；此后再议 contract 修订与 `MEDICAL_INSURANCE_READY`。
