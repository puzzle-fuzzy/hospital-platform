## 本次确认的关键结论

这份文档明确把挂号和诊间支付放在同一个“统一下单”接口中，并通过 `order_type` 区分业务类型，不是两个完全独立的下单地址：

```text
https://api.weixin.qq.com/payinsurance/unifiedorder?access_token=ACCESS_TOKEN

order_type=RegPay      挂号支付
order_type=DiagPay     诊间支付
```

同一个字段还列出了 `InHospPay`（住院缴费支付）、`PharmacyPay`（药店支付）、`InsurancePay`（保险费支付）、`IntRegPay`（互联网医院挂号支付）、`IntReDiagPay`（互联网医院复诊支付）和 `IntPscPay`（互联网医院处方支付）等类型。

因此，对当前问题的准确表述是：在这份国家局 v4.0 的移动医疗平台接口合同里，“挂号支付”和“诊间支付”共用统一下单接口，业务差异由 `order_type` 和费用/医保字段表达。

## 统一下单请求中已核对到的字段

页面中的请求参数表包含以下字段（类型和必填性以页面原表为准）：

- `order_type`：支付类型，必填；
- `appid`、`mch_id`：公众号 ID、商户号，必填；
- `sub_appid`、`sub_mch_id`：子商户公众号 ID、子商户号，按模式选填；
- `openid` / `sub_openid`：用户标识二选一；
- `hosp_out_trade_no`：第三方服务商平台生成的订单号，必填；
- `hospital_name`：医院名称，必填；
- `nonce_str`：随机字符串，必填；
- `total_fee`：订单总金额，单位为分，必填；
- `cash_fee`：现金应付金额，纯自费金额，必填；
- `cash_add_fee`：医疗机构额外增加的现金金额，选填；
- `cash_add_wording`：额外现金金额文案，选填；
- `cash_reduced_fee`：医院减免的现金优惠金额，选填；
- `allow_fee_change`：是否允许预结算费用发生变化，必填；`0` 不允许，`1` 允许；
- `spbill_create_ip`：用户端 IP，必填；
- `notify_url`：微信支付异步通知地址，必填；
- `limit_pay`：是否限制信用卡支付，选填；
- `body`：商品描述，必填；
- `return_url`：支付后回跳页面，公众号场景使用；
- `pay_type`：支付方式：`1` 现金、`2` 医保、`3` 现金+医保，必填；
- `city_id`：城市 ID，必填；
- `consume_type`：医保部分扣费类型，选填，默认 `0`（统筹+个账）；
- `insurance_fee`：医保支付金额，使用医保支付时必填；
- `user_card_type`、`user_card_no`、`user_name`：参保人证件类型、证件号码、真实姓名，使用医保支付时必填；
- `is_dept`：医保标识，页面标注 `is_dept=4` 为医保电子凭证支付；
- `serial_no`：医院 HIS 系统订单号，必填；页面特别说明它要与 `[6201]` 医保明细上传中的 `medOrgOrd` 保持一致，否则会支付失败；
- `org_no`：医保提供的医疗机构编码，必填；
- `gmt_out_create`：医院下单时间，格式 `yyyyMMddHHmmss`，必填；
- `request_content`：医保结构化信息透传字段，必填；示例包含 `payAuthNo`、`payOrdId`、`setlAt`；
- `bill_no`：业务单据号，选填；
- `extends`：扩展字段，选填；
- `attach`：附加数据，选填；
- `channel_no`：腾讯工程师分配的渠道号，必填；
- `sign`：签名，必填；
- `use_sandbox`：是否使用沙箱，选填；文档说明测试环境需要传 `1`，且测试用户需要绑定测试环境医保电子凭证。

页面还特别给出费用关系：`total_fee` 是总金额，`cash_fee` 是现金应付金额，`insurance_fee` 是医保支付金额，`cash_add_fee` 是机构额外增加的现金金额，`cash_reduced_fee` 是机构减免金额。当前项目如果支持三种支付按钮，不能只传一个总价，必须以医保结算返回的真实费用明细计算并校验这几个字段。

## 返回和后续接口

- 公众号返回示例：统一下单成功返回 XML，包含 `return_code`、`result_code`、`med_trans_id`、`pay_url`、`nonce_str`、`sign` 等字段；
- 小程序返回示例：同样返回 `med_trans_id`、`pay_url` 等字段，并额外有 `pay_appid`；示例中的 `pay_url` 是小程序支付页面路径；
- 查询支付单：
  `https://api.weixin.qq.com/payinsurance/queryorder?access_token=ACCESS_TOKEN`
  请求参数使用 `med_trans_id` 或 `hosp_out_trade_no` 二选一，并带 `nonce_str`、`sign`；
- 支付结果通知：由统一下单时提交的 `notify_url` 接收。文档强调同一通知可能重复发送，服务端必须先锁定并检查业务状态，重复通知直接返回成功；即使收到通知，也建议主动查询支付单，以 `med_trade_state` 作为最终状态；
- 申请退款：
  `https://api.weixin.qq.com/payinsurance/refund?access_token=ACCESS_TOKEN`
  文档说明该接口需要 IP 白名单，并建议退款前先确认医保部分已经退款；纯医保退款应在省中台退完医保部分后再调用腾讯退款接口；

## 与新版接口的边界

这份文档标题明确是“国家局 v4.0”。主文档已明确提示旧指引停止更新，并给出新版微信支付官方 v3 文档入口。因此这里确认的是旧版移动医疗平台适配器的真实接口关系，不能直接把 `payinsurance/unifiedorder` 当成当前新版 v3 合同；后续改代码前仍需以当前使用的真实众阳/医院适配器合同和新版官方接口逐字段对齐。
