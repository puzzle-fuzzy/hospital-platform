## 4. 材料与配置字段的对应

| 材料字段 | 使用位置 | 核对要求 |
| --- | --- | --- |
| 移动支付渠道应用标识 | `MBS_APP_ID` | 从对应环境的移动支付反馈材料确认，不与微信小程序 AppID 混用 |
| 数字密钥 | `MBS_APP_SECRET` | 按对应环境配置，用于业务数据加解密 |
| 渠道 SM2 私钥、己方公钥 | `MBS_SM2_PRIVATE_KEY_B64`、`MBS_SM2_OWN_PUBLIC_B64` | 与正式渠道已上报公钥及实际 SDK 配置匹配 |
| 平台 SM2 公钥 | `MBS_SM2_PLATFORM_PUBLIC_B64` | 使用正式平台材料，并取得回包验签证据 |
| 机构渠道认证编码 | 本地正式材料的 `identityVerificationFeedback.orgChannelAuthCode` | 主小程序构建注入；测试和正式材料分别存放 |
| 机构编码、线上业务类型 | 对应机构配置与 `medicalBizType` | 按正式身份核验材料核对；本次没有推测或改写标识值 |

移动支付反馈单说明要求：切换正式环境前，渠道侧须自行生成渠道公私钥并上报公钥。
正式 PDF 中出现密钥字段，不等于已完成该流程；本次未生成密钥、上报公钥或验证其正式可用性。
真实密钥、应用/渠道标识和机构渠道认证编码不写入本页、源码、测试 fixture 或日志。

`MEDICAL_INSURANCE_CREDENTIAL_ENCRYPTION_KEY` 是本平台持久化医保凭证的加密密钥，
不属于上游反馈单材料，不因渠道地址切换而随机轮换，否则可能导致已有凭证无法解密。

## 5. 本次完成与待确认边界

本次完成的是本地分支、配置默认值、材料选择路径和对照文档。没有修改服务器环境文件、
发布服务、启动 Worker、执行数据库迁移或向医保、HIS、微信发送业务请求。
现有 `MEDICAL_INSURANCE_READY` 等模板开关继续关闭。

正式业务启用前还需要确认：

1. 正式 userQuery 的 partnerId、渠道应用、机构认证材料，以及已上报的正式渠道公钥。
2. 正式材料通过既有密钥管理流程落入实际部署环境。本次没有将 PDF 凭据提取成可用环境文件；
   主小程序缺少正式机构渠道凭证时会注入空值，现有授权前置检查会阻止继续跳转。
3. 正式回包验签。`MBS_SM2_VERIFY_STRICT` 当前仍保留原有兼容默认 `false`，不代表正式验签已通过；
   正式启用应取得平台公钥/SDK 验签证据并明确严格模式配置。
4. 使用当前正式分支生成运行包，并分别记录授权、1101、userQuery、医保业务、微信及 HIS 的实际验收结果。

这些待确认项不改变已按所有者要求准备的三个正式配置：授权 `release`、1101 `50080`、
用户查询 `receiver.wecity.qq.com`。正式医保业务端口另已确认为 `56380`。
