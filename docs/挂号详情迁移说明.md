# 挂号详情迁移说明

## 迁移结论

新服务已经把旧服务的“挂号详情”迁移为真实的患者端详情能力：新服务预约记录点击后进入详情页，平台预约通过服务端详情接口读取；没有平台详情引用的历史 Provider 记录，只展示列表中已经核实的安全摘要。

旧端页面证据：

- `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/hospital/registration_detail.vue`
- `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/user/my_registration.vue`

旧端详情展示范围是医院、科室、医生/类型、就诊日期和时段、号序、挂号费、就诊人及预约状态，并提供取消预约入口。旧端详情没有独立的详情 Provider 接口，主要使用挂号列表返回的数据和页面参数渲染。

## 新服务调用链

```text
挂号记录列表
  -> 读取 owner-scoped 预约记录
  -> 新服务预约带 opaque appointmentId
  -> GET /api/v2/appointments/registrations/{appointmentId}?patientId={patientId}
  -> 服务端校验当前会话、owner、就诊人和预约归属
  -> 返回脱敏挂号详情
```

详情接口对应的内部路由是 `GET /api/v1/appointments/registrations/{appointmentId}`，公网由 Nginx 映射到 `/api/v2`。接口只返回当前账号可以查看的详情字段：医院、科室、医生、日期、时段、时间、号序、金额、预约状态，以及姓名和脱敏就诊卡。

## 字段迁移边界

| 旧端内容 | 新端处理 |
| --- | --- |
| 医院、科室、医生 | 由服务端详情响应返回 |
| 就诊日期、上午/下午、具体时间 | 由服务端详情响应返回；页面只做显示格式化 |
| 号序、挂号金额、预约状态 | 由服务端详情响应返回，金额使用分保存 |
| 就诊人姓名、就诊卡 | 服务端按 owner 和 patient 校验后返回，卡号只返回脱敏值 |
| 身份证号、完整手机号、Provider 患者号 | 不迁移到小程序详情页 |
| Provider 原始预约号 | 不作为页面参数或公共接口字段；只保留在服务端取消映射中 |
| 历史 Provider 记录 | 没有平台 `appointmentId` 时，使用已校验列表摘要展示，不提供取消或支付写操作 |
| 取消预约 | 只有新服务已建立平台详情引用的预约显示取消按钮，调用 `POST /api/v2/appointments/registrations/{appointmentId}/cancel` |

`appointmentId` 是新服务内部的受控详情引用，不是众阳的 `appointmentInfoId`，也不能由小程序自行拼接或替换。

## 与支付页面的边界

挂号详情页只负责查看挂号记录和取消预约，不在主小程序中重复实现支付。自费、医保支付和混合支付仍由 `miniprogram-pay` 通过对应支付接口处理；支付结果由服务端订单和预约记录关联，主小程序重新读取挂号记录即可看到最新状态。
