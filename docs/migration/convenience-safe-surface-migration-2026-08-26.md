# 电子锦旗与表扬信原生安全页面迁移（2026-08-26）

## 本轮范围

本轮横向推进两个便民业务域：电子锦旗和表扬信。旧端分别存在列表、赠送/提交和记录详情页面，当前新端将它们收口到两个原生页面入口：

- `pages/gift-banner/gift-banner`；
- `pages/health-praise/health-praise`。

本轮迁移的是旧端能够确认的页面结构、当前就诊人入口、错误重试和稳定关闭态，不代表内容 Provider、审核或提交能力已经完成。

## 已迁移行为

- 页面进入后读取全局当前就诊人，并允许进入统一患者选择页；
- 旧端列表/记录区域保留固定高度的插图和“公开记录暂未开放”状态；
- 患者读取失败显示顶部红色错误区和显式重试，不把错误降级为“暂无记录”；
- 通过统一 `FeatureKey` 进入完整迁移状态说明；
- 页面只使用本地受控图片，不把旧端患者/医生快照、文件 URL 或 Provider 原文带入小程序。

## 明确未迁移

以下能力仍保持关闭，不能由本轮页面结构推导出来：

- 公开记录查询、赠送/提交和详情读取；
- 患者、医生、就诊引用的服务端归属；
- 文本/图片审核、内容安全、脱敏公开和管理端读取；
- 幂等、撤回、失效、分页和留存周期。

“公开记录暂未开放”是服务能力关闭态，不是 Provider 成功返回的空列表；没有正式 contract 前不能显示“暂无记录”，也不能出现提交成功 Toast。

## 验证

- TypeScript 检查通过；
- 小程序回归：`303 pass / 0 fail / 3462 expect()`；
- 页面广度审计继续覆盖 40 个注册页面和全部 WXML 事件；
- 本轮没有修改旧 Python 服务、线上服务、数据库、Redis 或另一会话负责的众阳预约适配器。

正式开放前需分别完成内容 Provider contract、审核/脱敏规则、写入幂等和撤回审计，不能与临床病历或支付业务共用接口。
