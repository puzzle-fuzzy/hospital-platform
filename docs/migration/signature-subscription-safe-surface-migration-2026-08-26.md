## 2. 本轮实现

### 患者签名

- 使用 `/patients` 的 owner-scoped 脱敏读模型，列表只展示平台 contract 允许的姓名、关系和脱敏电子就诊卡；
- 当前已有明确选择时恢复选中态，不因为列表顺序静默选择第一位患者；
- 从选择页返回后重新读取目录，避免继续展示旧账号或旧患者快照；
- 支持“选择其他就诊人”进入统一 `/pages/patient-select/patient-select`；
- 加载、顶部红色错误、重试、空目录和固定高度状态容器均已补齐；
- 点击可用患者只更新当前页面的视觉选中态并提示“签名功能尚未开放”，不修改全局患者、不上传文件、不调用 `navigateToMiniProgram`。

旧端性别和手机号不在新端公开患者 contract 中，因此没有猜测字段或拼接假数据。签名真实开放前仍需要用途/同意、文件安全、短期访问、撤回、医护读取和审计 contract。

### 消息订阅

- 保留旧端的橙色提示、当前就诊人入口、标题搜索、四类提醒和分类折叠布局；
- 当前就诊人由统一的 `loadCurrentPatient()` 读取，切换入口回到统一患者选择页；
- 搜索和折叠只改变页面本地展示；
- 开关固定为关闭且显示“暂未接入”，底部动作改为“查看完整迁移说明”和“返回我的”；
- 未调用 `wx.requestSubscribeMessage`，未写入用户订阅状态，未显示“设置已保存”，也没有把医院静态信息伪装成动态选择。

真实开放前必须确认模板 ID、授权时机、业务事件、患者/账号作用域、授权回执、发送结果、失败重试、撤销和审计日志。
