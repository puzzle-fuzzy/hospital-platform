# 临床只读域批量迁移合同门禁（2026-08-25）

> 本文是批次 B 的执行清单，不是接口实现。当前四个域均未注册新 API、未安装生产 adapter、未打开小程序业务入口。
> 旧端页面和接口声明只能证明历史行为，不能直接成为新端 contract。收到正式 Provider/HIS 材料后，必须按域新增
> 版本、指纹、脱敏样例和验收证据，不能直接把 `normalized` 改成 `confirmed`。

当前仓库的机器门禁为 `pnpm clinical:contract:audit`，并已纳入 `pnpm check`。它只校验四域的准入文档、FeatureKey、状态页落点和 API 未注册状态；通过不代表任何临床业务已经开放。

## 1. 为什么要拆成四个独立域

旧端把门诊记录、住院、医生关系和问诊都放在“健康/我的”入口下，但它们的权威来源、患者标识、权限和保留周期不同。
如果先做一个通用 `/clinical` 或万能转发，会产生四类不可接受的问题：

1. 把门诊 `patId`、住院号、医生内部 ID 或问诊会话号暴露给小程序；
2. Provider HTTP 200、业务拒绝、权限不足、映射缺失和真实空结果被折叠成同一个空列表；
3. 病历正文、住院费用、医生关系和问诊内容共用错误的 owner/患者授权；
4. 页面完成会被误认为业务完成，后续无法判断是哪一层真正可用。

因此本批次只允许以下纵向路径逐域落地：

```text
正式资料登记
  -> 请求/响应/错误/脱敏差异表
  -> contracts schema
  -> adapter 白名单与错误归一化
  -> owner-scoped domain service
  -> persistence（有跨请求引用时才增加）
  -> Elysia route
  -> 原生小程序页面
  -> Pino 与客户端 requestId 同链日志
  -> 内网、公网、真机和越权验收
```

## 2. 四个域的迁移矩阵

| 域 | 旧端入口 | 目标只读能力 | 当前状态 | 第一项可执行工作 |
| --- | --- | --- | --- | --- |
| 门诊就诊记录 | `pagesB/health/electronic_record.vue` | 门诊就诊摘要目录 | `normalized / 未注册` | 取得 `out-visit-records` 的正式 contract、患者映射和四类脱敏响应 |
| 住院信息 | `pagesB/health/inpatient_center.vue` | 住院 episode 与基础状态 | `normalized / 未注册` | 确认住院患者标识、episode 权威来源、权限和时间/金额语义 |
| 我的医生 | `pagesB/patient/doctor.vue` | 当前医生关系只读目录 | `normalized / 未注册` | 确认受控医生目录、关系来源、在职/失效和展示白名单 |
| 我的问诊/电子导诊 | `pagesB/user/my_consultation.vue`、`pagesB/health/electronic_consultation.vue` | 会话索引或导诊摘要 | `normalized / 未注册` | 先区分内部读模型和外部主体，再确认 owner、回跳和保留周期 |

### 2.1 门诊就诊记录

- **候选公共输入**：仅接受平台内部 `patientId` 和服务端固定的中国标准时间日期窗口；小程序不能提交 `patId`、卡号、姓名、身份证或医院号。
- **候选公共输出**：只考虑 opaque `visitRecordId`、科室、医生、就诊时间、机构和有限就诊类型；`regId`、诊断、身份资料和原始正文不进入公共响应。
- **必须区分**：真实空目录、患者映射缺失、Provider 权限拒绝、依赖未配置、超时/限流和响应格式错误。
- **正文边界**：目录成功不等于病历正文、诊断、处方、附件可读；正文必须另有引用、TTL 和授权。
- **页面状态**：当前继续使用稳定迁移提示；取得正式 contract 后先做目录，不同时开放正文和附件。

### 2.2 住院信息

- **候选公共输入**：平台内部 `patientId`，由服务端解析当前 owner 下的住院 episode；不接受 `patInHosId`、住院号、婴儿号或 provider 查询参数。
- **候选公共输出**：住院状态、入院/出院时间、科室等经确认的摘要；费用、预缴、结算和病历内容必须拆开。
- **必须确认**：一个患者是否可能存在多个 episode、当前 episode 的选择规则、已出院记录保留期、时间时区和状态撤回语义。
- **支付边界**：住院信息只读完成后也不能跳住院缴费；金额单位、订单 owner、查单和 HIS 回写属于最后的支付批次。
- **页面状态**：当前继续使用 `inpatient-center` 状态页，不能用门诊预约或门诊费用数据补齐。

### 2.3 我的医生

- **候选公共输入**：平台内部 `patientId` 或经服务端确认的关系引用；不能传旧库 `doctorId` 或任意医生 ID。
- **候选公共输出**：医生展示名、科室、职称等最小白名单；不返回联系方式、内部排班号、未审核头像地址或旧库快照全文。
- **必须确认**：关系是关注、曾就诊、当前责任医生还是推荐关系；重复关系、失效/离职、删除和患者切换必须有明确语义。
- **写入边界**：旧端使用客户端快照和非幂等操作，不能照搬；关注/取消若未来开放，必须是 owner-scoped 命令并有唯一约束和审计。
- **页面状态**：当前继续使用 `doctor` 状态页，不展示旧表 `my_doctor` 的库存快照。

### 2.4 我的问诊与电子导诊单

- **先拆主体**：我的问诊可能是内部会话索引，也可能跳到外部问诊主体；电子导诊单不能因为展示了科室/时间就复用预约历史。
- **候选公共输入**：平台内部患者引用、会话 opaque 引用或短期外部会话票据；不能接受 `appointmentInfoId`、Provider 患者号或旧 WebView URL。
- **候选公共输出**：仅输出会话状态、创建/更新时间和经确认的摘要；诊疗正文、处方、消息和模型结果必须有独立授权与留存规则。
- **外部入口边界**：域名 allowlist、短期票据、回跳路径、退出、超时、重复打开和失败回退必须先冻结，不能恢复通用 WebView。
- **实时边界**：旧端 WebSocket/叫号消息不能迁移为“今日就诊”事实；实时队列需要独立服务、心跳、断线和设备验收。

## 3. 每个域必须提交的最小材料

正式材料不足时，域保持 `blocked-provider`，不新增 schema、adapter、route 或假页面。最小材料如下：

| 材料 | 要回答的问题 |
| --- | --- |
| 文档版本与内容指纹 | 哪个环境、哪个版本、谁确认、何时生效和撤回 |
| 请求样例 | method、路径、认证、超时、重试、日期/分页和患者映射 |
| 成功样例 | 成功非空和成功空目录分别是什么，字段是否稳定 |
| 失败样例 | 业务拒绝、无权限、映射缺失、未配置、超时/限流和格式错误如何区分 |
| 字段白名单 | 每个进入小程序的字段来源、用途、长度、脱敏和空值语义 |
| 越权样例 | 同一用户访问另一患者、失效患者、失效引用时必须不触网或不泄露 |
| 日志要求 | 只保留平台 traceId、业务事件、错误分类和 Provider requestId；禁止正文、token、患者身份和原始 provider ID |
| 回滚方案 | adapter、配置 gate、数据库迁移和小程序入口如何独立回退，不能影响旧 Python `8001` |

## 4. 放行门禁

单个域必须同时满足以下条件，才允许从状态页进入业务页面：

1. contract 已进入 `packages/contracts`，并有运行时校验和未知字段拒绝；
2. adapter 在触网前校验输入，响应只映射白名单字段，provider ID 不进入公共响应；
3. service 强制 owner、患者和会话代际一致，跨患者请求在 Provider 之前拒绝；
4. 成功、空、未授权、暂时故障、依赖未配置和响应异常各有稳定错误语义；
5. 如有列表引用，必须有 TTL、复合 owner 约束和过期行为；
6. 页面覆盖加载、成功、真实空、错误、重试、患者切换和过多数据分批渲染；
7. 自动化门禁、服务端 Pino、客户端 requestId、Provider 低敏 requestId、公网和真机证据全部配对；
8. 通过发布候选验收后再打开 gate，不能因为本地 fixture 或页面截图提前改状态。

## 5. 本轮实际推进与停止点

本轮已完成两项不依赖 Provider 的广度工作：

- 健康百科搜索和详情页补齐固定高度错误态与“重新加载”，重试只复用已校验的症状/内容 opaque ID，不重新拼接外部参数；
- 四个临床只读域形成独立合同门禁，后续拿到任一域资料即可单独进入实现，不需要等待其它域，也不触碰另一会话的众阳预约适配器。

本轮不执行以下动作：

- 不把旧接口声明复制为新 adapter；
- 不从旧数据库快照、`patId`、卡号或 WebView 补齐业务；
- 不修改旧 Python 项目、旧服务、旧数据库和 Redis；
- 不把微信开发者工具锁住的旧 `dist` 当作新候选验收；
- 不提前打开报告详情、二维码、患者绑定、临床写入、支付、医保或 HIS 回写。

下一轮按“材料先到先做”的方式选择一个域进入正式 contract，但批次 A 的真实只读证据、批次 B 的四域合同、批次 C 的患者/临床写入准备和批次 D 的支付医保末批会并行维护，避免再次只盯一个页面。
