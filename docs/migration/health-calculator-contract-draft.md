# 健康自测计算器 Contract 草案

> 状态：`draft`，尚未完成临床审核，不得据此注册患者端页面、保存医疗结论或宣称“风险评估已迁移”。
> 盘点日期：2026-08-16。
>
> 本文覆盖旧端 BMI 和血压计算页面的本地行为审计，以及新端必须先确认的规则边界。它不是临床指南，
> 也不把旧页面中的阈值、说明文字或示例数据视为可继续使用的医疗标准。

## 1. 业务范围

本草案只覆盖：

- BMI 数值计算和分层展示；
- 成人血压输入的非诊断性参考提示；
- 输入校验、免责声明、规则版本和页面临时状态。

本草案不覆盖：

- 疾病诊断、用药建议、急救判断或个体化治疗方案；
- 儿童/青少年、孕妇、运动员、老年人或特殊疾病人群的专用评估；
- 家庭血压长期趋势、诊室血压、动态血压和医生确认；
- 风险评估问卷、随访、预问诊和任何患者医疗档案写入。

## 2. 旧端已确认的实现事实（不是新 Contract）

### 2.1 BMI 页面

旧页面 `G:\\fuck\\hospital\\hospital-app\\src\\pagesB\\health\\bmi_calc.vue`：

- 只在页面内读取身高 `CM` 和体重 `KG`，没有 provider 请求和数据库写入；
- 使用 `BMI = 体重(kg) / (身高(m)²)`，展示一位小数；
- 分类代码使用以下边界：`<18.5` 偏瘦、`18.5~<24` 正常、`24~<28` 偏胖、
  `28~<35` 肥胖、`35~<40` 重度肥胖、`>=40` 极重度肥胖；
- 页面下方的 WHO、亚洲和中国参考表使用另一组展示区间，且代码注释写有“数值可按规范微调”；
- 只检查输入是否为真值，没有完整的正数、上限、单位精度和特殊人群校验；
- 提示“理想的体重指数为22”，并声明结果仅供参考、以医生临床诊断为主。

因此旧端已经存在“计算代码、参考表和说明文字可能不一致”的事实，不能直接复制为新规则。

### 2.2 血压页面

旧页面 `G:\\fuck\\hospital\\hospital-app\\src\\pagesB\\health\\blood_pressure_calc.vue`：

- 页面输入年龄、性别、收缩压和舒张压，单位分别为岁、男/女和 `mmHg`；
- 低血压判断为 `收缩压<90 或 舒张压<60`；
- `收缩压>=140 或 舒张压>=90` 时继续分为一级/二级，其中 `>=160 或 >=100` 为二级；
- `收缩压>=130 或 舒张压>=85` 时显示“偏高”，否则显示“正常”；
- 年龄和性别只用于查找 16～55 岁的页面参考均值表，不参与上面的血压分类；
- 页面提示使用“1998年标准”，且将一次输入结果直接展示为状态；
- 输入只做非空式校验，没有完整的年龄范围、血压范围、重复测量、单位和异常值校验。

这意味着旧页面的参考均值、分类规则、适用人群和免责声明不是同一个版本的规则集，不能把页面能计算当作
临床逻辑正确。

## 3. 新端候选边界（待临床确认）

如果临床审核允许保留该能力，建议新端先做“本地临时参考计算”，不注册服务端写入 API：

```text
输入校验
  -> 选择明确的规则版本和适用人群
  -> 纯函数计算
  -> 展示数值、参考分类和限制说明
  -> 不保存、不上传、不生成医疗档案
```

候选不变量：

1. 页面必须携带不可变 `ruleSetVersion`，规则来源、审核人、审核时间和生效时间进入构建清单；
2. 计算函数只接收已经归一化的数值和单位，不接收任意 JSON 或客户端自定义阈值；
3. BMI 必须明确成人/儿童等适用人群；特殊人群不适用时显示“不适用”，不能套用成人分类；
4. 血压必须明确是“参考筛查”还是“临床分级”，默认只能做前者；单次测量不能生成诊断或用药建议；
5. 输入非法、超范围、单位不明或规则版本未知时拒绝计算，不返回看似正常的默认结果；
6. 页面不得把结果写入患者档案、报告、随访或风险评估，除非另有经过临床和隐私审核的持久化 contract；
7. 发生明显危险值时只能展示经过审核的就医提示，不能由前端自行编写急救结论；
8. 规则更新必须新增版本并保留旧版本解释，不能静默改变历史结果含义。

## 4. 临床/产品必须确认的问题

| 编号 | 必须确认的问题 | 未确认时的风险 |
| --- | --- | --- |
| HC-01 | BMI 规则适用人群、采用的权威来源、分界值和边界归属 | 不同人群套用错误标准 |
| HC-02 | BMI 参考表、分类文字和风险描述是否属于同一个规则版本 | 页面数值与解释互相矛盾 |
| HC-03 | 身高/体重允许范围、小数精度、异常值和单位换算 | 负数、极端值或单位错误产生假结果 |
| HC-04 | 血压能力是否只做教育性参考，还是允许临床筛查 | 把一次读数误认为诊断结论 |
| HC-05 | 血压分类的权威版本、阈值、边界和特殊人群策略 | 继续使用过时或不适用的 1998 年说明 |
| HC-06 | 年龄/性别是否真正参与血压分类，参考均值的来源和适用范围 | 输入字段看似有效但实际没有业务意义 |
| HC-07 | 收缩压/舒张压允许范围、单位、重复测量和异常组合校验 | 错误设备读数被正常展示 |
| HC-08 | 危险值提示的固定文案、适用条件和紧急就医入口 | 前端自行扩大为医疗建议或延误就医 |
| HC-09 | 是否允许保存历史结果；若允许，患者授权、版本、撤回和保留期限是什么 | 敏感健康数据无授权落库 |
| HC-10 | 规则变更、紧急下线、内容审核和发布回滚流程 | 已发布规则无法追溯或撤回 |

## 5. 推荐实现顺序

```text
临床来源与审核记录
  -> ruleSet contract / golden cases
  -> domain 纯函数与边界测试
  -> 页面输入校验与免责声明
  -> 无持久化原生页面
  -> 规则版本显示、紧急下线和构建门禁
  -> 开发者工具/真机验收
```

在 HC-01 至 HC-08 未确认前，禁止：

- 把旧页面的阈值和“1998年标准”迁入新端；
- 把 BMI/血压结果写入患者、报告或风险评估接口；
- 在页面中使用“诊断”“确诊”“治疗建议”或同等含义文案；
- 让用户传入自定义阈值，或以客户端结果作为医护侧权威事实；
- 用静态单元测试通过代替临床审核和版本发布证据。

## 6. 验收证据

| 层级 | 必须保存的证据 |
| --- | --- |
| 临床 | 规则来源、版本、审核人、适用人群、边界案例和危险值文案确认 |
| 代码 | 纯函数、边界/异常/未知版本测试；规则表与显示文字一致性测试 |
| 小程序 | 输入错误、超范围、不适用、结果、免责声明和规则版本展示 |
| 隐私 | 默认无网络请求、无本地敏感持久化、无医疗结论日志 |
| 发布 | 规则版本、下线开关、回滚和旧页面不受影响的证据 |

在上述证据完成前，迁移清单状态保持“待临床审核”，不计入患者端已迁移业务闭环。
