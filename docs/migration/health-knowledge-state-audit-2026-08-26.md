## 修正前的逻辑风险

当页面没有可复用的部位目录时，旧的 Tab 事件处理会直接调用 `loadSymptoms("")` 或 `loadDiseases("part", "")`。这会把以下情况错误地转成整体空态：

1. 页面第一次加载还没有形成目录；
2. 上一次目录请求失败，用户切换了另一个 Tab；
3. 较早请求被新请求淘汰后，页面暂时没有目录缓存。

这会让用户看不到“内容未发布/网络失败”的重试语义，也会让 UI 看起来像医院确实没有任何健康内容。

## 当前正确规则

`resolveKnowledgeTabSource(tab, cachedPartCount)` 现在固定以下决策：

| 条件 | 行为 |
| --- | --- |
| 有已确认的部位目录 | 两个 Tab 复用该目录，只读取关联内容 |
| 症状 Tab 没有目录 | 重新读取症状目录，不创建空 `partId` |
| 疾病 Tab 没有目录 | 重新读取疾病默认关系目录，不创建空 `partId` |
| 左侧目录已存在但右侧无内容 | 保留左侧导航，只显示当前分类空态 |
| 服务端无审核 bundle/请求失败 | 显示明确错误和重试，不降级成空目录 |

服务端仍是最终发布闸门：当前源快照 `publicationState=not-approved`，正式审核 bundle 不存在，因此健康内容继续 fail-closed。客户端本轮只是修正状态解释，不能把旧快照当作已审核医学内容。
