# 低风险业务域统一语义契约（2026-08-25）

## 目的

本文件把就诊人、预约、报告、门诊费用和普通个人资料五个已开放低风险域的页面状态统一成一套可检查的业务语义。它解决的是迁移广度阶段最容易被忽略的问题：页面虽然有接口，但失败时把错误画成空列表，或者把一个“正在请求”的中间状态误当成业务结果。

机器事实源是 [`tools/read-only-domain-catalog.mjs`](../../tools/read-only-domain-catalog.mjs)，审计命令是：

```powershell
pnpm readonly:audit
```

这份契约只描述新服务的代码边界，不代表 Provider、生产公网、微信真机或真实业务已经验收。五个域仍然不能据此打开预约写入、患者绑定、支付、医保或 HIS 回写。

## 统一状态机

| 状态 | 含义 | 页面允许展示 | 页面禁止做什么 |
| --- | --- | --- | --- |
| `requesting` | 请求尚未结束 | 保持稳定的加载占位，不改变卡片整体骨架 | 不展示“暂无记录”，不重复发起并发请求 |
| `success-non-empty` | 服务端确认有可展示数据 | 展示列表或资料 | 不从展示字段反推 Provider 原始身份 |
| `success-empty` | 服务端明确确认当前范围没有数据 | 展示稳定空状态 | 不把它当成网络失败，也不因为空结果继续调用写入能力 |
| `unauthorized` | 会话缺失、无效或过期 | 引导统一登录恢复流程 | 不带旧 token 重试，不把结果清空后伪装成空列表 |
| `invalid-input` | 客户端或服务端输入违反公开 contract | 展示参数错误和修正入口 | 不把非法查询继续透传给 Provider |
| `temporary-failure` | 数据库、Redis 或 Provider 暂时不可用 | 展示可重试错误，保留原有页面骨架 | 不降级为空数组，不产生业务写入 |
| `contract-invalid` | Provider 或内部读模型违反字段、身份或状态 contract | 展示数据异常和 requestId | 不猜测字段含义，不展示未经验证的原始内容 |

### 空结果规则

`success-empty` 只有在服务端明确返回成功包络、数据结构通过校验，并且 Provider/读模型明确表示当前范围为空时才能成立。以下情况绝不能转换成空数组：

- 会话无效、Redis/数据库/schema 未配置或暂时不可用；
- Provider 超时、拒绝、返回错误包络或字段不符合 contract；
- 当前用户与患者、报告、费用或预约记录的 owner 映射缺失；
- 读模型版本冲突、快照不安全、身份映射冲突或持久化校验失败。

小程序应把 `requesting`、`success-empty` 和错误状态分开管理。加载占位可以复用空状态的尺寸，但不能在数据请求完成前写入“未查询记录”，否则用户会看到空状态和错误状态之间不自然的跳变。

## 五个域的语义与关闭边界

| 业务域 | 成功空结果的含义 | 必须保留的错误语义 | 当前明确关闭能力 |
| --- | --- | --- | --- |
| 就诊人目录 | 当前 owner 没有可展示的就诊人 | 查询非法、同步冲突、快照不安全、Provider/持久化异常 | 新增绑定、实名关系变更、Provider 患者档案写入 |
| 预约目录与历史 | 当前筛选范围没有科室、排班或历史记录 | 查询非法、患者映射缺失、Provider/持久化异常 | 锁号预约、取消预约、HIS 回写 |
| 检查报告 | 当前就诊人没有可展示报告 | 查询非法、患者/报告不可用、Provider/持久化异常 | 影像/心电/体检扩展、附件、自动解读 |
| 门诊费用 | 当前就诊人没有可展示费用记录 | 查询非法、费用映射缺失、Provider/持久化异常 | 微信支付、医保授权/结算、退费及 HIS 回写 |
| 普通个人资料 | 当前用户尚未填写可选普通资料 | 字段非法、版本冲突、持久化异常 | 实名/微信身份、就诊人绑定、头像资源上传 |

## 错误码与日志要求

每个域的 `errorCodes` 必须同时能在服务端错误处理、小程序稳定文案表和公共 API 文档中找到。新增错误码时必须同步这三处，并补充对应的服务端/小程序回归测试；未知错误码不能直接展示 Provider 原始 message。

每次请求至少保留 `requestId`，业务失败事件只记录低敏的 owner、域、操作、错误分类和耗时，不记录 openid、session_key、AppSecret、身份证号、完整手机号、Provider token 或报告正文。成功空结果也应有正常的请求/完成日志，不能只记录失败。

## 继续迁移时的准入条件

后续病历、问诊、住院、医生、互联网医院、便民服务等域必须先复制这套语义结构，再接入自己的 Provider contract；如果不能证明成功空结果和失败状态可区分，就停在状态页，不创建“看起来能用”的空接口。支付、医保、结算和 HIS 回写仍然单独执行最后一批，不得借用本契约的只读状态机。
