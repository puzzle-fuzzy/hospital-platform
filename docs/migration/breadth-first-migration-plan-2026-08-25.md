因此下一步不再继续重复加固同一页面，而是按以下并行队列推进：

1. **批次 A：已有只读域统一取证。** 预约目录、预约历史、爽约、门诊费用、报告目录/详情和普通资料并行采集页面、HTTP、Pino、Provider 低敏请求号；不因空结果或依赖未配置标记成功。
2. **批次 B：临床只读 contract 并行冻结。** 门诊记录、住院信息、医生关系、问诊/电子导诊单和健康内容分别建立字段白名单、患者归属、错误分类和脱敏样例；材料先到先做，不共用 `patId` 或万能接口。
3. **批次 C：患者/便民/临床写入准备。** 患者新增/绑卡、二维码、预问诊、随访、风险评估、健康自测、锦旗和表扬信并行整理协议、版本、同意、幂等、撤回和审核清单；未冻结前保留稳定状态页。

## 三、下一批按业务域批量推进

### 批次 A：低风险只读与静态能力

优先把不涉及金额、医疗结论和写回的入口形成闭环：

1. 预约目录、预约历史、爽约记录：补齐真实微信页面、客户端 requestId、服务端 Pino 事件和 provider 同链证据。
2. 门诊费用只读：补齐待缴/已缴列表的真实 provider 样例、患者归属和空态，不接支付按钮。
3. 报告目录：先确认 LIS 摘要的真实字段；影像/心电/PEIS、附件和下载继续分开验收。
4. 普通资料：完成真实 GET/PUT/409 页面验收，保持头像授权与服务端资料边界分离。

### 批次 B：已有页面但 contract 尚未冻结的读模型

这批先完成 contract 和只读展示，不跨域复用患者 ID：

- 门诊病历：HIS/EMR 只读资源、字段白名单、owner/患者映射和脱敏失败样例；
- 我的问诊、电子导诊单、我的医生：会话/关系来源、内容保留和患者归属；
- 住院信息：独立住院患者标识、费用清单和权限模型；
- 健康百科：页面只读链路已接入；仍需版本化内容、临床审核、搜索索引、发布/撤回和下线审计。

每个域都必须完成 `contract → adapter → domain → persistence（如需要）→ API → 小程序 → 日志 → 验收`，不允许直接从页面调用旧 provider。
病历、住院、医生关系和问诊的并行材料入口固定为
[`../provider-intake/clinical-read-models-2026-08-25.md`](../provider-intake/clinical-read-models-2026-08-25.md)，
逐域放行门禁见 [`clinical-domain-batch-contract-gates-2026-08-25.md`](clinical-domain-batch-contract-gates-2026-08-25.md)。
收到材料后按域独立推进，不因为同属“健康”就共用 `patId`、通用响应或 WebView。

### 批次 C：写入与敏感医疗业务

这些能力需要单独的状态机和回滚证据：

- 患者新增、绑定、解绑、协议和签名；
- 二维码/就诊码：确认字段、有效期、签名、受众、防重放和撤销后再开放；
- 预约锁号、下单、取消、退号和 HIS 回写；
- 预问诊、随访、风险自评、健康自测、锦旗和表扬信。

旧端存在请求代码或页面，不能作为新端写入契约。缺少幂等、owner、撤回或审核规则时，继续保留状态页。

### 批次 D：支付与医保最后处理

微信支付、医保授权、1101/6201/6202/6301/6203/6401、结算、退款、查单和 HIS 回写统一最后处理。必须有金额单位、订单 owner、幂等键、回调/查单状态机、失败补偿和真实沙箱/生产验收；当前只读费用页不得跳入支付流程。

## 四、每批的完成定义

只有同时满足以下条件，才将矩阵状态从“迁移中/部分迁移”改为“已完成”：

1. 新端页面和 API contract 已注册，字段白名单与患者归属明确；
2. 成功、空结果、未授权、暂时故障和未知响应均有稳定读模型；
3. 服务端日志只记录低敏业务字段，并能用 requestId 与客户端链路关联；
4. 自动化测试、类型检查、运行包构建通过；
5. 真实环境页面、HTTP requestId、服务端日志和 provider 结果完成同链验收；
6. 文档、发布候选和旧服务共存证据同步更新。

## 五、当前明确不做的事情

- 不修改旧 Python 项目、旧 `8001` 服务、旧数据库和 Redis；
- 不因为“先全量迁移”而复制旧端 provider URL、完整身份证号、卡号、`patId` 或 token 到小程序；
- 不把状态页、Toast、空列表或本地计算结果包装成真实医疗业务成功；
- 不强制结束微信开发者工具进程，不删除被锁定的 live `dist/`；
- 不与另一会话负责的众阳自动化文件冲突。
