# 健康知识源快照质量分诊台账（2026-08-26）

> 本文只记录源快照的脱敏数量和处理边界，不包含疾病名称、药品名称、健康正文、患者字段或 Provider 原文。
> 数据来源为本机 `.local/health-knowledge/legacy-source-snapshot.json` 的只读审计；旧 Python 服务、数据库、Redis、线上进程和患者端 API 均未修改。

## 1. 当前结果

`pnpm health:quality:findings` 和 `pnpm health:remediation:ledger` 在同一份源快照上运行结果一致：

| 问题类型 | 数量 | 当前结论 | 自动修复 |
| --- | ---: | --- | --- |
| 疾病详情中的重复药品关系组 | 6 组 | 必须由内容责任人确认是重复导入、同名不同来源还是合法多关系 | 禁止 |
| 旧正文控制字符 | 115 个、分布于 26 个字段 | 必须重新导出并由内容责任人确认字符清理不会改变医学含义 | 禁止 |
| 首尾空白被记录的字段 | 10 个 | 旧导出只保留聚合数量，无法安全定位，必须重新导出后处理 | 禁止 |
| 缺少药品主键的可点击关系 | 0 个 | 当前没有发现可点击关系指向未知药品 | 不适用 |
| 被忽略的旧字段 | 1 个 | 需要确认是否进入正式 contract，不能静默塞进其他内容类型 | 禁止 |
| 被忽略的旧来源 | 1 个 | 需要单独决定来源、字段、权限和展示入口 | 禁止 |
| 源质量问题合计 | 133 条 | `source-quality` gate 阻断 | 禁止 |

源元数据仍为 `publicationState=not-approved`。即使 133 条源质量问题全部整改，仍必须等待独立临床审核 bundle；工程工具不得把“质量告警为 0”解释成“医学内容可发布”。

## 2. 分诊规则

### 2.1 工程可以继续做的事情

- 继续维护稳定 opaque id、字段白名单、禁止字段检测和质量摘要一致性校验；
- 生成不含正文的路径/数组下标/数量报告，供内容责任人在私有源文件中定位；
- 在没有正式审核 bundle 的情况下保持患者端健康知识 API `fail-closed`；
- 对重新导出的源快照重新执行 `source audit → quality findings → remediation ledger`，并检查质量摘要没有被手工改写；
- 准备 staging 导入、单事务回滚、重复导入、重叠版本和撤回演练的技术门禁，但不写入生产或 staging 内容。

### 2.2 必须由内容责任人完成的事情

- 对 6 组重复药品关系逐组确认关系语义，不允许按名称自动去重；
- 对 115 个控制字符逐字段确认清理结果，尤其是药品用法、禁忌和不良反应字段；
- 重新导出带字段定位信息的质量快照，补齐 10 个清理字段的位置；
- 为被忽略字段和被忽略来源单独提供 contract、来源、展示范围、权限和保留策略；
- 提交脱敏审核 bundle，包含 `contentVersion`、带时区 `reviewedAt`、审核责任人引用、生效窗口、固定免责声明和撤回依据。

### 2.3 明确禁止的操作

- 不批量删除重复关系；
- 不用正则自动改写健康正文后直接生成发布 bundle；
- 不把 `knowledge_tips` 等未定义来源强行映射为疾病详情或药品详情；
- 不因目录、搜索、详情页面已经存在就开放患者端内容；
- 不把源快照、质量台账或审核队列提交到 Git、运行包、日志、数据库或长期缓存。

## 3. 下一步接收门禁

收到新的内容材料后按以下顺序处理，任一步失败就停在该步，不切换患者端状态：

```text
重新导出源快照
  -> source audit 与质量摘要一致
  -> 内容责任人逐项审核
  -> 脱敏审核 bundle validator
  -> staging 单事务导入与失败回滚
  -> 发布/撤回/重复导入演练
  -> 同一运行包真机只读验收
```

本轮分诊只推进 B 批次的材料接收准备，不改变 64 个旧入口的迁移状态，不打开健康百科正式内容、自测题库、诊断结论、个体化用药建议或任何支付/医保能力。

## 4. 可复核命令

```powershell
pnpm health:source:audit
pnpm health:quality:findings
pnpm health:remediation:ledger
pnpm docs:audit
```

当前预期：源质量 gate 为 `blocked`、总 `publishable=false`；这些命令只读本机忽略目录，不访问数据库、Redis、Provider 或线上服务。
