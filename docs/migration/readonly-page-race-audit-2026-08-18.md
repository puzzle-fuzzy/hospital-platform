# 患者只读页面请求生命周期审计（2026-08-18）

本文记录当前 release `c26e696` 之后对患者端 P0 只读页面进行的代码级请求生命周期复核。
这里的“修复完成”只表示源码、构建和回归门禁已经覆盖，不表示已经取得微信真机、Provider
和公网三层业务证据。

## 审计范围

- 我的挂号：患者目录确认、预约历史查询、在线标签、院区弹层、科室位置弹层；
- 爽约记录：患者目录确认、过去 90 天预约历史查询和 `missed` 派生；
- 门诊缴费：患者目录确认、待缴/已缴状态查询和本地渲染窗口；
- 共用边界：页面实例级最新请求守卫、显式患者选择和失败态清理。

## 本轮发现与修复

预约记录页原本在 `showError` 中清空预约记录、患者上下文和科室位置弹层，但没有清空院区选择弹层。
如果用户在请求尚未完成时打开院区弹层，随后请求因为网络或 Provider 依赖失败，错误提示虽然已经写入页面，
却会被仍然存在的底部弹层遮挡；用户还可能继续停留在过期的院区交互层中。

现在错误态统一关闭 `showHospitalModal` 和 `showLocationModal`，并继续清空当前读模型。这样失败页面只保留
可见的错误信息和“重新选择就诊人”入口，不会把弹层中的静态院区内容误认为本次患者查询成功。

对应回归门禁位于 `apps/miniprogram/scripts/acceptance.test.ts`，验证错误处理函数显式关闭院区弹层。
该门禁是页面状态约束，不把字符串检查当作真机验收替代品。

## 未改变的业务边界

- 没有新增预约写入、取消、支付、医保、退款或 HIS 回写；
- 没有把小程序本地 `onLoadMore` 解释成 Provider 分页；
- 预约历史仍覆盖中国标准时间前后各 90 天，爽约记录仍只查询过去 90 天；
- 门诊费用仍只有待缴/已缴只读列表，真实支付和医保授权继续关闭；
- 本轮没有执行生产重启、数据库迁移或旧 Python 服务操作。

## 后续证据

下一步仍需在当前 release 上采集受控微信会话、患者显式切换、预约历史、爽约和门诊费用的 Provider、
公网以及真机页面证据。代码门禁通过、HTTP 200 或日志成功事件均不能单独标记这些业务已经完成。
