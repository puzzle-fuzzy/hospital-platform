# 当前就诊人上下文横向迁移记录（2026-08-26）

## 目标

本轮不继续深挖单个临床 Provider，而是先把已经存在的多类页面入口统一到同一套当前就诊人显示和切换规则，避免每个页面自行登录、重复同步或展示上一位患者的旧结果。

## 已覆盖页面

| 页面族 | 页面 | 本轮结果 |
| --- | --- | --- |
| 临床内容 | 入院预问诊、出院随访、预问诊、风险评估 | 统一当前患者卡片、重试和选择入口；业务 Provider 仍关闭 |
| 临床入口 | 门诊病历、住院中心、我的医生、电子问诊 | 统一当前患者卡片、重试和选择入口；正式字段 contract 仍待 |
| Provider 入口 | 预约详情 | 统一当前患者卡片、重试和选择入口；预约详情 Provider 仍待 |

电子锦旗、健康表扬信、采血预约等便民页面此前已使用同一类安全空态基础；本轮只扩展共享上下文，不改变它们的真实能力状态。

## 逻辑约束

1. 数据来源是当前登录 owner 的平台患者读模型；页面只拿 `displayName` 和 `cardNumberMasked` 两个展示字段。
2. 内部 `patient.id`、Provider `patId`、身份证号和完整卡号不能进入页面展示上下文。
3. 页面上下文不会调用 Provider 同步，不会创建预约、病历、支付、医保或任何患者写入。
4. 患者选择页返回后，页面在 `onShow` 重新读取当前患者；加载期间保留稳定布局，不将旧患者伪装成新患者。
5. 页面卸载、请求代际变化和 owner 失效时，旧响应必须丢弃；错误要区分未授权、未选择、临床依赖不可用和暂时不可用。
6. 当前患者卡片只说明页面作用域，不说明页面对应的真实临床或 Provider 业务已经可用。
