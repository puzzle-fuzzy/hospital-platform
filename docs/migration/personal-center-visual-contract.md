# 个人中心视觉与功能迁移契约

本文档冻结原生小程序“我的”和“我的挂号”当前应保持的旧端可见结构，供后续会话、页面重构和真机验收使用。
视觉一致不等于业务能力已经开放；未取得稳定 provider contract 的详情、预问诊、医生关系和医保入口必须继续保持安全提示。

## 1. 对照来源

旧端事实来源：

- `G:\fuck\hospital\hospital-app\src\pages\user\user.vue`
- `G:\fuck\hospital\hospital-app\src\jsonData\userNavData.json`
- `G:\fuck\hospital\hospital-app\src\pagesB\user\my_registration.vue`
- `G:\fuck\hospital\hospital-app\src\components\health\patient-hospital-selector.vue`

原生实现：

- `apps/miniprogram/src/pages/my/`
- `apps/miniprogram/src/pages/appointment-records/`
- `apps/miniprogram/src/assets/legacy-user/`

个人中心背景、默认头像、家庭成员箭头和 9 个菜单图标已从旧端资源复制到本地，并在 2026-08-17 通过线上资源响应做过逐字节校验。小程序不得重新改为 WXSS `background-image`，否则微信渲染层会再次报“本地资源图片无法通过 WXSS 获取”。

## 2. “我的”页面可见契约

必须保持：

1. 顶部使用 750×566 的旧端背景，按屏宽等比展示；头像区上下各 50rpx，头像 130rpx、白色 8rpx 边框、圆形；
2. 头像区点击进入普通资料页；普通资料不是微信授权、实名患者或医疗档案，不得把患者字段塞进资料 contract；
3. 家庭成员管理卡片宽 710rpx、高 120rpx、圆角 30rpx、蓝色渐变，点击进入独立的选择就诊人页面；
4. 菜单保留旧端三个同名“我的订单”分组、原顺序、四列网格、行列间距 20rpx、图标 50rpx 和文字 26rpx；菜单图标使用旧端本地资源，不能只保留文字或随意换图标；
5. 四个主 Tab 使用微信原生 `app.json.tabBar`，由框架统一持有底部导航和选中态；图标、选中图标以及“医疗服务 / 就诊 / 互联网医院 / 我的”顺序不变。页面内容必须为平台底栏预留空间，不能再复制自定义底栏 WXML。旧版“我的挂号”使用 `default` 布局，不渲染这组底部导航，原生挂号页不得额外添加底栏。

当前可用入口：我的挂号、爽约记录、意见反馈、患者选择和普通资料。我的问诊、门诊病历、电子导诊单、我的医生、智能客服、医保电子凭证保留旧端位置和图标，但分别显示迁移/授权状态，不能用 toast 伪造旧端页面已经完成。

## 3. “我的挂号”页面可见契约

必须保持：

1. 页面顶部是全宽的患者/院区两行选择区，下面紧接“在线挂号 / 全部挂号”双标签；
   就诊人行沿用旧端“姓名（编号）”的紧凑排版，但括号中的内容必须是平台返回的脱敏卡号，不能展示 Provider 患者号；
2. 页面使用旧端 `default` 布局，不显示首页/“我的”页的固定底部导航；列表只沿用旧端 `pb-20` 的底部留白，不为不存在的底栏额外增加安全区空间；
3. 列表区域使用 `#f5f5f5` 背景、32rpx 内边距、白色 16rpx 圆角卡片；科室、医生/院区、日期/时段、时间/序号和状态位置保持旧端层级，详情区间距沿用旧端 24/32rpx 节奏；双标签高度按旧端 `py-4` 固定为约 112rpx，列表底部 `pb-20` 固定为 160rpx，不能因原生换写而压缩纵向留白；
4. 已预约记录使用旧端蓝色预约状态图标，其他状态只展示服务端归一化后的中文状态；客户端不能解释 provider 数字状态；
5. 卡片保留“预问诊 / 院内导航”按钮位置和触摸反馈；院内导航只读取已经审核的静态科室位置，匹配不到时展示空态；
6. 结果过多时先展示 10 条，再在本地展开更多。这个分批只优化 WXML 首帧，不代表 provider 分页，也不能截断服务端事实；
7. 当前页面只使用 owner-scoped 内部 `patientId` 和脱敏患者字段。旧端曾把 provider 患者标识拼到详情/预问诊 URL，新端 contract 未冻结前不得恢复这种做法。

无记录空态继续使用旧端 `wd-icon name="file-text"` 的 48rpx 文件图标；原生端落为本地
`assets/legacy-user/empty-record.svg`，不复用首页的大型空服务插图，避免两个页面的空态层级发生视觉漂移。

挂号记录和爽约记录的卡片共用“科室/状态 → 医生与院区 → 日期/时段 → 号序 → 操作”的阅读层级；
爽约页只替换服务端已确认的状态文案，不增加客户端状态推断。查询加载、错误和合法空结果共用固定的
`query-state-shell` 外壳，内部内容切换不能改变卡片空间或把 Provider 错误降级为空结果。实现记录见
[`release/appointment-records-visual-state-shell-2026-08-24.md`](../release/appointment-records-visual-state-shell-2026-08-24.md)。

患者/院区行的灰色右箭头、院内导航弹窗的关闭和搜索图标也必须通过 `<image>` 使用本地资源：
`selector-arrow-right.svg`、`location-close.svg` 和 `location-search.svg`。家庭成员卡片使用的
`arrow-right.svg` 是白色圆形资源，只能用于蓝色家庭成员卡片，不能误用于挂号页的白色选择行。

双标签的业务语义需要单独说明：旧端“在线挂号/全部挂号”分别向 provider 传过不同的
`requestChannel` 值。新端在线范围固定使用已确认的微信渠道 `requestChannel=3`，排除服务端
明确归一化的 `cancelled` 记录；全部范围固定使用独立的 `requestChannel=4`，由服务端省略日期
参数读取完整历史并保留取消记录。小程序只发送 `scope=online|all`，切换标签会重新请求服务端，
不能复制在线结果或让客户端猜测渠道数字；详情、取消、预问诊和预约写入仍保持关闭。

## 4. 有意保留的业务差异

| 旧端入口 | 原生端当前行为 | 原因 |
| --- | --- | --- |
| 患者选择 | 进入独立患者选择页，返回后重新读取目录和业务数据 | 防止把普通微信用户、目录患者和临床 `his-patient` 混为一体 |
| 院区选择 | 保留旧端右侧箭头和底部选择面板；当前面板只展示并确认唯一的高平市人民医院 | 动态院区 contract 未确认，不能伪造其他院区或透传 provider 参数；取得 contract 后只替换面板数据来源 |
| 挂号详情 | 提示“挂号详情暂未开放” | 当前公共读模型没有稳定详情引用，列表索引不能当业务主键 |
| 预问诊 | 保留按钮位置并提示迁移中 | 旧 URL 需要患者/挂号/provider 标识，现阶段没有安全 contract |
| 预约写入、取消、支付、医保 | 不开放 | 这些是独立写入/支付状态机，不能由页面布局或旧字段推导成功 |

## 5. 验收要求

- 静态门禁：`apps/miniprogram/scripts/acceptance.test.ts` 必须覆盖页面入口、旧资源、分组顺序、底部导航、患者切换和只读边界；
- 构建门禁：`pnpm --filter @hospital/miniprogram build` 必须生成每个 `app.json` 页面对应的 `.js`，并拒绝 WXSS 本地 `background-image`；
- 真机验收：至少检查背景不变形、个人中心图标和分组、首页/“我的”页底栏固定、挂号页不出现额外底栏、患者切换后记录清空并重新加载、长姓名不撑破选择区、无记录/网络异常位置和迁移提示；
- 业务验收：详情、预问诊、预约写入、支付和医保仍需分别取得 provider 文档、脱敏样例、状态机和真实账号证据，不能用本页面视觉验收代替。
