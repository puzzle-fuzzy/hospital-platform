# 静态能力与关闭能力迁移真值审计

> 盘点基准：2026-08-17。本文专门区分“旧端已有行为已经被安全迁移”和“未来产品能力仍未开放”，
> 防止把静态页面、旧端假保存或注释掉的二维码误记成未完成的旧业务，也防止把页面存在误记成真实能力。

## 1. 结论

| 领域 | 旧端实际行为 | 新端状态 | 仍未完成的内容 |
| --- | --- | --- | --- |
| 意见反馈 | 只有 FAQ、客服电话和点击后的 Toast；没有提交 API、表单或工单持久化 | 旧静态行为已迁移；点击反馈显示明确的“迁移中”提示，拨号需要用户确认 | 真正的反馈/工单是新增业务，需定义内容安全、受理状态、客服端权限、撤回和保留期限 |
| 公众号说明 | 只有静态公众号名称和通知说明；二维码 WXML 已被注释，未调用关注或订阅 API | 旧静态说明已迁移；不把打开页面当作已关注 | 真实二维码、主体确认、关注状态、订阅消息授权和发送结果 |
| 医院列表 | `v-for="1"` 渲染一个固定医院卡片；“去挂号”进入旧预约入口，“查看路线”没有真实路线逻辑 | 单医院静态卡片和预约只读前置已迁移 | 动态机构/院区目录、坐标路线和多院区选择 |
| 院内导航 | 只展示本地 `map.jpg`，支持预览和失败提示 | 静态地图、`aspectFit` 和预览已迁移 | 楼层/科室实时定位、路线和地图服务 |
| 消息订阅 | 页面开关只改变内存中的 `notifications`，重新进入不会恢复；“确定修改”只显示 Toast，没有微信授权或后端请求 | 未注册，保持关闭是正确状态 | 模板 ID、授权时机、业务事件、患者/家庭成员范围、发送结果、重试和撤销 |
| “我的”页未开放入口 | 旧端展示电子导诊单、智能客服、我的问诊、我的医生和医保电子凭证入口；其中外部 WebView、医生关系和医保跳转不构成可用 contract | 新端保留入口位置并逐项显示迁移/授权未开放，不执行旧 WebView、旧关系接口或医保小程序跳转 | 导诊/问诊会话、医生关系 owner、外部入口 allowlist、医保授权和回调 contract |

## 2. 证据与边界

### 意见反馈

旧端 `src/pagesB/user/feedback.vue` 的 `handleFeedback` 只显示“跳转到意见反馈页面”的 Toast，
实际跳转代码被注释；旧服务路由盘点中也没有意见反馈提交接口。新端
`apps/miniprogram/src/pages/feedback/feedback.ts` 将该行为改成明确迁移提示，并保留 FAQ、客服电话、
用户确认后的系统拨号。这里没有丢失一个已存在的提交业务；如果未来要增加工单，必须作为新领域设计，
不能把 Toast 改成“提交成功”。

### 公众号说明

旧端 `src/pagesB/account/follow.vue` 中二维码区域是注释代码，页面没有微信关注状态查询、订阅授权或发送结果。
新端只复用静态通知说明和受控本地资源，并在代码注释中明确“打开页面不等于已关注”。二维码和订阅不是当前
旧页面的可用事实，后续必须取得主体、资源、授权和回调 contract 后单独实现。

### 消息订阅

旧端 `src/pagesB/user/subscription_message.vue` 的开关只修改页面内存对象；`handleConfirm` 直接显示“设置已保存”
并返回，没有 `wx.requestSubscribeMessage`、服务端保存或发送结果。新端没有注册一个等价的假设置页，避免把本地
UI 状态误认为微信授权事实。未来实现时必须拆开“微信授权事实”“业务事件订阅关系”和“发送结果”，并分别记录日志。

## 3. 迁移台账规则

1. 旧端确实只有静态行为的页面，可以标记为“静态行为已迁移”，同时在“未来能力”列保留动态扩展缺口。
2. 旧端只有假保存/本地状态的页面，不应通过复制假交互来宣称迁移完成；应保持未注册或明确迁移提示。
3. 注释掉的二维码、外部图片和旧入口不构成运行时 contract；不能因为源码中出现 URL 或字段就直接迁移。
4. 新增真实提交、关注、订阅、路线或机构目录，都必须建立独立 contract、日志、权限、测试和真机证据。
5. 个人中心入口的“可见”与“可用”必须分开：旧入口可以保留视觉位置，但未冻结 contract 前只能显示能力级关闭文案，不能落到模糊默认分支或伪造成功。

## 4. 下一步

当前没有新的 Provider/微信订阅/机构目录文档，因此本域不新增公共 API。下一步优先级保持为：

1. 使用真实微信 session 完成已有患者、预约历史、报告目录和门诊费用只读链路验收；
2. 新文档到达后先更新 intake 和差异表，再选择病历目录或其他低风险只读域；
3. 取得工单、订阅、机构目录或二维码资料后，分别冻结 contract，再决定是否增加真实业务。

支付、医保、预约写入、患者绑定、二维码、WebSocket、AI 和 HIS 回写继续保持关闭。
