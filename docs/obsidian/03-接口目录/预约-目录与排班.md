# 预约 · 目录与排班

当前 API 只提供只读目录和排班。应用组合根前缀为 `/api/v1`；本页路径省略此前缀。

## 接口清单

| 方法 | 路径 | 查询参数 | 返回重点 |
| --- | --- | --- | --- |
| `GET` | `/appointments/departments` | 无 | `departmentId`、`departmentCode?`、`displayName`、`location?` |
| `GET` | `/appointments/schedules` | `startDate`、`endDate` 必填；`departmentId?`、`doctorId?` 可选 | `scheduleId`、科室/医生、工作日、班次、时间、号源数 |

## `GET /appointments/schedules` 的字段

- 日期格式为 `YYYY-MM-DD`，页面按 `workDate` 分组。
- 每个排班可包含 `scheduleId`、`departmentId`/名称、`doctorId`/名称、`workDate`、`shiftName`、`startTime`/`endTime`、`totalSlots`、`availableSlots`、`timeGroup`。
- 页面把结果完整读回后做本地“加载更多”，不能据此假定服务端支持分页。

## 认证、错误和页面行为

- 两个接口都要求当前认证会话；请求头还可以带 `idempotency-key`、`x-request-id`，由统一客户端/服务端处理。
- 未认证：前端先走登录恢复，服务端仍拒绝匿名请求。
- 无科室/无排班：显示空态，不虚构医院或号源。
- 供应商未配置/不可用：保留错误上下文；不能用旧排班冒充当前结果。
- 当前模块没有预约写入路由；`onScheduleTap` 只显示“预约下单功能迁移中”。

## 不能误读的地方

当前首页的“互联网医院”入口复用固定医院展示页，不代表有动态医院列表接口；当前源码也没有由本模块提供的预约 POST。
