# 患者 · 同步

## 请求契约

完整路径：`POST /api/v1/patients/sync`。

| 部分 | 当前要求 |
| --- | --- |
| 身份 | 需要当前 Bearer 会话 |
| Header | `idempotency-key` 必填，字符只能是 `[A-Za-z0-9._:-]+`，长度最多 128 |
| Body | 当前客户端发送 `{}`；外部身份输入由同步协调器/适配器边界处理 |
| Response | `PatientListResponse`，返回规范化患者列表 |

## 服务端链

`PatientService.sync(principal.userId, adapterContextFromHeaders(headers))` → 外部患者目录 `listByIdentity` → 患者数据规范化 → 绑定关系写入/冲突检查 → 返回当前用户可展示的患者结果。

## 页面调用顺序

1. 页面确认会话并读取 `GET /patients`。
2. 同步协调器以业务理由生成幂等键，防止首页、我的、选择页同时触发重复同步。
3. 同步完成后再次读取列表；只有最新请求代际可以回写。

## 风险判断

- 同步必须绑定当前 principal，不能只相信客户端传入的患者标识。
- 同一外部患者已经绑定其他用户时，应走冲突分支，不静默转移。
- 同步失败不能删除原有患者列表，也不能把“同步请求已返回”当成临床访问已 ready。
- 当前 contract 没有允许客户端随意提交医院、provider 或 ownerUserId 的字段。
