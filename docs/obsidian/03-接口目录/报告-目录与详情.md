# 报告 · 目录与详情

API 全路径还要加组合根前缀 `/api/v1`；下面的路径是模块路由语义。

## 接口清单

| 方法 | 路径 | 必填参数 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/reports` | `patientId`、`startDate`、`endDate` | 当前患者报告摘要列表 |
| `GET` | `/reports/:reportId` | 路径 `reportId`；查询 `patientId` | 当前患者单份报告详情 |

### `GET /reports`

查询参数：

- `patientId`：当前用户已绑定的患者 ID。
- `startDate`、`endDate`：报告日期窗口。
- `kind` 可选：`laboratory`、`imaging`、`ecg`。

返回摘要字段：`reportId?`、`kind`、`title`、`reportedAt`、`status`（`available|abnormal`）、`hasAttachment`、`total`。列表允许某些摘要没有可用 `reportId`，页面点击时必须拒绝进入详情。

### `GET /reports/:reportId`

必须同时携带 `patientId`。服务端通过当前 Bearer 用户、患者归属和报告短期引用进行校验，再调用对应详情适配器。当前 contracts 明确的详情形状是检验报告：报告基本信息和 `items[]`，每项有名称、结果、单位、参考范围和 `flag`（`normal|high|low|critical|unknown`）。

## 服务端实际链

列表：`ReportService.list` → provider `listReports` → 规范化 → 生成带 TTL 的 report reference。

详情：`ReportService.detail` → 校验 reference 的 owner/patient/过期边界 → 当前支持的 laboratory detail adapter → 规范化结果。

## 页面错误分支

- 未认证：认证门禁/统一错误处理，不返回另一个用户的报告。
- 患者不属于当前用户：拒绝访问。
- reference 过期或不是当前列表发出的短期引用：拒绝详情。
- provider 不可用：展示错误，不伪造空报告。
