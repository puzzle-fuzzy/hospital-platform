# 患者门禁

患者门禁回答一个核心问题：当前操作到底属于哪个就诊人。

## 适用范围

预约、预约记录、报告、门诊费用等患者范围功能都需要当前患者；医院静态信息、建设中提示等功能不一定需要患者。

## 判断顺序

1. 先认证。
2. 再读取/确认当前患者。
3. 再校验患者是否属于当前 principal。
4. 最后才调用供应商或患者范围业务接口。

患者为空时，前端去 [[就诊人选择|就诊人选择]]；不应直接发送一个空 `patientId`。
