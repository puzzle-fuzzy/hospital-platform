# 错误码与页面行为

接口错误只有转成页面动作才对用户有意义。错误处理还要清理不再可信的页面读模型，不能只把 error 字段改掉。

| 错误类别/代码 | 页面动作 | 是否重试 |
| --- | --- | --- |
| 未认证/会话失效 | 登录恢复；成功后重放原入口或请求一次 | 最多一次，不能无限重放 |
| 患者缺失 | 打开就诊人选择 | 选择后重新加载 |
| 患者无权限/不可用 | 停止请求并提示当前患者不可查询 | 不盲目重试 |
| `dependency-not-configured` | 显示对应服务“暂未配置” | 用户主动重试/联系管理员 |
| `outpatient-payment-patient-not-found` | 清空费用列表，提示当前患者暂无缴费映射 | 可重新选择患者 |
| 空数据 | 展示空状态 | 用户主动刷新 |
| 供应商暂时失败 | 错误状态和重试 | 有边界地重试 |
| 建设中/迁移 | 展示产品提示 | 不调用不存在的接口 |
| 参数校验失败/版本冲突 | 指向字段或保存动作，保留输入 | 修正后提交 |

## 必须区分的两组状态

- 空列表 ≠ 请求失败：空列表是合法业务结果，应显示暂无数据。
- 认证失败 ≠ 患者为空：前者先恢复登录，后者才进入患者选择。
- 当前患者错误 ≠ 当前用户资料错误：患者范围页要清理患者派生数据，资料页要保留用户输入并等待新的 canonical GET。
- 支付预下单成功 ≠ 支付完成：必须等待回调/查询确认，见 [[支付状态机]]。

## 旧响应处理

如果错误来自已被新一轮请求淘汰的响应，页面不应覆盖当前状态；请求代际规则见 [[会话代际与旧响应]]。
