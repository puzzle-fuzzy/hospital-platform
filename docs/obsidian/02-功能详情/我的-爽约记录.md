# 我的 · 爽约记录

“爽约记录”没有独立的 `/missed` API。页面先读取当前用户和患者范围的预约记录，再在页面模型中筛选状态为 `missed` 的记录。

## 实际链路

1. 在“我的”点击爽约记录，进入 `/pages/missed-appointments/missed-appointments`。
2. 页面执行当前会话确认，并读取当前患者/患者目录。
3. 调用 `GET /api/v1/appointments/records`，使用预约记录服务固定的查询窗口。
4. 在客户端把预约状态翻译成中文，并筛选 `missed`；加载更多仍是本地展示窗口。
5. 点击当前患者卡片可以进入患者选择；重试会重新执行完整链路。

## 判断边界

| 情况 | 行为 |
| --- | --- |
| 没有患者 | 显示稳定空态/错误态，不伪造爽约记录 |
| 记录为空 | 显示没有爽约记录 |
| 非 `missed` 状态 | 不显示在爽约列表，但保留在预约记录接口事实中 |
| 会话或患者变化 | 旧响应失效，按新代际重新加载 |
| 点击记录 | 当前没有详情动作可证明，不应写成已可查看详情 |

接口：[[预约-记录]]、[[患者门禁]]、[[会话代际与旧响应]]。
