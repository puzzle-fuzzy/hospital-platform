# 我的挂号

首页服务栅格“我的挂号”和“我的”菜单“我的挂号”都进入 `/pages/appointment-records/appointment-records`。页面显示的是预约记录读模型，不会在这里创建预约。

## 用户操作和判断

| 操作 | 页面行为 | 接口/规则 |
| --- | --- | --- |
| 打开页面 | 先确认会话、当前患者，再加载列表 | `GET /me`、患者上下文、`GET /appointments/records` |
| 在线/全部标签 | 切换后重新请求对应 `scope`，不复制旧列表 | `scope=online` 或 `scope=all` |
| 加载更多 | 扩大当前过滤结果的本地展示窗口 | 不是服务端分页 |
| 切换患者 | 打开 [[就诊人选择]]，返回后重新加载 | 患者代际守卫 |
| 点击记录 | 当前 Toast：“挂号详情暂未开放” | 没有预约详情接口 |
| 预问诊 | Toast：“预问诊功能正在迁移中” | 没有当前写入/跳转接口 |
| 院区行 | 打开本地单院区面板 | 不请求院区 API |

## 记录请求

`GET /api/v1/appointments/records?patientId=<患者ID>&scope=<online|all>&startDate?&endDate?`。服务端按当前 Bearer 用户和患者范围查询，返回预约记录及 `total`。记录状态可能是 `scheduled`、`cancelled`、`completed`、`missed`、`stopped`、`substituted`、`registered`、`unknown`。

## 旧响应保护

切换患者、会话恢复、重试和 Tab 切换都会启动新的请求代际；只有当前代际的响应能更新页面。错误时不能只清掉错误文字而保留上一位患者的记录。

接口：[[预约-记录]]、[[患者门禁]]、[[会话代际与旧响应]]。
