# 门诊缴费

## 用户触发

首页顶部快捷入口或“我的”中的门诊缴费入口。

## 逻辑

1. 检查会话。
2. 检查当前患者；没有患者时返回就诊人选择，而不是调用患者范围接口。
3. 进入门诊费用页，读取该患者的门诊费用记录。
4. 根据费用状态渲染待缴、已缴、失效或异常状态。
5. 如果进入微信支付，支付预下单和支付参数转换必须在服务端完成；小程序只负责拉起支付。

接口：[[门诊费用-记录|门诊费用记录]]、[[微信支付-代码边界|微信支付代码边界]]。

## 重点判断

- 当前患者切换后，旧患者的费用列表不能覆盖新患者页面。
- 费用列表读取成功不代表支付成功；支付是另一个状态机。
- `uni.requestPayment` 是支付拉起动作，不是创建预支付订单的接口。
