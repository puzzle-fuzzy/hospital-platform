# 首页 · 就诊人绑定与切换

## 用户触发

用户点击首页当前就诊人卡片上的绑定/二维码区域，或点击家庭成员入口。

## 实际逻辑

1. 进入 [[就诊人选择|就诊人选择]]。
2. 先读取 `GET /patients`，展示当前账号已经绑定的患者。
3. 用户扫码得到外部身份信息后，调用 `POST /patients/sync`。
4. 服务端根据当前登录用户和外部身份查找患者，规范化后写入绑定关系。
5. 同步成功后刷新患者列表；冲突、无匹配或供应商失败时，保留页面状态并展示错误。

## 判断点

| 判断 | 行为 |
| --- | --- |
| 没有会话 | 先走微信登录，不直接同步 |
| 患者列表为空 | 显示绑定引导 |
| 已有当前患者 | 切换前更新上下文，不能把旧患者 ID 留在后续请求 |
| 外部身份冲突 | 不覆盖已有绑定，提示用户处理 |
| 同步响应晚于新一代会话 | 丢弃旧响应，见 [[会话代际与旧响应|会话代际]] |
