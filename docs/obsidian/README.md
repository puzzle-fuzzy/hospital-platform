# 医疗小程序项目知识库

这是给 Obsidian 使用的项目导航层。它把“用户点了什么”拆成可点击的页面、功能、接口、业务规则和源码证据。

## 从这里开始

打开 [[00-项目总览|项目总览]]。推荐阅读顺序是：

1. [[01-页面地图/首页|首页]]：看首页全部点击位、每个点击后的页面和门禁。
2. [[01-页面地图/我的|我的]]：看个人中心全部入口、当前可用性和迁移中入口。
3. 从页面表格点击某个 [[02-功能详情/首页-预约挂号|功能详情]]。
4. 从功能详情继续点到 [[03-接口目录/预约-目录与排班|接口目录]]、[[04-业务规则/患者门禁|业务规则]] 和源码证据。

## 这套知识库如何工作

| 笔记类型 | 解决的问题 | 典型内容 |
| --- | --- | --- |
| 页面地图 | 当前页面有多少功能 | 点击位置、下一页面、可用性 |
| 功能详情 | 点击以后发生什么 | 触发器、判断、接口、异常、源码 |
| 接口目录 | 前后端到底调用什么 | 方法、路径、入参、响应、鉴权 |
| 业务规则 | 为什么要这样判断 | 患者门禁、会话代际、短期引用、错误码 |
| 源码证据 | 结论从哪里来 | 文件、行号、CodeGraph 关系、静态证据边界 |

## 使用约定

- 页面、功能和规则之间用 Obsidian 内部链接跳转；源码使用相对文件链接，避免把工程术语当成业务说明。
- `实际可用` 表示当前源码存在完整入口和调用链；`迁移中` 表示点击有反馈但没有真实业务闭环；`建设中` 表示统一提示；`待运行验证` 表示静态代码能解释，但仍需真实环境确认。
- 源码证据是只读索引，不在这里复制实现代码。实现改变后，应先更新对应源码证据，再更新页面和功能说明。
- 当前知识库不依赖社区插件，也不创建自定义 Canvas 文件；使用 Obsidian 的内部链接、反向链接和搜索即可导航。Obsidian 官方文档说明这些能力属于核心插件：[核心插件](https://obsidian.md/help/plugins)、[反向链接](https://obsidian.md/help/Plugins/Backlinks)。

## Vault 打开方式

当前这套笔记请直接选择 `E:\__Super_Core__\hospital-platform\docs\obsidian` 作为 Vault。笔记内部链接以这个目录为根，例如 `[[00-项目总览|项目总览]]`，不要再加 `docs/obsidian/` 前缀，否则 Obsidian 会把它解析成重复目录并创建空白文档。源码证据使用相对文件链接，仍可跳回仓库中的真实源码。

如果以后改为把仓库根目录 `E:\__Super_Core__\hospital-platform` 作为 Vault，需要整体重写内部链接前缀；不要在两个 Vault 根目录之间混用链接格式。
