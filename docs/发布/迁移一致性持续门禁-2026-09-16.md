# 迁移一致性持续门禁（2026-09-16）

## 结论

P3-03 已完成持续门禁配置：GitHub CI 的质量 job 统一调用 `pnpm check:candidate`，而 `check:candidate` 现已串联迁移台账、边界、事实、运行包来源、临床 contract、只读域、Provider 文档、页面/患者显示审计、文档、工具链、秘密/日志/错误契约、格式、lint、工具测试、类型检查、全仓测试、构建和最终 `runtime:verify`。这项变更只修改根 `package.json` 的候选门禁命令和本记录，没有修改业务实现或支付代码。

本门禁是持续一致性检查，不把门禁通过等同于 Provider、微信真机或生产业务通过；临床、外部主体、患者绑定、报告附件和支付/医保仍按各自范围和受控证据处理。

## 1. CI 入口证据

`.github/workflows/ci.yml:27-53` 固定 Bun、Node、pnpm，执行 `pnpm install --frozen-lockfile`，然后执行 `pnpm check:candidate`。根 `package.json:14-15` 现在把所有候选检查置于同一串行命令中，并在 `pnpm build` 后显式执行 `pnpm runtime:verify`，确保构建完成后实际 `dist` 仍通过来源、页数、根文件和相对依赖校验。

## 2. 持续检查分组

| 分组 | 当前门禁 | 持续防止的漂移 |
| --- | --- | --- |
| 旧服务/迁移台账 | `migration:audit`、`migration:boundary:audit`、`migration:contract:audit`、`migration:fact:audit`、`todo:audit` | 旧页面/接口来源、冻结入口、contract key、TODO 统计和事实记录脱节 |
| 小程序入口和显示 | `migration:breadth:audit`、`miniprogram:navigation:audit`、`miniprogram:patient-display:audit` | 首页/我的入口、页面落点、患者内部标识展示和 47 页运行输入漂移 |
| 临床/只读/Provider | `clinical:contract:audit`、`readonly:audit`、`provider:audit` | 未审核临床域误开放、低风险域结构误报完成、Provider contract 缺失 |
| 文档/发布来源 | `docs:audit`、`release:baseline:index:audit`、`toolchain:audit`、最终 `runtime:verify` | 文档断链、server/dist 候选不一致、工具链声明漂移、构建包来源失真 |
| 工程质量 | `architecture:audit`、`env:template:audit`、`secret:audit`、`logging:audit`、`error:contract:audit`、`format:check`、`lint`、`test:tools`、`typecheck`、`test`、`build` | 依赖边界、环境/秘密、日志敏感字段、错误契约和代码回归 |

`apps/miniprogram/scripts/runtime-provenance.ts:133-226` 负责 release Git revision 和 development 工作树快照；`apps/miniprogram/scripts/verify-runtime.ts:208-307` 负责页数、来源和运行包结构校验。docs-only 提交不会无故更换运行输入来源，但任何页面、构建脚本或公共运行输入变化都会改变候选来源或快照。

## 3. 变更时的强制记录

涉及旧页面、FeatureKey、旧接口矩阵、页面运行输入或 dist 的变更，必须同时更新：

1. 旧源码路径和真实行为证据；
2. 当前 source/dist 来源 revision 与构建时间；
3. `代码完成`、`运行环境`、`Provider`、`真机`、`生产接受` 五类状态；
4. 成功、空、拒绝、超时、会话切换、越权和回滚边界；
5. 受控证据文件的路径、权限、大小、SHA-256、时间窗口和缺口。

只改页面文案也不能把历史运行包当成当前候选；只改文档也不能删除已有未验证项。支付/医保/收银台及相关 HIS 回写仍是范围排除，不因通用候选门禁而进入本任务修改或业务验收。
