## 医保实际拒绝内容

脱敏后核心内容：

> [FSI-FMI服务执行异常] 校验失败：证件类型【01】姓名【null】的基本信息为空。
> [晋城]不符合业务要求。[FSI-1101]

错误中的流水号已省略。实际请求在服务器内比对，未输出患者资料或授权号：

- body.input.data.psn_name 非空，长度 3，与 userQuery 返回姓名一致。
- body.input.data.certno 非空，长度 18，与 userQuery 返回身份一致。
- mdtrt_cert_type=01、psn_cert_type=01。
- mdtrt_cert_no 与 userQuery 返回的 pay_auth_no 一致。
- input.data 包装和 AUTH 授权号用法均与旧项目相同。

所以“姓名 null”是上游错误信息，不能反推小程序或医院 API 漏传姓名。
当前证据可确认上游 1101 业务拒绝，不能进一步判定省医保内部基础信息、电子凭证解析或机构配置中的具体哪一项失败。

## 页面为何表现不明显

实际上传包与源码一致：registration-payment.ts 的 handleReturn 已消费授权码并调用服务端；
authorize 失败后进入 handlePaymentError，令 error 为空，将 provider-response-invalid 合并成通用持久提示：

> 支付未完成，当前订单状态已保留；请稍后继续原支付方式，如已扣款请勿重复付款

提示位于预约、患者信息之后，没有展示“医保基础信息查询失败”的阶段，也没有弹窗或结果页跳转。
用实际上传 JS 做纯内存模拟确认该 502 路径的支付调起和结果页跳转次数均为 0；没有真实调用。
