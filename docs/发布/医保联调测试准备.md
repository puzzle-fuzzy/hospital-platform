# 医保联调测试准备

更新时间：2026-09-06

## 目的

在开始真实用户测试前，先完成腾讯侧测试资格和测试人员准备，避免测试过程中因账号、医保资格或地区条件不满足而无法判断真实链路问题。

## 需要提前申请或协调的事项

### 腾讯侧

- 请腾讯老师协助添加或开通测试人，确认测试环境、测试资格的生效时间和有效期。
- 确认测试人可以进入当前医保支付测试链路，并明确需要提供的测试身份信息格式。
- 测试过程中如需新增测试人、解除限制或刷新资格，统一由腾讯侧协助处理并记录。

### 医院及联调侧

- 确认测试人在本地医院和当前医保地区具备可用的医保缴纳资格。
- 提前确认测试预约、号源、患者绑定和支付测试数据，避免使用真实业务中的待支付订单。
- 测试前确认 3090 的 `PROVIDER_RAW_LOGGING=true` 已保持开启，并限制原始 Provider 日志的服务器访问范围；该开关不能关闭。

## 测试人的优先条件

测试人应尽量满足以下条件：

1. 高平地区医保账号、可重复测试，能够配合多次登录、预约、支付、退出、重试和异常场景验证。
2. 是本地医保缴纳者，医保状态有效，且参保地、就医地与本次测试条件匹配。
3. 优先选择医院职工，便于快速沟通、现场复现和及时反馈。
4. 能配合使用微信完成登录、患者绑定及医保相关授权，并同意在测试范围内使用其测试身份。
5. 最好准备不止一名测试人，避免单一账号状态异常导致测试中断。

## 测试前检查清单

- [ ] 腾讯侧已确认测试人已添加，且资格已经生效。
- [ ] 测试人确认是本地有效医保缴纳者，优先为医院职工。
- [ ] 测试环境、医院、地区和测试时间窗口已确认。
- [ ] 测试账号没有遗留的待支付订单、未完成预约或被占用号源。
- [ ] 已准备可重复使用的预约和费用测试数据。
- [ ] 已确认自费、混合支付、纯医保三条测试路径的记录方式。
- [ ] 已确认用户中途退出支付时订单失效并释放号源。
- [ ] 已确认测试期间可以按订单、请求链路和 Provider 返回结果进行排查。

## 执行顺序

当前自费支付已经走通，后续优先使用准备好的测试人验证：

1. 先复核登录、患者绑定、预约和号源数据是否正常。
2. 再验证纯医保支付。
3. 再验证混合支付。
4. 每条链路都覆盖成功、用户中途退出、超时、重复点击和 Provider 拒绝等情况。
5. 测试结束后整理结果，保留必要的原始日志和业务证据；原始日志输出继续保持开启，只关闭不再需要的测试资格或测试窗口。

## 信息安全要求

测试人的身份证号、医保凭证、手机号等敏感信息不得直接写入普通文档、工单或聊天记录；只通过受控方式提供给负责联调的人员。文档只记录测试准备状态、责任人和结果，不记录完整身份信息。
