# 普通微信挂号退款与医院状态同步

## 行为

已完成的普通微信挂号订单可从后台选择整笔退款或退微信；金额取服务端原支付实付余额，医保为零时不提供医保退款。退款使用原支付商户单号，同一预约复用固定退款身份。

处理顺序为：确认微信原路退款成功，回写医院 `2.6.65.15` 的退款事实，再取消挂号。后台区分微信退款处理中、医院回写待完成和取消挂号待完成；仅三步全部确认后显示整体完成。中间失败沿原退款及已保存回执恢复，不新建另一笔退款。纯微信查单接口和 Worker 查单不发起退款申请；权威查无退款时，仅原请求恢复入口可用原号、原金额、原原因重发。

微信退款之前纯校验医院回写所需上下文；缺原支付关联号、医院流水或回写关键字段时，不预留退款也不调用资金接口。微信结果未知时保留预约。回写已成功而取消失败时，不重复退钱，继续恢复取消挂号。

## 医院接口鉴权

`YUNHEALTH_REGISTRATION_REFUND_AUTH_MODE` 默认 `bearer`，保留服务端授权检查。当前生产使用既有签名中转时显式选择 `signed-relay`；只接受 `https://gpsrmyy.meiyi.pro` 根地址（可带末尾 `/`），拒绝其他地址、端口、用户信息、路径、查询串和重定向。该模式复用 Java 中转的签名及设备许可，不向中转转发患者或管理员 Bearer。

参考当前仓库 [生产链路拓扑](../../infra/生产链路拓扑.md) 与[众阳官方文档](https://openapi.msuncloud.com/document)中的 `1.1 请求结构`、`1.3 接口调用流程参考`、`2.6.65.15 支付回写`。原 Python 应用的非空 Bearer 检查是应用前置条件，不能视为签名中转通道的唯一鉴权方式。

禁用提示分别说明医院完成状态未确认、取消挂号服务未配置、医院回写未配置、缺服务端授权或鉴权配置不受支持，不再统一提示先核对医院状态。

## 验证与发布边界

使用网络模拟验证原号重试、微信处理中、医院回写失败、回执保存失败及取消失败的恢复；校验错误不会触发资金动作。微信协议沿用[申请退款](https://pay.weixin.qq.com/doc/v3/merchant/4013071036)、[退款查询](https://pay.weixin.qq.com/doc/v3/merchant/4013071041)的原单与原退款号规则。

本次发布保留已上线 UTC 时间、医保地区修复、导诊模型和后台宽度；只变更 API、后台静态客户端及上述非敏感鉴权模式配置，不重启 Worker，不迁移数据库。发布脚本验证备份、候选就绪、指定订单能力与原支付回写上下文，验证过程不发起真实退款、医院退费回写或取消挂号。生产发布结果以本次发布目录的 manifest 与验证记录为准；自动测试和能力开放不等于已执行真实退款。
