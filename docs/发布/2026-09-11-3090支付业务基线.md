# 3090 支付业务基线

## 目的

本分支只用于继续验证和发布挂号支付业务流程，避免把仍在开发的报告、退费、退款通知和资金对账功能混入 3090。

## 3090 已发布事实

- 线上 release：`md5medpay-f12b40a2bc18-20260911`
- API 与 Worker 已启动且就绪探针通过。
- `PROVIDER_RAW_LOGGING=true`，继续保留完整 Provider 请求与响应日志。
- 当前收款模式统一为 HIS 收款：纯自费和医保混合的微信现金分项都使用众阳 `2.6.65.2.result` 返回的 APIv2/MD5 参数。
- 普通微信自费的验证顺序固定为：`2.6.65.1 -> 2.27.2.27 -> 2.6.65.2 -> 微信支付 -> 2.6.65.5`；支付成功后直接调用 `.5`，不调用 `2.27.2.29` 或 `2.6.65.15`。
- 用户点击医保支付时，医保结算与其中的微信自费腿分别确认；该微信自费腿继续调用 `.29 -> .15 -> .5`。这组接口不得被普通微信支付入口复用。
- `.5` 返回 `isSettle=1` 才作为众阳最终结算确认；微信调起成功或 `.2` 返回成功都不单独构成 HIS 完成证据。
- 支付查询与关联迁移 `0046_registration_self_pay_record_code_hash.sql`、`0047_yunhealth_payment_query_references.sql` 已包含在发布源码中。

本文档及后续支付文档均以“HIS 收款”作为唯一业务口径。代码中为兼容历史订单保留的接口路径或事件名只作为技术标识，不代表另一种收款模式。

上述代码统一保存在 `codex/unpublished-reports-refunds-20260911` 分支。后续发布必须从该分支单独评审、迁移、测试和部署，不能因代码已提交就视为已经上线。

## 后续发布规则

1. 日常支付联调和 3090 支付修复从 `codex/3090-payment-flow-20260911` 开始。
2. 不从包含报告、退费或对账代码的工作区直接打包 3090。
3. 退费等后续功能需要发布时，先合并已验证的支付基线，再单独执行数据库迁移、服务配置、回调和真实业务验收。
