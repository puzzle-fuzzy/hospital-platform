# 医保正式授权机构应用 ID 配套修复

> 日期：2026-10-14（Asia/Shanghai）。
> 新开发版本 `2026.10.14.1` 已上传；手机当前使用体验版，新版本切换与真实医保授权接受结果待真机验证。

## 问题与原因

手机跳转正式医保授权页显示“该机构渠道认证编码错误”。重新逐字核对正式身份核验反馈单、
本地材料、原运行包及 ZIP，认证码均一致，64 字符完整，无内部空格或遗漏。

真正发现的配置错误是：原主小程序 `medicalOrgAppId` 完全匹配**测试移动支付反馈单**的应用 ID，
与正式移动支付反馈单的应用 ID 不同。此前构建只注入正式认证码，未同步切换机构应用 ID，
因此实际授权参数为“正式 `orgChnlCrtfCodg` + 测试 `orgAppId`”。
所有者随后提供的正式应用 ID 与正式反馈单提取值一致，并确认手机运行体验版。

[用户授权接入协议](https://docs.qq.com/doc/DV3JYRG1xelhKTWdz)第 2.2.4 节说明，
`orgAppId` 为定点医药机构应用 ID，来源于国家医保移动支付/处方流转反馈单。
同表与[微信支付报错排查指引](https://pay.weixin.qq.com/doc/v3/partner/4020401184)明确小程序授权认证码不需要 encode；
当前两条入口原样传递该值，未发现 `%2F` 或截断，因此保留原样传法。

这定位了明确的参数环境混用，并不等于已经取得上游授权日志或真机成功结果。
2026-10-13 复核中“四份反馈单未提供 medicalOrgAppId”的结论已更正。

## 修复

- `medicalOrgAppId` 改为构建占位符，与认证码一起从同一本机正式材料集合读取。
- 应用 ID 使用 `paymentChannelFeedback.appId`，认证码使用 `identityVerificationFeedback.orgChannelAuthCode`。
- 已有材料必须标记 `environment=production`，两项均需为非空字符串；拒绝测试、缺半对及隐式类型转换。
- 没有本机材料时，两项同时为空，保留医保配置门禁，不再携带旧测试应用 ID。
- 将材料解析模块加入运行包来源指纹，并将回归测试加入默认小程序测试名单。

正式标识与认证码仅注入本机运行包，不写入源码或本文。保持授权目标 `release`、已有渠道号、
机构码、业务类型及四种授权业务不变。此次未修改、发布或重启 API/Worker，非严格验签配置未变。
