# 凭据扫描边界

新仓库不保存真实微信、医保、Provider、MySQL、Redis 或支付凭据。凭据只应通过服务器
密钥管理或受控 SSH 环境注入，不能进入小程序、Git、systemd release 目录、命令行参数、
shell history、日志或 API 响应。

## 扫描命令

工作树扫描：

```powershell
pnpm secret:audit
```

发布前追加 Git 可达历史扫描：

```powershell
pnpm secret:audit:history
```

扫描会检查：

- 当前 Git 跟踪文件中是否有 PEM/private key 标记；
- 当前 Git 跟踪路径是否包含真实 `.env`、`.pem` 或 `.key` 文件；
- 当前文件中是否出现非空、非占位符的关键凭据配置；
- Git 可达历史中的敏感文件路径和密钥/凭据新增行。

输出只包含原因、路径、行号或提交号，不输出匹配的秘密原文。`.env.example` 和其他
`.example` 模板允许存在，但必须只放空值或 `<占位符>`。

## 当前结果与责任边界

截至 2026-08-31，新仓库工作树扫描和 Git 可达历史扫描均通过，没有发现需要在本仓库
吊销的真实凭据。这个结果不能替代旧项目的暴露历史判断：旧项目曾跟踪生产 env、微信
证书和医保配置，是否曾被不应访问的人员或远程仓库获取，仍必须由服务器/代码托管管理员
确认；无法排除时，按微信、医保、Provider、支付、MySQL 和 Redis 凭据分别安排轮换。
