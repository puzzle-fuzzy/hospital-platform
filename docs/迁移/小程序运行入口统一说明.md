# 小程序运行入口统一说明

## 唯一管理入口

主小程序只保留一个微信开发者工具项目：

```text
/Users/yxswy/Documents/GitHub/hospital-platform/apps/miniprogram/dist/
```

`apps/miniprogram/src/` 是 TypeScript/WXML/WXSS 源码，`apps/miniprogram/` 是构建工程；它们不是第二个可单独管理的小程序。开发者工具、预览、真机调试和上传都只打开 `dist/`，不要打开仓库根目录、`src/` 或 `.local/` 下的运行目录。

## 开发与正式构建

开发和正式构建现在都写入同一份 `apps/miniprogram/dist/`：

- `pnpm --filter @hospital/miniprogram dev`：监听源码，写入 `dist/`，`build-info.json` 标记 `buildMode=development` 和工作树快照。
- `pnpm --filter @hospital/miniprogram build`：正式构建，写入 `dist/`，要求运行输入已提交，并用 Git 提交号标识。
- `pnpm --filter @hospital/miniprogram runtime:verify:dev`：验证当前 `dist/` 是否匹配开发快照。
- `pnpm --filter @hospital/miniprogram runtime:verify`：验证当前 `dist/` 是否匹配正式 Git 来源。

两种模式只区别来源证明，不再生成两套可以被开发者工具打开的运行包。`dist/build-info.json` 是判断当前加载内容的唯一来源记录。
同一时间只运行一种构建模式；不要同时启动 `dev` 监听和正式 `build`，避免两个构建过程竞争同一个 `dist/`。

## 旧目录处理

`.local/hospital-miniprogram/development/` 已退出运行链路，不再更新或打开；旧目录已移出仓库工作区保存为临时归档。`.local/hospital-miniprogram/pending*` 仅用于开发者工具锁定 `dist/` 时暂存候选，也不是小程序管理入口。

如果开发者工具“管理”页仍有旧的 `apps/miniprogram/` 父工程、`src/` 工程或 development 工程卡片，应关闭这些旧窗口并移除对应卡片，只保留 `apps/miniprogram/dist/`。重新编译前先确认资源树根目录是 `dist`，再执行普通编译。
