# 外部入口与通用 WebView 对照复核（2026-09-16）

## 结论

旧端 `pagesB/health/webview.vue` 是一个通用 WebView：默认可打开智能客服，也接受路由传入的 `path` 或完整 `url`，并向任意最终地址追加旧 `/system/auth/ticket`。同一页面还承载智能导诊、患者绑定和解绑入口。旧端互联网医院则是另一个固定 H5 地址。它们虽然技术上都使用 WebView，但 audience、授权、会话、回跳和退出责任不同，不能作为一个通用迁移能力。

新端已经将智能导诊改为原生页面，将客服和互联网医院限制为各自固定 HTTPS 地址，不接受任意 URL、不向 WebView 传平台 token、不复用旧 ticket。外部域名业务域名配置、主体授权、短期会话、退出/回跳、失败和真机证据仍未确认，因此 P1-20 保持未完成。

本复核只覆盖智能客服、智能导诊、互联网医院和旧通用 WebView 的外部边界，不触碰支付、医保、收银台、退费、账单支付或支付相关 HIS 回写。

## 1. 旧端真实行为

### 1.1 通用 WebView 同时承载多个 audience

旧 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/webview.vue:17-27,50-82` 将 `VITE_AI_WEBVIEW` 作为基础地址；加载时读取 `path`、完整 `url`，先请求 `POST /system/auth/ticket`，再把 ticket 追加到最终地址。

当传入完整 URL 时，旧代码直接 `decodeURIComponent(fullUrl)` 后使用，只有根据 URL 中是否包含 `onlineBinding` 或 `healthCardManagement` 改标题；当传入 `path` 时则拼接 `${baseUrl}/${path}`。`outpatient-guide`、客服、患者绑定和解绑因此共用同一个 URL/ticket 交换器，没有独立 audience、域名/path allowlist、短期会话或回跳协议。

旧代码还把最终 URL 打印到日志，见同文件 `:79-82`；ticket 经 query 参数进入 WebView，无法证明外部页面的退出、过期和重放控制。

### 1.2 互联网医院是独立固定地址

旧 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pages/hospital/hospital.vue:13-29` 固定打开：

```text
https://cx.o2o.bailingjk.net/wechat/#/bluser/userCard/index?publicNoCode=gzh-048400_0001
```

页面每次显示时追加时间戳刷新。该行为只能证明存在一个固定外部入口，不能证明域名已加入当前小程序业务域名、外部主体已授权、登录/回跳已成功或互联网医院业务已完成。

## 2. 新端当前实现

- `apps/miniprogram/src/pages/smart-customer/smart-customer.ts:1-28` 只允许固定 `https://html.ydrj.top`，切回页面时追加时间戳；
- `apps/miniprogram/src/pages/hospital/hospital.ts:1-31` 只允许固定互联网医院 URL，切回 Tab 时追加时间戳；
- `apps/miniprogram/src/pages/smart-customer/smart-customer.wxml:1-2` 和 `hospital/hospital.wxml:1-2` 只承载对应固定 WebView；
- `apps/miniprogram/src/pages/smart-guide/smart-guide.ts` 使用新端原生文字/语音导诊服务，不再把旧 `outpatient-guide` path 或 ticket 交给 H5；
- `apps/miniprogram/src/services/legacy-page-catalog.ts:58-62,365-370` 明确记录固定 HTTPS 入口边界，不恢复通用 URL、患者绑定/解绑或旧 ticket；
- `apps/miniprogram/src/services/external-entry-surface.ts:31-51,107-124` 的外部入口关闭态要求 allowlist、受众、短期会话、回跳、退出和撤销规则。

新端因此完成了“通用危险入口不回迁”的代码边界，但固定 WebView 能否在微信环境打开、外部页面如何建立有效会话和如何返回最终业务事实，仍没有当前环境证据。

## 3. 放行前必须冻结的 contract

客服、导诊、互联网医院、患者绑定/解绑必须分开确认：

1. audience、外部主体、业务域名/证书、固定 origin/path 和小程序后台业务域名配置；
2. 是否需要会话，若需要则明确服务端签发的一次性短期 opaque 引用，不把平台 token 或旧 ticket 放入 URL；
3. 患者绑定/解绑的 owner、患者、同意、目标主体和最终状态回传；
4. 外部页面打开失败、用户取消、登录失效、超时、重复打开、回退和退出语义；
5. 外部回跳签名/状态验证、撤回、访问审计和数据保留；
6. 页面不可见、账号切换和会话失效时的外部会话撤销；
7. DevTools、真机和生产中各自固定入口的 HTTPS 业务域名和回跳验收证据。

在这些材料到齐前，不恢复旧 `webview.vue`，不接受 `url/path` 路由参数，不请求旧 `/system/auth/ticket`，不把页面能打开写成客服/互联网医院/绑定已成功。

## 5. 处理决定

- P1-20 保持未完成，客服、互联网医院、导诊和患者绑定/解绑不共用通用 WebView contract；
- 保留新端固定 URL/固定 audience 的代码边界，不恢复任意完整 URL、动态 path 或旧 ticket；
- 待各外部主体分别提供 allowlist、会话、回跳、退出和审计材料，再分别实现并验收；
- 本复核没有修改旧服务、旧数据库、Provider、线上配置或支付/医保代码。
