# 入院预问诊与预约前预问诊迁移边界审计（2026-09-16）

## 结论

P1-13 当前不能直接把旧端表单复制到新小程序并开放提交。两条旧链路的事实不同：入院预问诊是旧服务自有的按 `user_id + pat_id` 查询/覆盖写入记录；预约前预问诊是旧小程序把预约/挂号标识和一组自由文本提交给外部 `msun-hzzn-app-config` 接口，当前旧 Python 仓库未发现对应实现或版本化问卷来源。

新端已经完成本地表单承载迁移：入院预问诊保留旧端 10 个问题，预约前预问诊保留旧端 6 个问题，并接入当前就诊人和受控预约上下文。两页都明确不读取旧答案、不调用旧保存接口，提交按钮只做本地完整性校验，真实写入仍关闭。当前仍没有足够材料安全定义住院事件、预约关系、问卷版本、授权、幂等和医护读取 contract。本项保持关闭，不复制旧答案或 `user_id/pat_id` 写入模型。

本审计只覆盖问诊内容和临床问卷写入边界，不触碰支付、医保、收银台、退费或支付相关 HIS 回写。

## 1. 旧服务真实行为

### 1.1 入院预问诊

旧小程序定义了 10 个固定题目，覆盖性别、年龄、与患者关系、不适描述、高血压、糖尿病、慢性病、传染病、手术史和其它信息，题目及字段键见 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/admission_preconsultation.vue:128-203`。其中多项要求用户输入疾病史、用药、手术医院和恢复情况，属于健康敏感文本。

旧页面将性别/年龄/关系/健康史等答案按题目顺序组装为 `content: string[]`，再从缓存读取 `user_id` 和 `pat_id` 提交：

- 患者 ID 来自 `SelCard` 深层缓存中的 `patId`，见同文件 `:265-288`；
- 提交前只校验用户和患者缓存是否存在，见 `:340-364`；
- 请求体为 `{ user_id, pat_id, content }`，见 `:365-404`；
- 调用旧 API `POST /convenience/admission-preconsultation/submit`，见 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/api/modules/health.ts:421-438`。

旧页面启动时还调用 `GET /convenience/admission-preconsultation/list`，取 `items` 第一条记录，把其 `content` 按当前位置回填到当前题目，见同页面 `:290-337`。这没有定义按患者、问卷版本或任务 ID 选择历史记录的规则。

旧 Python 服务真实实现为：

- controller 要求当前登录用户，提供 `/admission-preconsultation/list` 和 `/submit`，见 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/admission_preconsultation/controller.py:17-48`；
- 查询强制追加当前认证用户 `user_id`，可选按 `pat_id` 过滤，见 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/admission_preconsultation/service.py:31-65`；
- 提交先要求 `auth.user.id == data.user_id`，再按同一 `user_id + pat_id` 查找，存在则覆盖更新，否则新增，见同文件 `:15-29`；
- 存储模型只有 `user_id`、`pat_id`、`content`，见 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/admission_preconsultation/model.py:9-17`；
- schema 接受 `content` 数组或字符串，在写入时转 JSON；读取时 JSON 解析失败会把原字符串包成数组，见 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/admission_preconsultation/schema.py:10-53`。

因此旧端实际存在“同患者覆盖上一份答案”的写入语义，但没有住院 episode、入院事件、问卷版本、撤回、幂等键或医护读取权限事实。不能将旧的 `user_id + pat_id` 唯一键直接当成新端任务唯一键。

### 1.2 预约前预问诊

旧 API 模块只声明以下外部请求：

```text
POST /msun-hzzn-app-config/v1/saveBeforeVisitRecord
```

请求类型要求 `medicalCardNumber`、`registerId`、`hospitalId`，以及症状描述、患病时长、过敏史、既往史、现病史、家族史等自由文本，见 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/api/modules/health.ts:181-203`。

旧页面有 6 个问题（症状、患病时长、过敏、烟酒史、传染病史、家族史），见 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/pre_visit.vue:80-130`。页面提交前要求 `medicalCardNumber` 和 `registerId` 存在，构造请求时：

- `medicalCardNumber` 从 `SelCard.patCardNo/cardPatCardNo` 读取；
- `registerId` 从路由 `hisRegisterId` 读取；
- `hospitalId` 实际使用构建环境的 `VITE_HOSPITAL_ID`，缺失时回退 `10389001`，而不是使用此前读取的 `SelCard.hospitalId`；
- 选择“无”时不提交对应字段，选择“有”时把自由文本直接作为字段值。

证据：`/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/pre_visit.vue:136-167,194-246,248-274`，实际调用和结果处理见同文件 `:276-293`。

在旧 Python 仓库中未发现 `saveBeforeVisitRecord` 的后端 controller、schema、版本化题库或答案存储实现；当前只能确认旧小程序对外部接口的调用意图，不能确认外部服务的授权、幂等、覆盖规则、失败最终状态、字段长度和医护侧读取权限。

## 2. 新端当前实现

- `apps/miniprogram/src/pages/admission-preconsultation/admission-preconsultation.ts` 已承载旧端 10 个问题、当前就诊人和本地必填校验；页面提交只校验完整性，不调用旧 API 或新端写入接口。
- `apps/miniprogram/src/pages/pre-visit/pre-visit.ts` 已承载旧端 6 个问题、当前就诊人和平台预约上下文；没有平台 `appointmentId` 的历史摘要不会进入填写页，提交仍关闭。
- `apps/miniprogram/src/services/clinical-content-surface.ts` 继续提供统一 clinical contract 提示和关闭态边界；题目承载代码与关闭态服务分离，避免把“能填写”误当成“已提交”。
- 当前边界要求入院预问诊绑定住院事件和版本化问卷，预约前预问诊绑定具体预约上下文，见 `clinical-content-surface.ts`；feature 状态仍标记为等待临床审核/问卷版本/患者授权/幂等/医护读取规则，见 `apps/miniprogram/src/services/feature-navigation.ts:151-156,390-396`。
- 当前没有对应的新端问卷写入 API、repository、问卷 domain contract 或 Provider adapter；`PATIENT_WRITE_FEATURES` 只登记未来写入类别，不能视为业务已经实现。

本轮只迁移页面功能承载和本地校验，不迁移旧答案、不写旧库、不调用旧外部保存接口，也没有把问卷答案写入病历、报告或风险记录。

## 3. 放行前必须冻结的规则

### 3.1 入院预问诊

至少需要确认住院事件/episode 的权威来源、患者 owner 映射、代填人与患者关系、问卷版本、必答/选项/文本上限、答案替换和撤回、重复提交幂等、医护可读范围、敏感文本保留周期和审计字段。多次住院不能继续按 `user_id + pat_id` 静默覆盖。

### 3.2 预约前预问诊

必须先提供外部接口正式 contract 和真实成功/空/拒绝/超时/重复样例，确认预约 ID 与挂号 ID 的权威来源、医院标识的配置来源、问卷版本、患者授权、答案是否可修改/撤回、提交是否幂等，以及接口超时后是否可能已写入。小程序不能把 `patId`、旧 `patCardNo` 或可猜测的挂号字段当成授权凭证。

### 3.3 公共安全边界

两条问诊均需统一校验未知字段、控制字符、长度、空白和会话切换；日志只记录命令 ID、版本、结果类型和低敏关联号，不记录症状、既往史、家族史、用药或身份证/卡号原文。问卷答案不能被写入病历、报告或风险评估，也不能被页面文案解释为诊断或入院结论。
