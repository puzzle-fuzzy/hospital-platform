# 门诊费用摘要详情迁移说明

## 当前已处理

门诊费用列表中的每条记录现在可以进入新版摘要详情：

```text
GET /api/v2/payments/outpatient/records/{recordId}
  ?patientId={内部就诊人引用}&status=unpaid|paid
```

服务端先按当前登录用户解析 `his-patient` 映射，再复用众阳 2.6.33 门诊费用查询，只有在返回列表中找到同一个稳定 `recordId` 时才返回详情。这样详情不能绕过 owner/patient 隔离，也不会把数组下标、Provider 患者号或 Provider 单据号变成客户端主键。

详情返回的仍是已经确认的公开摘要字段：状态、科室、医生、账单时间和人民币分值金额。服务端日志会记录 `outpatient.payment.detail.requested`、`loaded`、`not_found` 或 `failed`，并带有业务类型 `outpatient`、订单类型 `DiagPay`、能力名、内部 patientId、opaque recordId、状态和 traceId；Provider 请求号只通过低敏关联字段记录。

## 明确没有混入的内容

旧端页面中的项目名称、单价、数量、医保支付金额、个人支付金额、费用分类、电子票据下载和支付按钮，当前没有可引用的众阳正式字段合同。因此这次没有猜测字段或从旧端对象补齐，页面只显示“已核对的费用摘要”，支付、医保结算、退费和电子票据继续由各自 contract 决定。

主小程序和 `miniprogram-outpatient-pay` 测试小程序都已使用同一条新版 API；详情页仍会在客户端重新确认会话和当前就诊人，网络响应也会再次校验患者、记录、状态、日期和金额。
