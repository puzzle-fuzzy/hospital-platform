每个矩阵行至少记录一个场景集合。`R` 仅适用于会请求服务端/Provider 的页面；静态页、关闭态页和范围排除页写 `N/A`，不得用“没有请求”伪造成功。每次候选采集都必须在证据文件中声明源码指纹、dist 指纹、页面观察、客户端 requestId/traceId、服务端同链事件和 Provider 低敏 requestId（如适用）。

| 编号 | 场景 | 页面观察和服务端证据要求 |
| --- | --- | --- |

## 5. 真机证据采集表格式

每个非排除行单独生成一份受控 JSON 或受控记录，不把以下字段放入普通 Markdown、Git、聊天或日志摘要：openid、unionid、session_key、token、完整身份证、完整手机号、完整卡号、患者内部标识、Provider 原始请求/响应和原始症状/音频。

```text
candidate.sourceRevision       = <当前源码完整 SHA-1>
candidate.distSourceRevision   = <dist/build-info.json 中的来源>
candidate.distTreeSha256       = <dist 文件树 SHA-256>
scenario                       = <S0-S9 固定枚举>
pageResult                     = <页面可见结果；仅脱敏摘要>
client.method/path/status      = <固定公共路径，不含查询参数和患者标识>
client.requestId/traceId       = <同一次请求的低敏关联值>
server.events                  = <同链结构化事件名和结果>
provider.requestId             = <如适用；只保留低敏 requestId>
operator/time/window           = <操作人、时间窗口、候选版本>
evidenceSha256                 = <受控文件摘要>
status                         = pending | passed | failed
```

只有页面结果、客户端请求、服务端同链事件和 Provider 结果同时满足固定场景，才能将 `pending` 改为 `passed`。临床、绑定、报告附件和外部主体另按权限 `600` 保存，并在普通文档中只记录路径、大小、SHA-256、时间窗口和完整性结论。
