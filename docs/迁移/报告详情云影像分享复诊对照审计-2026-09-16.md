# 报告详情云影像、分享、复诊对照审计（2026-09-16）

## 结论

P1-11 不能按“旧页面有三个按钮”直接全部实现。旧服务中：

- 云影像按钮确实会把报告响应中的 URL 直接交给客户端下载，但未形成资源来源、患者授权、有效期、内容类型或审计 contract；
- 分享按钮的函数只有“分享功能待实现”的提示，没有可迁移的分享业务；
- 复诊按钮只是跳转到固定的通用问诊路由，没有传递报告、患者或预约关联，也没有自动创建预约。

新端已存在一条较安全的报告附件代理骨架：客户端只提交 opaque `reportId/attachmentId`，服务端按 owner、patient、TTL 和 Provider allowlist 重新查询并代理二进制。该骨架可以作为云影像/附件的候选实现基础，但当前没有真实众阳资源映射、公网、真机和生产同链证据；报告分享和报告复诊仍应保持关闭，不凭空增加外部分享或自动预约。

本审计只覆盖报告详情动作。支付、医保、收银台、账单支付、退费和支付相关 HIS 回写均不在范围内。

## 1. 旧服务真实行为

### 1.1 云影像下载

旧详情页在报告卡片上提供“下载云影像”按钮，证据：
`/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/report_detail.vue:34-43`。

点击后从报告对象依次尝试 `reportImgPath`、`reportPdfPath`、`pdfUrl`，只要存在就执行：

1. `proxyForward(imageUrl)`；
2. `uni.downloadFile({ url })`；
3. HTTP 200 后 `uni.saveFile`。

证据：同文件 `:365-396`。

这段代码没有在页面侧验证 URL 的来源、协议、过期时间、患者授权、报告关联、Content-Type、大小上限或下载后的访问边界；它也没有证明这些字段在四类报告中都真实存在。旧报告接口模块只声明四类目录和 LIS 详情接口，见
`/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/api/modules/ZY.ts:80-145`，没有看到独立的云影像授权/短期资源接口。

### 1.2 分享

旧详情页有“分享报告”按钮，证据：
`/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/report_detail.vue:44-51`。

但 `shareReport` 的实现只有 `showToast("分享功能待实现")`，没有生成分享 token、短期 URL、受众、脱敏内容、撤回、访问日志或回跳协议；证据：同文件 `:398-402`。因此旧服务没有可直接迁移的分享业务事实。

### 1.3 复诊

旧详情页底部显示“复诊预约挂号”，点击 `gotoConsultation` 只执行：

```text
uni.navigateTo({ url: "/pages/consult/consult" })
```

证据：`/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pagesB/health/report_detail.vue:184-197,404-409`。

旧实现没有把 `reportId`、报告类型、患者身份或报告摘要传给目标页，也没有在该动作中创建预约。因此“报告复诊”只能确认有一个通用入口跳转事实，不能推导出“报告关联预约”或“根据报告自动复诊”的业务 contract。

## 2. 新端当前实现

### 2.1 已有的安全附件子集

新端报告详情页的当前链路如下：

- 详情页先校验深链患者是否为当前选择患者，再重新读取 owner 的当前患者上下文，最后请求服务端详情，见 `apps/miniprogram/src/pages/report-detail/report-detail.ts:96-150,156-218`；
- 详情页只接收服务端已经校验过的附件列表，并以 `attachmentId` 渲染，见同文件 `:217-240,280-287`；
- 打开附件时只调用 `downloadReportAttachment`，PDF 使用 `wx.openDocument`，图片使用 `wx.previewImage`，并在会话变化、失败和结束时清理页面状态，见同文件 `:290-350`；
- “下载云影像”目前只是打开附件列表第一项，见同文件 `:352-357`；
- 客户端只提交 `patientId/reportId/attachmentId`，Provider URL、鉴权和 origin allowlist 留在服务端，见 `apps/miniprogram/src/services/api-client.ts:3289-3334`；
- 服务端附件路由为 `GET /reports/:reportId/attachments/:attachmentId`，返回 `no-store`、`inline`、`nosniff` 的代理响应，见 `apps/api/src/modules/reports/index.ts:43-73`；
- 服务层重新按 owner、patient、报告引用和 TTL 查找，再确认附件 ID、二进制类型、Content-Type 和 20 MiB 边界，见 `apps/api/src/modules/reports/service.ts:848-997`。

这条链路是当前可保留的安全实现基础，但仍然只是代码状态。它不能证明旧 `reportImgPath/reportPdfPath/pdfUrl` 已经被 Provider 正式映射到稳定的 `attachments`，也不能证明 PACS/ECG/PEIS 在真实环境都有可打开资源。

### 2.2 分享和复诊仍未实现为报告业务

新端分享按钮明确跳转到关闭态：`apps/miniprogram/src/pages/report-detail/report-detail.ts:359-362`；feature 状态注明“不会生成可外传的临床报告链接”，并要求受众、脱敏、有效期、防重放、撤销和审计规则，见 `apps/miniprogram/src/services/feature-navigation.ts:428-434`。

新端复诊按钮目前跳转到通用预约目录：`apps/miniprogram/src/pages/report-detail/report-detail.ts:364-368`。它没有提交报告 ID，也没有自动创建预约，因此不会越权产生报告关联预约；但它也不能被描述为“报告复诊已经迁移”。报告复诊 feature 仍标记为等待 contract，见 `apps/miniprogram/src/services/feature-navigation.ts:421-426`。

云影像独立 feature 仍标记为等待 Provider contract，且明确不向第三方地址传递报告或患者标识，见 `apps/miniprogram/src/services/feature-navigation.ts:398-403`。

## 3. 放行前必须冻结的 contract

### 3.1 云影像 / 附件

需要 Provider 提供同一候选版本的报告类型、报告唯一标识、资源类型、资源 URL/定位符、Content-Type、大小、过期和权限样例；平台需要冻结 owner/patient/report/attachment 的绑定、allowlist、短期引用、失败和撤销语义。小程序不得接收或缓存永久 Provider URL，也不得将旧端报告对象中的任意 URL 原样外发。

### 3.2 报告分享

旧服务没有可迁移实现；如果业务仍需要，必须另立 contract，至少确认分享受众、患者授权、字段脱敏、TTL、防重放、撤回、访问审计、转发后的失效和跨账号访问结果。未确认前只保留关闭态，不实现永久链接、任意 URL 或把报告内容放入小程序分享参数。

### 3.3 报告复诊

必须先确认复诊目标是通用科室目录、指定科室、医生还是互联网问诊；同时确认报告是否仅作为用户主动查看的上下文、是否允许携带低敏摘要、预约关系、重复提交和取消规则。旧页面没有这些事实，因此不得自动从报告创建预约、把报告结论当诊断，也不得跨患者绑定。

## 5. 处理决定

- 保留新端服务端附件代理和详情页的 owner/patient/session 防护；不恢复旧端直接 `proxyForward` 任意 URL 的做法；
- P1-11 保持未完成，直到真实 Provider 资源映射及同版本运行证据齐备；
- 分享保持关闭，不新增伪实现；
- 复诊保持通用预约目录的安全跳转，不把它标为报告复诊完成，也不自动创建预约；
- 任何后续实现都必须继续与支付、医保和支付相关 HIS 回写隔离。
