# 旧便民与健康知识历史数据处置决策（2026-08-31）

> 本文完成历史数据“导入、只存档、不迁移”的处置决策，不是数据导出、导入或删除记录。当前不连接旧库/新库，不修改旧服务，不打开任何便民写入或健康内容发布能力。

## 1. 事实核对

已完成的只读审计显示：

- 旧便民六张表共 42 行：入院预问诊 2、表扬信 4、出院随访 4、我的医生 21、风险评估 7、电子锦旗 4；旧 `openid` 到新 owner 没有桥接成功，患者引用也没有可直接进入新域的证据。
- 旧便民记录混合保存了旧用户、原始患者 ID、患者姓名、医生/科室快照和自由 JSON；问卷缺少稳定版本，部分业务还按 `(user_id, pat_id)` 覆盖历史记录。
- 健康知识源快照包含 15,668 个条目，发布状态为 `not-approved`，质量告警包括 6 组重复药品关系、10 个被清理文本字段、115 个控制字符和 1 个被忽略旧字段/来源；当前没有正式 `reviewed-bundle.json`。

这些事实证明“旧表有数据”不等于“新用户可以安全看到历史”；当前不能用页面空态、字段名称或一次 owner 猜测替代归属和临床审核。

## 2. 统一处置原则

1. 默认不把旧便民或健康知识写入新领域表，不创建兼容读取，不让新 API 直接查询旧表。
2. 如果法律、运营或审计要求保留历史，优先进入受限、加密、只读的归档区；归档区与患者端读模型隔离，不能被页面直接查询。
3. 只有在 owner、患者、就诊/住院事实、版本、授权、公开范围和撤回规则全部明确后，才可把某一类历史转换为新的领域事实。
4. 无法唯一映射或无法证明当前有效性的记录统一标记 `legacy_unresolved`/隔离，不自动丢弃、不自动展示、不自动合并。
5. 审计报告只保留批次指纹、计数、冲突类型和内部引用；正文、答案、姓名、患者号、卡号、医生联系方式和原始 Provider 数据不进入日志、Git 或公共响应。

## 3. 分领域决策

| 历史来源 | 决策 | 原因与后续准入 |
| --- | --- | --- |
| 入院预问诊、风险评估、出院随访 | 默认不迁移；如有合规留存要求只存档 | 缺少题库/表单版本、授权、免责声明、就诊/住院/随访任务和医护读取权限；后续必须先冻结临床 contract，再决定是否按版本转换 |
| 我的医生 | 不迁移到新关系表；必要时只存档 | 旧记录是医生目录快照，不能证明当前在职、科室有效、关系仍存在或头像 URL 安全；后续必须取得受控医生目录和关系 contract |
| 表扬信、电子锦旗 | 默认不迁移；必要时只存档待审核 | 旧提交可携带患者/医生/科室伪造字段，缺内容审核、公开脱敏、撤回和就诊事实；后续需独立反馈域和审核流程 |
| 旧健康知识快照 | 不直接迁移或发布 | 源快照是未审核迁移材料，存在质量告警且没有责任人审核 bundle；后续只能经质量修复、临床审核、版本化 bundle、staging 导入和撤回演练后重建 |

“只存档”不代表患者端可见，也不代表可以恢复旧页面；存档访问必须属于独立的合规/运营权限，患者端仍以新 contract 的事实为准。

## 4. 受控归档边界

若未来决定归档，必须建立独立批次，不复用 `hp_patients`、`hp_user_profiles`、`hp_payment_orders` 或健康知识发布表作为历史垃圾桶。批次至少包含：

- 来源系统、表/快照版本、导出时间、保留期限、责任人和删除/撤回方式；
- 脱敏 owner/patient/encounter 摘要、记录类型、来源主键摘要和冲突状态；
- 原始正文或附件的受限加密位置引用，不把正文复制到普通日志或公共读模型；
- 数量、重复、孤儿、无法映射、内容格式异常和权限异常的汇总；
- 归档读取审计、最小权限、过期清理和恢复演练记录。

归档数据不能驱动预约、支付、医保、问诊、医生关系或临床风险结论；需要参与新业务时必须重新经过对应领域 contract 和真实主体确认。

## 5. 迁移准入与回滚

未来如果业务要求将某一类历史转为新领域事实，执行顺序固定为：

1. 先完成 owner 和患者连续性映射，并取得业务、数据、安全及临床责任人批准。
2. 在脱敏 staging 中导入 `legacy_unresolved`，完成数量、关系、版本、孤儿和权限校验；至少幂等重跑两次。
3. 为该领域建立独立的目标表、状态、撤回和保留策略；禁止跨领域复用 `patId`、表名、旧 JSON 或展示快照。
4. 完成空、拒绝、超时、重复、撤回、非 owner 和真机只读验收，再讨论公开或写入。
5. 迁移批次、规则版本、审核决定、构建版本和回滚点绑定；旧服务与旧数据库保持不变。

失败或发现冲突时，停止批次并撤销新侧可见映射；不删除旧数据、不改写旧表、不把未决记录转成空成功、不自动恢复临床或支付状态。

## 6. 当前结论

便民历史的默认决定是“新端不迁移，合规需要时受限只存档”；健康知识的默认决定是“源快照仅作审核输入，不迁移、不发布”。这完成了处置方向，但没有完成真实归档、临床审核、内容发布或患者端验收；相关业务继续保持 fail-closed。
