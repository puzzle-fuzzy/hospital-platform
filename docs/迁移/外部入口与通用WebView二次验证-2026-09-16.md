本次重新核对旧端通用 `webview.vue` 的动态 URL/path、ticket 交换和多 audience 承载，以及互联网医院固定 H5 入口；同时验证新端智能导诊、智能客服和互联网医院的边界。旧通用 WebView 实际把客服、导诊、患者绑定/解绑混在同一 URL/ticket 链路，完整 URL 可由路由传入；互联网医院则是另一固定地址。新端已禁止通用 URL、动态 path、旧 ticket 和平台 token 外传，智能导诊使用原生接口，客服/互联网医院分别使用固定 HTTPS 地址，但业务域名、外部主体、会话/回跳和真机证据仍未确认。P1-20 继续保持未完成。

## 5. 放行前必须取得的 contract

客服、导诊、互联网医院、患者绑定/解绑必须分别确认主体、origin/path allowlist、业务域名、一次性短期 opaque 会话、授权/回跳/退出、失败和撤销、审计和保留规则。必须分别取得 DevTools、真机和生产同版本证据，不能以 URL 能打开、WebView 没报错或 ticket 生成成功代替最终业务完成。

## 6. 处理决定

1. P1-20 保持未完成，四类外部能力不共用通用 WebView contract。
2. 保留新端固定 audience/固定 HTTPS 边界，不恢复任意完整 URL、动态 path、平台 token 或旧 `/system/auth/ticket`。
3. 待各外部主体分别提供 allowlist、会话、回跳、退出和审计材料后，再分别实现和验收。
