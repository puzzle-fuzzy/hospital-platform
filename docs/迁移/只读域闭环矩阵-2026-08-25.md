# 已开放低风险业务域闭环矩阵（2026-08-25）

## 结论

本轮先完成广度迁移的基础闭环，不继续在某一个页面或某一个 Provider 上反复深挖。预约、报告、门诊费用、就诊人和普通个人资料五个已开放低风险域，统一登记了页面、API、服务实现、领域模型、适配器、日志和文档落点，并由 `pnpm readonly:audit` 自动检查。审计同时要求每个域声明请求中、成功非空、成功空结果、鉴权失败、输入非法、暂时故障和契约异常七类语义，避免把故障伪装成空列表。

这里的“低风险”不是把所有操作都称为纯读取：就诊人目录的 POST 只负责受控同步患者读模型，普通个人资料包含版本化的普通字段 PUT；两者都不等于新增患者、实名绑定、支付或临床写入。

这份矩阵证明的是“代码入口和维护依据没有断链”，不等于真实 Provider、生产公网、微信真机或业务数据已经全部验收。支付、医保、预约写入、患者新增绑定、二维码、HIS 回写等高风险能力仍按迁移路线单独冻结。

## 机器事实源

机器清单位于 [`tools/read-only-domain-catalog.mjs`](../../tools/read-only-domain-catalog.mjs)，审计器位于 [`tools/read-only-domain-audit.mjs`](../../tools/read-only-domain-audit.mjs)，语义细则见 [`read-only-domain-semantics-contract-2026-08-25.md`](只读域语义契约-2026-08-25.md)。每个域必须同时具备：

1. 原生小程序已注册页面及四类页面源文件；
2. 对外 `/api/v2` 路由文档和 Elysia 实际路由 token；同一页面实际使用的同步命令也必须登记，不能只登记列表 GET；
3. API module、service、domain、适配器（无 Provider 的普通资料除外）；
4. 低敏日志事件在 [`docs/日志规范.md`](../日志规范.md) 有说明；
5. 至少一份迁移契约和一份当前正确性/验收边界文档。
6. 成功空结果规则、域级错误码和明确关闭能力；错误码必须同步服务端错误处理、小程序文案表和公共 API 文档。

## 当前闭环范围

| 业务域 | 操作边界 | 页面入口 | API | 当前边界 |
| --- | --- | --- | --- |

## 执行方式

```powershell
pnpm readonly:audit
```

该审计只读仓库文件，不访问旧 Python 服务、MySQL、Redis 或 Provider，也不会修改线上服务。若某个域新增页面、路由、日志事件或契约文件，必须先更新机器清单与中文说明，再运行格式、类型和测试门禁。

## 下一批迁移顺序

闭环通过后继续按以下顺序扩展广度，遇到真实契约不明确就停在状态页，不伪造成功：

1. 病历、问诊、电子问诊、医生、住院和健康内容只读入口；
2. 互联网医院、实时问诊和便民服务的只读/外部跳转边界；
3. 患者新增绑定、二维码及预约写入等身份和临床高风险链路；
4. 微信支付、医保授权、结算和 HIS 写回最后专项处理。
