## 旧服务到新端的实际映射

旧 API 只接收 Provider 患者号，旧页面又直接把数组渲染成住院信息，未定义多 episode 排序、未知状态、owner 授权和公开字段边界。本次因此只迁移可核对的安全摘要：服务端通过当前 owner 的 `patientId` 解析 `his-patient` 引用，再由 adapter 访问旧路径；小程序只提交平台 `patientId`，不接受 `patId`、`patInHosId` 或住院号作为查询参数。

当前投影保留旧页面确实展示的姓名、住院号、掩码就诊卡、性别/年龄、入出院时间、入院方式、住院/出院/取消状态、床位状态、病区/科室/床位、医护、诊断/护理/病情及婴儿摘要；Provider ID、身份证、原始卡号、联系方式、字典 ID、费用字段和支付字段不进入公共 contract。未知状态、重复 episode、未掩码卡号、异常字段、超限列表和异常婴儿测量会 fail-closed。

## 尚未验证和放行条件

以下材料仍缺失，不能打开 `ZHONGYANG_INPATIENT_EPISODES_READY`：

1. Provider 正式请求/响应、分页排序、超时、拒绝和未知状态样例，以及服务端调用权限；
2. 当前候选版本的 owner 映射真实结果，尤其是无映射、非 owner、患者切换和会话失效；
3. 多 episode 的正式选择/排序、历史窗口和状态转换规则；
4. 住院号、诊断、床位、医护、病情和婴儿字段的业务方公开白名单与脱敏确认；
5. 同候选版本的 `dist`、开发者工具、客户端 requestId、服务端 traceId、Provider requestId、真机和生产证据；
6. Provider 503、超时、重复/乱序、字段异常、合法空列表和回滚演练的同链结果。
