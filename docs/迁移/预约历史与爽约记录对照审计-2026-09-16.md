# 预约历史与爽约记录对照审计（2026-09-16）

## 结论

本项只审计非支付的预约历史与爽约只读链路，不涉及预约费用、支付、退费、收银台或医保。

静态源码已经完成第二次对照，并修正了一个明确的迁移偏差：旧端“在线挂号”和“全部挂号”分别使用 `requestChannel=3` 和 `requestChannel=4`，而新端此前两个标签都固定请求 `scope=all`。当前小程序已按标签传递 `online/all`，由服务端 adapter 统一映射渠道数字，并继续在展示边界只把明确的 `cancelled` 从在线列表排除。

P1-06 仍不能标记完成。当前缺少候选版本对应的 Provider 请求/响应样例、真实公网链路、开发者工具生成包和真机结果；此外旧端“前后各三个月”与新端“前后各 90 个中国标准时间自然日”、旧爽约无日期范围与新爽约过去 90 天之间存在需要业务确认的窗口差异。单元测试通过不等于 Provider 记录和状态已经完成迁移。

## 旧服务真实行为

### 我的挂号

旧端页面 `hospital-app/src/pagesB/user/my_registration.vue:186-220` 明确声明两个标签，并按当前标签构造请求：

| 旧端标签 | Provider 渠道 | 日期参数 | 客户端处理 |
| --- | --- | --- | --- |
| 在线挂号 | `3`（门诊微信） | `startDate` / `endDate`，以设备本地日期计算前后各三个月 | 记录直接映射为卡片 |
| 全部挂号 | `4`（门诊自助机） | 不传日期 | 记录直接映射为卡片 |

底层接口定义 `hospital-app/src/api/modules/appointment.ts:395-407,500-507` 也确认了这是同一个预约记录列表端点，`requestChannel` 是必需参数，日期和门诊/就诊日期标记是可选查询条件；`hospital-app/src/api/modules/appointment.ts:414-498` 显示旧响应还包含患者号、身份证、费用、支付、HIS 号等字段，不能整体透传到新的小程序公共读模型。

旧端详情入口另走 `hospital-app/src/api/modules/appointment.ts:510-517` 的 `/appointment-infos/{id}`，因此列表记录的显示下标、随机 ID 或 Provider ID 不能直接当作新端详情授权依据。

### 爽约记录

旧端 `hospital-app/src/pagesB/user/miss_appointment.vue:208-233` 固定使用 `requestChannel="3"`、`isMzFlag="1"`、`dateFlag="1"`，不传日期范围，然后在小程序端以 `item.status === 4` 筛选爽约。这里的数字状态只能作为旧服务行为证据，不能在新端绕过服务端 Provider 状态归一化。

## 尚未完成的实证与决策

1. **时间窗口语义**：旧在线历史用 JavaScript 本地日期前后各三个月（`my_registration.vue:205-218`），新端用 `Asia/Shanghai` 前后各 90 个自然日（`apps/miniprogram/src/services/dashboard-service.ts:866-880,968-994`）。需要业务确认是保持旧月历语义，还是保留新端固定日窗口；不能仅因数字接近就声称等价。
2. **爽约范围**：旧端渠道 3 不传日期，新端为过去 90 天（`dashboard-service.ts:1564-1638`）。需要确认 Provider 是否允许无日期、记录量上限和产品保留期；在确认前不能为了“完全照搬”放开无界查询。
3. **状态样例**：需要同一患者授权范围内的当前 Provider 原始请求/响应受控样例，逐项确认 0/1/3/4/5/6/7 的业务含义、空列表语义、未知状态和取消/爽约边界。没有样例时，不能用旧页面 `status === 4` 或 adapter 映射代码代替真实状态验收。
4. **跨层关联**：需要确认 Provider 预约号与平台 `appointmentId` 的稳定关联命中、无关联记录详情行为，以及 Provider 记录重复/缺号/分页时的真实响应。服务层已有 fail-closed 校验，但尚无当前候选版本的 Provider 证据。
5. **运行验收**：需在当前候选版本核对 API requestId/traceId、Provider HTTP 请求和响应、成功/空/拒绝/超时、会话换号隔离，并比较小程序 `src` 与 DevTools 实际执行的 `dist`；最后补真机验证。此前发布包或历史证据不能替代当前候选版本。
