# 风险评估与健康自测对照审计（2026-09-16）

## 结论

P1-15 必须拆成两条独立迁移链路：风险评估是患者关联的临床表单写入；健康自测是题库读取、答案评分和结果解释。旧端两者都有实际代码，但都没有可直接沿用到新端的安全 contract：风险评估按 `user_id + pat_id` 覆盖记录，健康自测按整数题库 ID 读取固定 Python 配置并在服务端评分，均缺少不可变版本、患者授权、临床审核、撤回/保留和结果解释审计。

新端风险页保持关闭；健康自测只开放不保存、不分级、不诊断的 BMI 公式和血压输入校验。不能因为旧服务有题目、评分代码或本地页面能渲染，就把旧题库和结果直接迁移。

本审计只覆盖风险评估和健康自测，不触碰支付、医保、收银台、退费、账单支付或支付相关 HIS 回写。

### 1.2 旧 Python 服务的覆盖语义

旧 Python controller 实际挂载列表和创建路由，并要求认证用户，见 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/risk_assessment/controller.py:19-48`。service 的真实逻辑是：

## 4. 放行前必须冻结的 contract

风险评估和健康自测必须分别确认：

1. 题目、选项、答案类型、跳转规则和校验范围的不可变版本；
2. 评分算法、阈值、结果等级、解释文案、适用人群和临床审核记录；
3. 患者是否需要绑定就诊/住院事件，授权主体和代填规则；
4. 重复提交、答案修改、结果撤回/失效、结果历史和数据保留周期；
5. 服务端计算与审计字段，日志不得记录健康答案和敏感自由文本原文；
6. 空题库、规则过期、答案越界、拒绝、超时、重复提交和版本回滚样例；
7. staging、DevTools、真机和生产同版本证据，以及风险结果不能替代诊断的免责声明。

BMI/血压如果继续保持参考工具，只需要补齐 `local-non-diagnostic-v1` 的 golden cases、范围/格式回归和免责声明验收；若要增加人群分级或建议，必须另建经审核的临床规则 contract，不能复用本地计算器。

## 6. 处理决定

- P1-15 保持未完成，风险评估与健康自测不得共用一个开放开关；
- 不迁移旧 `user_id + pat_id` 覆盖式风险记录，不复制旧题库、评分区间或医学建议；
- 保留新端 BMI/血压非诊断安全子集，不把它改名为临床风险评估；
- 待规则版本、临床审核、患者授权、幂等、撤回、保留和审计 contract 完整后，再分别实现两条链路；
- 本审计没有修改旧服务、旧数据库、Provider、线上配置或支付/医保代码。
