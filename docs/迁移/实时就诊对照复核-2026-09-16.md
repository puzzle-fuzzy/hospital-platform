# 实时就诊能力对照复核（2026-09-16）

## 结论

旧端“今日就诊”确实有 WebSocket 和叫号队列位置的运行代码；“未来就诊/历史就诊”则是另一条预约读取链路。旧 WebSocket 把 token 和 `patId` 放入 URL，消息没有版本、事件 ID、游标、去重或补偿协议，页面还按消息字段自行拼接展示。当前没有可核验的服务端 WebSocket contract、认证方式、事件来源、患者授权或断线补偿依据。

新端就诊页只读取 owner-scoped 预约摘要，并把三类标签分组为今日/未来/历史；今日页明确展示“实时就诊状态暂未开放”，不创建 WebSocket、不调用队列接口、不展示叫号位置。P1-19 保持未完成，不能把这段预约摘要代码改名为实时就诊。

本复核只覆盖实时就诊/陪诊能力，不触碰支付、医保、收银台、退费、账单支付或支付相关 HIS 回写。

## 1. 旧端真实行为

### 1.1 WebSocket 连接和消息

旧封装 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/api/ws.ts:1-128` 使用模块级 socket、回调和重连计数，连接地址为 `VITE_APP_WS_API + "/webSocket/online/message"`。有 token 时同时设置 `Authorization: Bearer ...` 和 URL 查询参数 `token`、`patId`，见同文件 `:66-88`；错误/关闭会自动最多重连 5 次，见 `:31-45,113-126`。

旧就诊页在今日标签建立连接，把收到的数组中的 `messages` 与科室、事件、时间、地点、预约号等字段拼接为页面项，见 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/pages/consult/consult.vue:214-287`。对“叫号通知”再调用队列位置接口并回填位置，见同文件 `:320-337` 及 `/Users/yxswy/Documents/GitHub/hospital/hospital-app/src/api/ws.ts:180-196` 的发送/关闭边界。旧页面切换到其他标签时关闭连接，但 `onHide` 关闭逻辑被注释，见 `consult.vue:430-433`。

旧代码没有看到统一的消息 schema/version、事件唯一 ID、游标、断线补偿、患者/就诊事件绑定、重放去重、服务端订阅范围或队列位置最终一致性规则；不能只凭 `onMessage` 能解析 JSON 就认为实时链路可迁移。

### 1.2 预约摘要与实时事件是两条链路

旧端未来/历史标签调用预约接口并按日期、状态和 `sourceType` 展示，相关 API 和页面行为已在 [`问诊与互联网医院边界审计-2026-08-25.md`](问诊与互联网医院边界审计-2026-08-25.md) 记录。预约日期/号源是静态预约事实，不等于当日排队、叫号或就诊动态事件；两者不能共用展示标题或完成状态。

## 2. 新端当前实现

- `apps/miniprogram/src/pages/consult/consult.ts:31-71` 固定三个标签和预约摘要页大小；
- `apps/miniprogram/src/pages/consult/consult.ts:169-173,236-291` 只调用 `loadAppointmentRecords`，并按业务日快照分组，没有 `WebSocket`/队列调用；
- `apps/miniprogram/src/pages/consult/consult.wxml:1-62` 把记录标为“预约摘要”，并明确写着“实时就诊状态暂未开放”；
- `apps/miniprogram/src/services/consult-record-view.ts:1-63` 仅按中国标准时间把预约事实分为今日/未来/历史，不生成临床实时状态；
- `apps/miniprogram/src/services/feature-navigation.ts` 和现有边界审计继续把实时就诊归为待独立 contract。

当前状态是已确认的预约摘要安全子集，不是实时陪诊业务。没有新端 WebSocket client、事件 repository、queue adapter 或实时 API route。

## 3. 放行前必须冻结的 contract

至少需要确认：

1. 实时事件权威来源、事件类型、状态机、事件 ID、版本和时间语义；
2. WebSocket 握手认证，不得把 Bearer token 或 provider 患者号放进 URL；
3. 当前 owner/患者/就诊事件的订阅范围，代办人授权和会话轮换；
4. 首次快照、游标、断线重连、补偿查询、重复/乱序事件和过期事件处理；
5. 叫号与队列位置的权威关联键、刷新频率、空/拒绝/超时/未知状态；
6. 消息脱敏、保留周期、客户端日志/服务端日志字段和审计要求；
7. 页面隐藏、后台、卸载、网络切换和账号/患者切换时的订阅撤销；
8. DevTools、真机和生产同版本的连接、消息、断线和最终状态证据。

在这些材料到齐前，不能创建新 WebSocket、复制旧 `connectWebSocket`、把队列接口直连小程序，或把预约摘要的“今日”显示成实时就诊。
