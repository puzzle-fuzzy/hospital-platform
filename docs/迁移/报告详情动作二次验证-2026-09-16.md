# 报告详情动作二次验证（2026-09-16）

## 结论

云影像、分享、复诊三个入口的旧端行为不同，不能因为按钮都存在就按同一种业务迁移：云影像是旧端任意 URL 下载，分享只有待实现提示，复诊只有通用页面跳转。新端目前保留了受 owner、患者、会话和短期引用保护的附件候选链路，分享保持关闭，复诊只跳通用预约目录且不自动创建预约。真实 Provider 资源映射、外部分享 contract 和报告关联复诊仍未验收，P1-11 保持未完成。

本次复核没有修改旧服务、Provider、生产配置或支付/医保/收银台代码，也没有执行报告附件真实下载或外部分享。

## 未验证和放行条件

1. 当前 Provider 对 LIS/PACS/ECG/PEIS 四类报告的真实资源字段、资源类型、Content-Type、大小、过期和授权样例；
2. 旧 `reportImgPath/reportPdfPath/pdfUrl` 到新 `attachments` 的逐字段映射和空/拒绝/超时/错误 MIME 结果；
3. 附件 origin allowlist、短期引用、撤回、会话切换、跨患者和真实真机打开的同链证据；
4. 分享受众、患者授权、脱敏字段、TTL、防重放、撤回和访问审计 contract；
5. 报告复诊的目标（科室/医生/互联网问诊）、可携带摘要、患者上下文、重复预约和取消规则；
6. 当前候选源码、dist、开发者工具、公网、Provider requestId、真机和生产证据一致性。

在上述材料齐备前，附件代理继续保持依赖未配置即失败，分享继续关闭，复诊继续只作为用户主动进入通用预约目录的安全跳转。不能把本地 fixture、HTTP 200、页面可进入、附件按钮存在或单元测试通过写成报告业务完成。
