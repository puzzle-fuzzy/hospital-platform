## 3. 本轮代码收口

`packages/adapters/src/zhongyang-medical-records.ts:42-57,129-184` 原先对可选展示字段使用“无法安全转换就返回
`undefined`”的宽松策略。例如 `deptName` 或 `diagnosis` 为对象时，adapter 会丢弃该字段后继续生成成功摘要。
这会把 Provider 响应异常隐藏成字段缺失，无法区分“医院没有该字段”和“响应格式错误”。

本轮已改为：

- `undefined/null/空字符串` 仍按可选字段缺失处理；
- 非字符串/非数字、控制字符、超长值或归一化为空的已存在字段直接抛出 `ProviderRequestError(responseInvalid=true)`；
- 回归测试 `packages/adapters/src/zhongyang-medical-records.test.ts` 新增异常类型字段用例；
- 按旧端 `patName/sexName/patAge/maritalStatusName` 补映射为受控的 `patientName/patientSex/patientAge/maritalStatus`；
- `apps/miniprogram/src/pages/medical-record/medical-record.wxml:59-63` 恢复旧记录卡的四项患者信息展示，且只在 Provider 返回明确字段时显示；
- 不改变旧服务、数据库、Redis、配置 gate、患者映射或任何支付代码。

这只是读模型完整性收口，不是 Provider 合同确认。
