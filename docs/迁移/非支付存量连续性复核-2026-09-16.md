## 2. 旧服务行为与目标模型对照

### 2.1 患者关系

旧服务患者关系来自旧用户、旧患者目录和 Provider 档案多层标识；患者相关便民表只有旧 `user_id`/`pat_id`。当前目标模型把平台 `patientId`、owner、目录 Provider 引用和临床 `his-patient` 引用分开：

- 目标 `hp_patients` 的 owner、展示字段和内部 ID 在 `packages/persistence/migrations/0001_core.sql:23-39`；Provider 引用按用途拆分在 `packages/persistence/migrations/0012_patient_provider_references.sql:1-20`。
- `packages/domain/src/patients.ts:412-457` 明确区分 `directory` 和 `his-patient`，且完整目录快照缺失即停用旧引用，不能把旧 `pat_id` 直接填进新表。
- 旧便民审计的固定白名单和 owner/patient 映射查询在 `packages/persistence/scripts/legacy-convenience-source-audit.ts:11-36,104-106,142-187`；即使数量能桥接，脚本也固定 `readyForReadOnlyMigration=false`。

**处置：不自动导入，不建立旧表双读。** 只有已批准的账户 owner 映射、当前 Provider 目录复核和 `his-patient` 用途确认全部成立，才允许另立受控批次；本轮 0 条 owner 桥接，故所有旧便民记录停在 `legacy_unresolved`/隔离语义。

### 2.2 我的医生历史

旧 `my_doctor` 是客户端可提交的医生快照：旧模型保存 `user_id`、数值 `doctor_id`、姓名、职称、擅长、科室和头像，见旧服务 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/my_doctor/model.py:9-23`；旧 service 只按当前用户和医生 ID 查重并直接保存客户端资料，见旧服务 `service.py:16-64`。

目标 `hp_my_doctors` 仅保存 owner-scoped 关系和受控字段，并由 `(owner_user_id, doctor_id)` 唯一键约束，见 `packages/persistence/migrations/0019_my_doctors.sql:1-21`；MySQL 读取始终带 owner 条件，见 `packages/persistence/src/mysql-repositories.ts:3499-3521`。

**处置：不导入新关系表；如有合规需要，仅进入隔离归档。** 21 条旧快照不能证明当前医生在职、科室有效、关系仍存在或头像 URL 安全；后续若业务要求保留，必须取得 owner 映射、当前医生目录逐条复核、失效规则和回滚演练。

### 2.3 报告引用

旧端报告目录/详情主要是按当前患者和 Provider 查询结果展示；旧库没有可直接等价于新端短期引用的历史 report reference contract。目标 `hp_report_references` 同时绑定 owner/patient/provider/kind，并有过期时间和外部引用唯一键，见 `packages/persistence/migrations/0009_report_references.sql:1-22`、`packages/domain/src/reports.ts:127-153`；读取还必须检查 owner、patient、reportId 和 `expires_at`，见 `packages/persistence/src/mysql-repositories.ts:3396-3406`。

**处置：不导入历史报告引用，不对旧报告做兼容双读。** 该表是实时查询后的短期授权边界，不是历史报告目录；旧报告若要在新端出现，必须由当前患者映射、当前 Provider 查询和新的短期引用重新生成。历史报告保留与否由旧系统/合规归档承担，不由新端凭旧 ID 猜测。

### 2.4 便民历史

旧服务模型证据如下：表扬信/电子锦旗的患者、就诊、医护和公开字段来自 `PatientFeedbackMixin`，见旧服务 `/Users/yxswy/Documents/GitHub/hospital/app/api/v1/module_convenience/base.py:8-23`；预问诊、随访、风险评估只保存旧 `user_id`、`pat_id`、表名和 JSON 内容，见旧服务各 `model.py:9-18`。旧服务还会按 `(user_id, pat_id)` 覆盖部分问卷历史，未保存题目版本、任务引用、审核或撤回事实，见 `docs/迁移/便民服务边界.md:44-112`。

**处置：不迁移、不向新 API 增加旧表兼容读取；合规需要时只存档。** 42 条库存的业务决定分别为：

| 旧域 | 处置 | 不能直接转换的原因 |

现有只读审计脚本只做固定表白名单、数量和映射缺口统计，没有 INSERT/UPDATE/DELETE/DDL 路径，见 `packages/persistence/scripts/legacy-convenience-source-audit.ts:104-106` 的只读边界说明；相关测试 5 项全部通过。
