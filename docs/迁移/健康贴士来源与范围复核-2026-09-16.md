# `knowledge_tips` 健康贴士来源与范围复核（2026-09-16）

## 1. 结论

`knowledge_tips` 不是不存在的旧表：旧 Python 服务确实定义了模型并挂载了认证后的详情接口。但当前证据不能证明它是旧小程序“指标解读”页面的实际数据来源，也不能证明表内内容已经具备新平台要求的临床审核、版本、免责声明和发布责任。

因此本项的安全结论是：

- 旧服务后端能力保留为待确认迁移输入，不删除、不修改、不直接导入。
- 旧小程序的“指标解读”目前按源码事实是页面内硬编码内容，不把它和 `knowledge_tips` 表强行关联。
- 新端不把 `knowledge_tips` 塞入疾病正文、药品说明、通用提示字段或当前健康知识 bundle；继续 `ignoredLegacySources` 并保持健康内容发布 gate 关闭。
- 只有取得表数据范围、移动端真实调用关系、内容责任人、临床审核规则和发布/撤回 contract 后，才可以另立 `tip` 内容类型并进行 staging 迁移。

本次只读核对没有修改旧服务、旧数据库、健康内容快照、Provider、生产配置或支付相关代码。

## 3. 新端边界核对

当前导出器在 `packages/persistence/scripts/health-knowledge-source-export.ts:91-99,516` 明确把 `knowledge_tips` 作为 `ignoredLegacySources`；现有导出快照因此没有该表的行数、正文或主键映射。这不是数据丢失声明，而是说明当前快照没有获得可安全迁移的 contract。

新端 bundle 的可接受类型在 `packages/domain/src/knowledge-import.ts:10-65`，仅包含目录、症状、疾病、药品及其关系；疾病/药品正文白名单和固定免责声明在 `packages/domain/src/knowledge.ts:44-123`。新 API 在 `apps/api/src/modules/knowledge/index.ts:29-221` 只提供三类目录、症状查询、疾病关系/详情和药品详情，没有 `tips` 路由。

已有门禁已经表达了正确的 fail-closed 结论：

- `docs/迁移/健康知识来源审计-2026-08-25.md:64-80` 将 `knowledge_tips` 记录为未定义来源，禁止塞入疾病正文、药品说明或通用提示字段。
- `docs/迁移/健康百科迁移放行审计-2026-09-16.md:59-69` 说明新端只读路由、bundle 校验、staging 导入和 published-only repository 均不能绕过 `not-approved` 内容状态。
- `packages/persistence/scripts/health-knowledge-source-export.test.ts:57-90` 已锁定源快照为 `not-approved`，并要求 `ignoredLegacySources` 包含 `knowledge_tips`。

## 4. 当前状态和不实现原因

| 层级 | 状态 | 证据/阻塞 |
| --- | --- | --- |
| 旧源码 | 已确认存在 | 旧模型、路由和详情 service 均可定位 |
| 移动端消费 | 未确认 | 旧 `health_test.vue` 使用本地数组，未发现调用 `/knowledge/tips/{id}` |
| 数据范围 | 未确认 | 当前只读健康快照不导出该表，没有表行数、有效内容比例和 `status` 分布 |
| 内容语义 | 未确认 | `title/content` 没有疾病、药品、指标种类、单位、适用人群或医学版本字段 |
| 临床责任 | 未确认 | 没有 reviewer、审核时间、免责声明、发布/撤回和责任人引用 |
| 新端 contract | 未建立 | 当前 bundle 不接收 `tip`，API 不提供该路由 |
| Provider/公网/真机/生产 | 不适用/未验证 | 在 contract 和审核责任确认前不发起新业务调用 |

当前不实现 `knowledge_tips` 的理由不是工程能力不足，而是实现它会凭空选择三件未证实的事实：把孤立后端表当成小程序真实来源、把本地硬编码医学文字当成可发布内容、把 `status=true` 当成审核/发布状态。三者都不符合本项目的迁移规则。

## 5. 未来可执行输入

如果业务方确认要迁移“指标解读”，必须先提供下列可核验材料：

1. 旧生产/脱敏 staging 中 `knowledge_tips` 的行数、字段分布和内容导出指纹；导出不得写入 Git、普通文档或聊天。
2. 旧小程序真实请求或产品确认，说明页面到底使用本地 10 项、`knowledge_tips` 详情，还是两者都属于不同入口。
3. `tip` 的字段白名单、指标类型/单位/适用人群、排序和列表/详情关系；不能继续使用整数主键直接暴露给小程序。
4. 内容责任人、临床审核人引用、审核时间、版本号、固定免责声明、生效/撤回规则和审计保留周期。
5. 新 contract、bundle validator、staging 单事务导入、published-only 读取、重叠窗口保护、失败回滚和小程序真机同链证据。

在这些材料到达前，保留 `ignoredLegacySources=["knowledge_tips"]` 是完整性保护，不是把该旧能力误报为已迁移。健康百科、健康自测和指标解读均不得因本次复核而开放医学内容。
