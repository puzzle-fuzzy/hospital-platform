## 4. 材料与配置字段的对应

| 材料字段 | 使用位置 | 核对要求 |
| --- | --- | --- |
| 移动支付渠道应用标识 | `MBS_APP_ID` | 从对应环境的移动支付反馈材料确认，不与微信小程序 AppID 混用 |
| 数字密钥 | `MBS_APP_SECRET` | 按对应环境配置，用于业务数据加解密 |
| 渠道 SM2 私钥、己方公钥 | `MBS_SM2_PRIVATE_KEY_B64`、`MBS_SM2_OWN_PUBLIC_B64` | 与正式渠道已上报公钥及实际 SDK 配置匹配 |
| 平台 SM2 公钥 | `MBS_SM2_PLATFORM_PUBLIC_B64` | 使用正式平台材料，并取得回包验签证据 |
| 机构渠道认证编码 | 本地正式材料的 `identityVerificationFeedback.orgChannelAuthCode` | 主小程序构建注入；测试和正式材料分别存放 |
| 移动支付渠道应用标识 | 本地正式材料的 `paymentChannelFeedback.appId` → 小程序授权 `orgAppId` | 与正式机构渠道认证码成对注入；这与服务端 `MBS_APP_ID` 取自同一正式反馈字段 |
| 机构编码、线上业务类型 | 对应机构配置与 `medicalBizType` | 按正式身份核验材料核对；本次没有推测或改写标识值 |
| 腾讯医保下单渠道号 | `WECHAT_MEDICAL_INSURANCE_CHANNEL_NO` → `channel_no` | 四份反馈单没有此字段；实际值已匹配所有者补充的医院渠道资料，与医保应用标识、机构认证编码分开使用 |
| 授权查询合作方签名密钥 | `MBS_USER_QUERY_PARTNER_SECRET` → `god-portal-*` 请求头 | API/Worker 已加载所提供正式密钥；仅 userQuery 生成签名，中转透传 |

移动支付反馈单说明要求：切换正式环境前，渠道侧须自行生成渠道公私钥并上报公钥。
2026-10-13 所有者已确认正式反馈单中的渠道密钥完成公钥上报，可直接用于正式环境。
本次按已提供的正式材料使用，不重新生成或替换该密钥对；这项状态依据所有者确认，实际回包验签另行验证。
真实密钥、应用/渠道标识和机构渠道认证编码不写入本页、源码、测试 fixture 或日志。

`MEDICAL_INSURANCE_CREDENTIAL_ENCRYPTION_KEY` 是本平台持久化医保凭证的加密密钥，
不属于上游反馈单材料，不因渠道地址切换而随机轮换，否则可能导致已有凭证无法解密。
