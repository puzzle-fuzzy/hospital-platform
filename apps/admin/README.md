# 高平市人民医院管理端：实时日志与支付查看

独立 React + Ant Design 管理端，放在现有小程序项目同级。账号密码登录保留现有兼容入口；登录后提供“支付数据”和“实时日志”菜单。支付数据页合并展示服务端已落库的普通支付订单和医保订单，退款范围、可退金额和是否需要取消挂号均由服务端核验。医院减免单独展示，不计入微信实付或原路退款。

“实时日志”直接以终端形式展示安全调用元数据，并每 2 秒自动更新：接口、事件、时间、状态、耗时、trace/request ID、Provider 操作和错误分类。它不展示请求或返回原文。

“支付数据”首先按服务端已落库订单展示支付时间、业务、就诊人、下单用户、订单号、金额分项、支付状态和已有退款台账摘要。就诊人和下单用户仅展示服务端提供的名称 `patientDisplayName`、`orderUserDisplayName`；未关联就诊人显示“未关联”，未设置用户昵称显示“未设置”。下单用户指创建订单的平台用户，不代表实际微信付款人。患者和用户 ID、身份证号、卡号、支付凭证、微信调起参数、`out_trade_no` 和 Provider 上下文不会返回浏览器。页面下方仍按北京时间日期复用 `pnpm payment:day` 的支付流程识别和“每次调用独立入参/返回、重试单独保留、缺失即不完整”的证据组织方式。支付流程按开始时间归属到当天；查询前后各读取 30 分钟边界，跨凌晨的接口仍保留在原流程并标记为“前一日边界/次日边界”。日汇总阶段只读取支付业务事件，随后按每笔订单的关联号定向读取 raw 传输记录，避免整天无关原始报文超过 journald 查询上限；只有能通过关联号或唯一时间线归属的记录才会进入流程，无法唯一归属的记录会被排除并提示。点击某个实际传输接口的 `i` 按钮后，服务端复用受控订单快照并校验 chunk、UTF-8 字节数和 SHA-256；原文不会进入支付日汇总响应、数据库或 Worker ingest。

## 本地运行

```bash
pnpm install
pnpm --filter @hospital/admin typecheck
pnpm --filter @hospital/admin test
pnpm --filter @hospital/admin build
pnpm --filter @hospital/admin start
```

默认访问 `http://127.0.0.1:18083`。生产环境使用 `.env.example` 中的变量配置旧登录服务和日志读取地址、服务间令牌；API 还需要配置 `ADMIN_LOGS_INGEST_TOKEN`，Worker 需要使用同一个内部 ingest 地址和令牌（`ADMIN_LOGS_INGEST_URL`、`ADMIN_LOGS_INGEST_TOKEN`）。建议只监听回环地址并通过 Nginx 提供 HTTPS。

## 独立只读账号

可选配置服务端 `ADMIN_VIEWER_USERNAME` 与 `ADMIN_VIEWER_PASSWORD_HASH`，后者必须是 `Bun.password.hash(password, { algorithm: "argon2id" })` 生成的 Argon2id hash；明文密码通过独立安全渠道交付，不写入配置、命令行或日志。登录页选择“只读查看”，或在地址后加 `?mode=viewer` 直接进入只读登录。默认运营登录进入页面时自动加载验证码；切回运营模式也会自动加载，不依赖输入框获得焦点。只读模式无验证码字段、校验或依赖，验证码服务失败不阻塞只读登录。只读登录始终由本服务验证，配置缺失、密码错误均直接拒绝，不访问旧系统认证，也不创建旧系统用户。配置的只读用户名即使选择运营登录，也只能走只读认证。

服务端签发独立随机会话，30 分钟到期，退出或管理端重启立即失效。浏览器只收到 opaque 只读会话及 `capabilities.readOnly=true`，不持有旧系统访问令牌或内部服务令牌。该会话不属于小程序患者认证。只读范围限全局支付列表、已落库支付运营账本、支付同步任务列表、支付日汇总和安全日志元数据；不包含患者目录或报告内容。服务端在路由分派前统一拒绝退款、取消、重试、人工处理、Provider 状态刷新、日志及接口原文等入口。前端隐藏相关按钮只用于呈现，实际权限由服务端会话决定。现有运营账号认证与权限行为保持不变。

这里的“只读”指财务操作只读，不承诺数据库物理零写：现有全局列表读取会幂等刷新由原支付事实派生的聚合、资金腿和事件账本，账本详情及只读会话访问保留审计记录。这些派生投影与审计不修改原支付单状态，也不调用授权、费用上传、结算、扣款、退款、取消或状态回源 Provider。鉴权审计仅记录固定账号类型、方法和资源类别，不记录账号名、密码、会话令牌、患者信息、订单标识或查询串。

浏览器只访问本项目的同源 `/api`；Bun 服务端代理仅开放验证码、登录、退出、日志、支付查看及固定的退费、挂号后端入口，不接受任意上游路径。`POST /api/refunds/payment` 按服务端返回的能力选择整笔、医保或微信范围，查询使用 `GET /api/refunds/payment/{source}/{orderId}?refundType=ALL|HI|CASH`。普通微信挂号在严格确认原订单已全额退款后请求医院取消；医院退费回写未确认不再阻断退号，但仍单独标记待核对，只有微信退款、医院退费回写与退号全部确认才显示全部完成。`appointment_cancelled_writeback_pending` 表示挂号已取消、医院退费回写待处理，不代表挂号仍占号。退费代理发送独立的 `X-Admin-Refund-Token`，不会把新服务令牌下发浏览器。账号密码、访问令牌和日志原文不会写入日志读模型；原始日志只在已登录管理会话的单条详情中按关联号读取，登录状态只保存在当前标签页的 `sessionStorage`。

医保聚合退费的同源入口是 `POST /api/refunds/medical-insurance`，服务端固定转发到新 API 的隐藏 Admin 路由；请求只包含订单号和可选退费原因，退费单号、6203 凭证、微信 `out_trade_no` 和两腿状态均由服务端处理。状态查询使用 `GET /api/refunds/medical-insurance/{refundNo}`。

挂号订单在支付台账中另列“挂号状态”。列表只显示服务端本地快照，例如“平台已预约 / 医院未核对”，不会逐行自动查询医院。点击“查看挂号”或“刷新医院状态”，通过 `GET /api/registrations/{source}/{orderId}` 核对医院状态、支付状态、科室医生、日期、序号和核对时间；`source` 只允许 `payment_order`、`medical_insurance`。非挂号订单不提供挂号操作，未关联、院方状态未知、已就诊或支付结果未确认时不能直接取消。

“取消挂号”仅在医院仍可预约且服务端完整核验证据允许时启用。确认框必填 2 至 80 字原因；`POST /api/registrations/{source}/{orderId}/cancel` 正文只含 `reason`，必须携带稳定 `Idempotency-Key`。此入口不自动退款；普通微信挂号已严格确认原路全额退款后可只补办取消，收费回写未确认会保留提示；原订单或退款身份、金额不一致仍须先核对。医保挂号保留原有核验要求。按钮提交中锁定，响应丢失后必须先刷新医院状态再重试，并沿用当前标签页保存的原操作单号与原因。

管理端取消与患者端挂号授权、下单、预支付、结算和退出共用按用户与挂号关联的持久锁。锁目标从服务端原订单解析；持锁后重新核对医院与全部资金记录，防止核对结束后出现新的并发付款。医院取消成功不代表退款成功，医院已取消也不会触发第二次退款。

挂号代理先校验有效管理会话，再解析正文或访问上游。内部请求固定转发至 `/admin/registrations/{source}/{orderId}`，取消时附加 `/cancel`；操作人引用由服务端将有效会话令牌哈希为 `admin-session:<sha256前40位>`，不接受浏览器自填操作人、患者归属或 HIS 标识，内部服务令牌不进入浏览器响应。
